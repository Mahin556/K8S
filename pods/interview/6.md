## What are the different Image Pull Policies in Kubernetes? Explain each.

### Three Types of Image Pull Policies:

**1. Always:**
- Always goes to the registry to check for the latest version
- Even if the image exists locally, it will try to pull from registry
- If registry is unreachable, pod creation fails
- Use when: You regularly update images with the same tag (e.g., `latest`)

**2. IfNotPresent:**
- First checks local system for the image
- If found locally, uses it (does NOT go to registry)
- If NOT found locally, then goes to registry to pull
- Use when: You want to save bandwidth; image is already on the node

**3. Never:**
- Only uses locally available images
- Never goes to the registry
- If image is not found locally, pod creation fails
- Use when: Air-gapped environments; no internet/registry access

### Default Policy:
- If tag is `:latest` → default is `Always`
- If tag is specific (e.g., `:v1.0`) → default is `IfNotPresent`

### Real-World Scenario:
- Company provides image once, then disconnects internet
- With `Always` policy → pod creation fails (can't reach registry)
- Solution: Use `IfNotPresent` or `Never`
