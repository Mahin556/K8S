### A developer wants to change configurations for debugging their pod but doesn't want to impact any other deployments. What's the safe and isolated way to achieve this?

**Challenge:** You cannot simply update the existing ConfigMap because it might trigger restarts on other deployments using the same ConfigMap.

**Solution:**

**Option 1 - Using kubectl run command:**
```bash
kubectl run --rm debug-pod \
  --image=myapp:latest \
  --env="LOG_LEVEL=debug" \
  --restart=Never
```

**Option 2 - Create a separate standalone Pod YAML:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: debug-pod
  labels:
    purpose: debug
spec:
  containers:
  - name: app-container
    image: myapp:latest
    env:
    - name: LOG_LEVEL
      value: "debug"
  restartPolicy: Never
```

Then apply:
```bash
kubectl apply -f debug-pod.yaml
```

**Key Points:**
- Create a completely separate standalone pod for debugging
- This pod has its own custom configurations (e.g., LOG_LEVEL=debug)
- No impact on existing deployments or other pods
- Use `restartPolicy: Never` since this is a one-off debugging pod
- Once debugging is complete, simply delete the pod
