## Understanding the Three Phases of Pod Lifecycle

Before debugging, you must understand which phase your pod is in:

| Phase | What Happens | Status |
|-------|--------------|--------|
| **Phase 1: Scheduling** | Pod needs to be assigned to a worker node | `Pending` |
| **Phase 2: Container Creation** | Image download, config/secret injection, volume mounting | `ContainerCreating` |
| **Phase 3: Runtime** | Application is running; may have health check failures, app crashes | `Running` → `CrashLoopBackOff` |

**First Command Always:**
```bash
kubectl get pods -w
```

## Phase 1 Errors: Pod Stuck in `Pending` State

### Scenario 1: Insufficient Resources (CPU/Memory)

**Symptom:** Pod status shows `Pending` - pod cannot be assigned to any machine.

**Debugging:**
```bash
kubectl describe pod <pod-name>
```

**Error Message:**
```
0/1 nodes are available: 1 Insufficient memory
```

**Root Cause:**
- The pod's `requests` (minimum resource requirement) exceeds available capacity on any node
- Example: Pod requests 4GB memory but node only has 1.8GB available

**YAML Issue:**
```yaml
resources:
  requests:
    memory: "4Gi"    # Too high for available nodes
```

**Solution:**
1. Check cluster capacity: Do you have enough machines?
2. Add more worker nodes to the cluster
3. Use Cluster Autoscaler (cloud-managed clusters like EKS/AKS)
4. Work with dev team: Do you really need 4GB? Reduce the request if possible

---

### Scenario 2: Node Affinity / Node Selector Mismatch

**Symptom:** Pod `Pending` - scheduler cannot find a matching node.

**Debugging:**
```bash
kubectl describe pod <pod-name>
```

**Error Message:**
```
0/1 nodes are available: 1 node(s) didn't match node selector
```

**Root Cause:**
- Pod has `nodeSelector` or `nodeAffinity` requiring a label that no node has
- Example: Pod requires `my-node=demo-node` but no node has this label

**YAML Issue:**
```yaml
spec:
  nodeSelector:
    my-node: demo-node    # Label doesn't exist on any node
```

**Solution:**
1. Check existing node labels:
   ```bash
   kubectl get nodes --show-labels
   ```
2. Apply the required label to the appropriate node:
   ```bash
   kubectl label node <node-name> my-node=demo-node
   ```

---

### Scenario 3: Unbound Persistent Volume

**Symptom:** Pod `Pending` - cannot be assigned due to storage issues.

**Debugging:**
```bash
kubectl describe pod <pod-name>
kubectl get pvc
```

**Error Message:**
```
0/1 nodes are available: 1 node(s) didn't find available persistent volumes
```

**Root Cause:**
- Pod references a PVC, but no matching PV exists
- PVC itself is in `Pending` state

**Solution:**
1. Check if PVs exist:
   ```bash
   kubectl get pv
   ```
2. Create a PV that matches the PVC requirements
3. OR configure StorageClass with a provisioner for dynamic provisioning
4. For cloud: Ensure StorageClass is set up to create EBS volumes automatically

---

### Scenario 4: Node Taints

**Symptom:** Pod `Pending` - node has a taint that repels the pod.

**Debugging:**
```bash
kubectl describe pod <pod-name>
kubectl describe node <node-name> | grep -i taint
```

**Error Message:**
```
0/1 nodes are available: 1 node(s) had untolerated taint
```

**Root Cause:**
- Node has a `taint` applied, but pod doesn't have a matching `toleration`
- Taint repels all pods without the matching toleration

**Solution:**
1. Check node taints:
   ```bash
   kubectl describe node <node-name> | grep Taint
   ```
2. Add matching toleration to the pod spec:
   ```yaml
   tolerations:
   - key: "taint"
     operator: "Equal"
     value: "true"
     effect: "NoSchedule"
   ```
3. OR remove the taint from the node:
   ```bash
   kubectl taint node <node-name> key=value:NoSchedule-
   ```

## Phase 2 Errors: Container Creation Failures

### Scenario 5: Unavailable ConfigMap

**Symptom:** Pod moves from `Pending` to `ContainerCreating` but gets stuck.

**Debugging:**
```bash
kubectl describe pod <pod-name>
kubectl get configmap
```

**Error Message:**
```
Failed to create container: configmap "my-map" not found
```

**Root Cause:**
- Pod references a ConfigMap that doesn't exist
- Container requires the config file to start

**YAML Issue:**
```yaml
volumes:
- name: config
  configMap:
    name: my-map    # This ConfigMap doesn't exist
```

**Solution:**
1. Create the required ConfigMap:
   ```bash
   kubectl create configmap my-map --from-file=config.properties
   ```
2. Verify the ConfigMap exists and has the correct data

---

### Scenario 6: Unavailable Secret

**Symptom:** Pod stuck in `ContainerCreating`.

**Debugging:**
```bash
kubectl describe pod <pod-name>
kubectl get secret
```

**Error Message:**
```
Failed to create container: secret "my-password" not found
```

**Root Cause:**
- Pod references a Secret that doesn't exist
- Container needs the secret to start

**Solution:**
1. Create the required Secret:
   ```bash
   kubectl create secret generic my-password --from-literal=password=secret123
   ```

---

### Scenario 7: Resource Quota Exceeded

**Symptom:** Pods running fine, but desired replicas don't match. No error on the pods themselves.

**Debugging:**
```bash
kubectl get deployment
kubectl get replicaset
kubectl describe replicaset <rs-name>
```

**Error Message:**
```
Error creating: pods is forbidden: exceeded quota
```

**Root Cause:**
- A `ResourceQuota` is applied on the namespace limiting the number of pods
- Example: Quota allows only 2 pods, but deployment requests 3

**Solution:**
1. Check resource quota:
   ```bash
   kubectl get resourcequota
   kubectl describe resourcequota <quota-name>
   ```
2. Either reduce replicas in deployment OR increase the quota

---

### Scenario 8: Image Pull BackOff

**Symptom:** Pod shows `ImagePullBackOff` or `ErrImagePull`.

**Debugging:**
```bash
kubectl describe pod <pod-name>
```

**Error Message:**
```
Failed to pull image "nginx:invalid-tag": image not found
```

**Root Causes:**
- Wrong image tag
- Image doesn't exist in registry
- Credential/permission issues for private registry

**Solution:**
1. Verify image name and tag are correct
2. Check if image exists in Docker Hub/private registry
3. For private registry: Verify `imagePullSecrets` are configured

## Phase 3 Errors: Runtime Failures (CrashLoopBackOff)

### Scenario 9: Out of Memory (OOM)

**Symptom:** Pod in `CrashLoopBackOff` state.

**Debugging:**
```bash
kubectl describe pod <pod-name>
```

**Error Message:**
```
OOMKilled: container exceeded memory limit
```

**Root Cause:**
- Container's `limits.memory` is set too low
- Application needs more memory than the limit allows

**YAML Issue:**
```yaml
resources:
  limits:
    memory: "200Mi"    # Too low
# But stress command uses 250Mi
```

**Solution:**
1. Work with dev team to understand actual memory needs
2. Increase the `limits.memory` to a value above what the application needs
3. Example: Change limit from 200Mi to 300Mi

---

### Scenario 10: Health Check Failure (Liveness Probe)

**Symptom:** Pod restarts every 30 seconds, marked as `CrashLoopBackOff`.

**Debugging:**
```bash
kubectl describe pod <pod-name>
```

**Root Cause:**
- Liveness probe is failing
- After 3 consecutive failures, Kubernetes restarts the container

**YAML Issue:**
```yaml
livenessProbe:
  exec:
    command:
    - ls
    - /tmp/nonexistent    # This file doesn't exist
```

**Solution:**
1. Check application logs to understand why health check fails
2. Fix the liveness probe path or command
3. Ensure the application actually serves the health endpoint

---

### Scenario 11: Init Container Failure

**Symptom:** Pod in `CrashLoopBackOff`, main container never starts.

**Debugging:**
```bash
kubectl describe pod <pod-name>
```

**Root Cause:**
- Init container is failing
- Main container waits for init container to complete successfully

**YAML Issue:**
```yaml
initContainers:
- name: init-setup
  image: centos
  command: ['sh', '-c', 'exit 1']    # Always fails
```

**Solution:**
1. Check init container logs:
   ```bash
   kubectl logs <pod-name> -c <init-container-name>
   ```
2. Fix the init container script or command

---

### Scenario 12: Application Runtime Error (Database Connection)

**Symptom:** Pod in `CrashLoopBackOff`.

**Debugging:**
```bash
kubectl logs <pod-name>
```

**Error Message:**
```
java.sql.SQLException: Unable to connect to database
Communications link failure
```

**Root Cause:**
- Application cannot connect to its backend (database, another microservice)
- Database may be down, unreachable, or connection details are wrong
- Too many connections causing rejection

**Solution:**
1. Check if database is up and running
2. Verify database connection string (JDBC URL)
3. Check network connectivity between application and database
4. Check if database connection pool is exhausted

## Phase 4 Errors: Networking Issues

### Scenario 13: Application Not Accessible Despite Pod Running

**Symptom:**
- Pod status: `Running` ✓
- Pod accessible directly via pod IP ✓
- Service endpoint shows NOTHING ✗
- Application not reachable via Service ✗

**Debugging Steps:**

**Step 1: Check if pod is accessible directly**
```bash
kubectl get pods -o wide
curl <pod-ip>:80
```

**Step 2: Check if Service has endpoints**
```bash
kubectl get endpoints <service-name>
```

**Step 3: Describe the Service**
```bash
kubectl describe service <service-name>
```

**Root Cause:**
- Service `selector` labels don't match the pod's labels
- Service is pointing to non-existent pods

**Example:**
```yaml
# Pod labels:
labels:
  app: my-app

# Service selector (WRONG):
selector:
  app: different-name    # Doesn't match!
```

**Solution:**
1. Fix the service selector to match pod labels
2. OR fix pod labels to match service selector
3. Apply changes and verify endpoints appear:
   ```bash
   kubectl apply -f service.yaml
   kubectl get endpoints <service-name>
   ```

## Complete Troubleshooting Flowchart

```
kubectl get pods
       │
       ▼
┌──────────────┐
│ Pod Pending? │──YES──► Describe pod → Check events
└──────────────┘         ├── Insufficient resources? → Add nodes/reduce requests
                         ├── Node affinity issue? → Add labels to nodes
                         ├── PVC unbound? → Create PV or fix StorageClass
                         └── Node taint? → Add toleration to pod

       NO
       │
       ▼
┌────────────────────┐
│ ContainerCreating? │──YES──► Describe pod → Check events
└────────────────────┘         ├── ConfigMap missing? → Create ConfigMap
                               ├── Secret missing? → Create Secret
                               ├── Resource quota? → Increase quota
                               └── Image pull error? → Fix image/tag

       NO
       │
       ▼
┌──────────────────┐
│ CrashLoopBackOff?│──YES──► Describe pod + Check logs
└──────────────────┘         ├── OOMKilled? → Increase memory limit
                             ├── Liveness probe fail? → Fix health check
                             ├── Init container fail? → Check init logs
                             └── App runtime error? → Check app logs

       NO
       │
       ▼
┌─────────────────┐
│ Pod Running but │──YES──► Check endpoints
│ not accessible? │         ├── Service selector mismatch? → Fix labels
└─────────────────┘         ├── Check pod IP directly
                            └── Check network policies
```

## Key Commands Summary

| Command | Purpose |
|---------|---------|
| `kubectl get pods -w` | Watch pod status changes |
| `kubectl describe pod <name>` | Detailed pod info + events |
| `kubectl describe node <name>` | Node details including taints |
| `kubectl logs <pod-name>` | View pod logs |
| `kubectl logs <pod> -c <container>` | View specific container logs |
| `kubectl get events` | View cluster events |
| `kubectl get pv` / `kubectl get pvc` | Check persistent volumes |
| `kubectl get configmap` / `kubectl get secret` | Check configs/secrets |
| `kubectl get resourcequota` | Check resource quotas |
| `kubectl get replicaset` | Check replica set status |
| `kubectl describe rs <name>` | Debug replica set issues |
| `kubectl get endpoints` | Check service-to-pod mapping |
| `kubectl get nodes --show-labels` | View node labels |
| `kubectl label node <node> key=value` | Add label to node |
| `kubectl taint node <node> key=value-` | Remove taint from node |
| `curl <pod-ip>:<port>` | Test pod directly |
