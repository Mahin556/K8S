## Question 1: What is a Container?

**Answer:** A container is a **lightweight, standalone, executable package** of software that includes everything needed to run an application: code, runtime, system tools, libraries, and settings.

### Key Characteristics:

| Feature | Description |
|---------|-------------|
| **Isolation** | Each container runs in its own isolated environment |
| **Portability** | Runs consistently across different environments (dev, test, prod) |
| **Lightweight** | Shares the host OS kernel; no need for a full OS per container |
| **Fast Startup** | Containers start in seconds (unlike VMs) |
| **Resource Efficient** | Uses fewer resources than virtual machines |

### Container vs Virtual Machine:

| Feature | Container | Virtual Machine |
|---------|-----------|-----------------|
| **OS** | Shares host OS kernel | Each VM has its own OS |
| **Size** | Megabytes | Gigabytes |
| **Startup Time** | Seconds | Minutes |
| **Isolation** | Process-level | Full OS-level |

### Real-World Analogy:
- A container is like a **shipping container** - standardized, portable, and works the same way regardless of where it's placed.
