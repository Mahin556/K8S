# Pod Stuck in ContainerCreating — Complete Troubleshooting Guide

---

## What ContainerCreating Actually Means

Before debugging, understand what Kubernetes is doing during this phase:

```
ContainerCreating = the pod has been SCHEDULED to a node (that part worked)
                    but the container hasn't started yet.

The kubelet on that node is trying to:
  1. Pull the container image
  2. Create the network namespace (CNI)
  3. Mount volumes (PVC, ConfigMap, Secret)
  4. Set up any init containers
  5. Start the container process

Stuck in ContainerCreating = one of these 5 steps is BLOCKED.
Each step has its own failure signature in kubectl describe pod.
```

## Step 1 — Always Start Here: Read the Events Section

```bash
kubectl describe pod <pod-name> -n <namespace>
```

The **Events section at the bottom** tells you exactly which step is stuck:

```
Events:
  Type     Reason                  Age   Message
  ----     ------                  ----  -------

# Image pull failure:
  Warning  Failed                  2m    Failed to pull image "myapp:latest":
                                         rpc error: pulling from host
                                         registry.example.com: unauthorized

# CNI/network failure:
  Warning  NetworkNotReady         5m    network is not ready:
                                         container runtime network not ready:
                                         NetworkPlugin cni failed to set up pod

# Volume mount failure:
  Warning  FailedMount             3m    MountVolume.SetUp failed for volume
                                         "config-vol": configmap "app-config"
                                         not found

# PVC not bound:
  Warning  FailedMount             10m   Unable to attach or mount volumes:
                                         unmounted volumes=[data-vol],
                                         unattached volumes=[data-vol]:
                                         timed out waiting for the condition

# Secret not found:
  Warning  FailedMount             2m    MountVolume.SetUp failed for volume
                                         "secret-vol": secret "db-credentials"
                                         not found

# Init container failing:
  Warning  BackOff                 1m    Back-off restarting failed container
                                         init-migration in pod default/myapp
```

**Read the Message column carefully** — it tells you the failure mode directly.

## Cause 1 — Image Pull Failures

### 1a: Image doesn't exist
```bash
kubectl describe pod <pod-name> | grep -A5 "Failed to pull"
# Failed to pull image "myapp:v99": not found

# Fix: check the image name and tag
kubectl get pod <pod-name> -o jsonpath='{.spec.containers[*].image}'
# Verify this image:tag actually exists in your registry
```

### 1b: Private registry — missing imagePullSecret
```bash
# Event shows:
# "unauthorized: authentication required"
# or: "access denied"

# Fix step 1: create the pull secret
kubectl create secret docker-registry registry-credentials \
  --docker-server=registry.example.com \
  --docker-username=myuser \
  --docker-password=mypassword \
  --docker-email=admin@example.com \
  -n <namespace>

# Fix step 2: reference it in pod spec
spec:
  imagePullSecrets:
    - name: registry-credentials   # MUST be in same namespace as pod
  containers:
    - name: app
      image: registry.example.com/myapp:v1.2

# Or attach to the service account (applies to ALL pods in namespace):
kubectl patch serviceaccount default -n <namespace> \
  -p '{"imagePullSecrets":[{"name":"registry-credentials"}]}'
```

### 1c: Node can't reach the registry
```bash
# Event: "dial tcp registry.example.com:443: i/o timeout"
# or: "no route to host"

# Test from the node (not the pod):
kubectl debug node/<node-name> -it --image=alpine -- sh
wget -q --spider https://registry.example.com/v2/
# If timeout → node firewall/network issue, not Kubernetes issue

# Check if it's a proxy issue on the node:
kubectl describe node <node-name> | grep -i proxy
```

### 1d: Wrong image architecture
```bash
# Event: "exec format error"
# Pod is running on arm64 node but image is amd64 only

kubectl get node <node-name> -o jsonpath='{.status.nodeInfo.architecture}'
# arm64

# Fix: build multi-arch image or use node affinity
affinity:
  nodeAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      nodeSelectorTerms:
        - matchExpressions:
            - key: kubernetes.io/arch
              operator: In
              values: ["amd64"]
```

## Cause 2 — Volume Mount Failures (Most Common Cause After Image Pull)

### 2a: ConfigMap not found
```bash
# Event: "configmap "app-config" not found"

# Check: does it exist IN THE SAME NAMESPACE?
kubectl get configmap app-config -n <pod-namespace>
# Error from server (NotFound) ← not in this namespace

# Fix: create it in the correct namespace
kubectl create configmap app-config -n <namespace> \
  --from-file=config.yaml

# Common mistake: ConfigMap is in "default" but pod is in "production"
kubectl get configmap -A | grep app-config
```

### 2b: Secret not found
```bash
# Event: "secret "db-credentials" not found"
# Identical issue to ConfigMap — namespace mismatch is most common

kubectl get secret db-credentials -n <namespace>
# Copy from another namespace if needed:
kubectl get secret db-credentials -n source-ns -o yaml | \
  sed 's/namespace: source-ns/namespace: target-ns/' | \
  kubectl apply -f -
```

### 2c: PVC not bound (stuck Pending)
```bash
# Event: "Unable to attach or mount volumes: timed out waiting for the condition"

kubectl get pvc -n <namespace>
# NAME       STATUS    VOLUME   CAPACITY  STORAGECLASS
# data-pvc   Pending   <empty>  10Gi      fast-ssd    ← PENDING = not bound

kubectl describe pvc data-pvc -n <namespace>
# Events show WHY it's pending:

# Case A: no matching PV
# "no persistent volumes available for this claim"
# Fix: create a PV, or check StorageClass exists:
kubectl get storageclass

# Case B: StorageClass doesn't exist
# "storageclass.storage.k8s.io "fast-ssd" not found"
# Fix: fix the storageClassName in PVC, or install the StorageClass

# Case C: volume is attached to a different node (ReadWriteOnce)
# "Multi-Attach error: volume is already exclusively attached to node X"
# Fix: delete old pod first, or use ReadWriteMany StorageClass
```

### 2d: PV is in Released state (bound to old PVC)
```bash
kubectl get pv
# NAME     STATUS    CLAIM               STORAGECLASS
# pv-001   Released  old-ns/old-pvc      standard
#          ↑ stuck in Released — old PVC deleted, PV not reclaimed

# Fix: clear the claimRef so the PV can be bound again
kubectl patch pv pv-001 -p '{"spec":{"claimRef":null}}'
# PV goes back to Available → can bind to new PVC
```

## Cause 3 — CNI Network Failure

```bash
# Event: "NetworkPlugin cni failed to set up pod network"
# or: "network is not ready: NetworkPlugin cni failed"

# Check CNI pods on the failing node:
kubectl get pods -n kube-system -o wide | grep <node-name>
# Look for: calico-node, weave, cilium-agent, flannel
# If CNI pod is NotRunning or CrashLoopBackOff → root cause

kubectl describe pod <cni-pod> -n kube-system
kubectl logs <cni-pod> -n kube-system --previous

# Check if node has network-related taints/conditions:
kubectl describe node <node-name> | grep -A5 "Conditions:"
# NetworkUnavailable  True ← confirms CNI is broken on this node

# Quick fix: restart CNI DaemonSet on that node
kubectl rollout restart daemonset calico-node -n kube-system
# or for Cilium:
kubectl rollout restart daemonset cilium -n kube-system
```

## Cause 4 — Init Container Failing

```bash
# The main container can't start until ALL init containers succeed
# If an init container keeps failing → pod stuck in ContainerCreating/Init

kubectl describe pod <pod-name> | grep -A10 "Init Containers:"
# Init Containers:
#   migrate-db:
#     State: Running  ← it's running but hasn't exited yet
#     or
#     State: Terminated  Reason: Error  ← it failed

# Check init container logs:
kubectl logs <pod-name> -c <init-container-name>
kubectl logs <pod-name> -c migrate-db --previous   # if it crashed

# Common init container failures:
# 1. DB migration script fails → fix the migration
# 2. Init container waiting for a service that doesn't exist yet
# 3. Init container needs a secret that doesn't exist
```

## Cause 5 — Resource Constraints

```bash
# Step 1: Is the node actually out of resources?
kubectl top node <node-name>
# NAME      CPU(cores)   CPU%   MEMORY(bytes)   MEMORY%
# node-1    1900m        95%    7500Mi          93%   ← very high

# Step 2: Check node's allocatable vs allocated:
kubectl describe node <node-name> | grep -A10 "Allocated resources:"
# Resource       Requests    Limits
# cpu            1850m/2     1900m/2    ← 92.5% of CPU requested
# memory         7100Mi/8Gi  7800Mi/8Gi ← 88.75% of memory requested

# Step 3: Is it disk pressure? (different from memory pressure)
kubectl describe node <node-name> | grep "DiskPressure"
# DiskPressure  True ← node evicting pods due to disk

# Fix disk pressure: clean up old images on the node
kubectl debug node/<node-name> -it --image=alpine -- chroot /host
crictl rmi --prune    # remove unused container images

# Or check what's filling the disk:
du -sh /var/lib/containerd/*   # containerd image storage
du -sh /var/log/pods/*         # pod logs
```

## Cause 6 — Node Affinity / Taint/Toleration Issues

```bash
# ContainerCreating can sometimes appear when scheduler puts pod on node
# but kubelet then can't start it due to local issues

# Check if pod is on the right node:
kubectl get pod <pod-name> -o wide
kubectl describe node <node-name> | grep Taints

# If pod needs to be on different node:
kubectl delete pod <pod-name>
# Add proper nodeSelector/affinity or fix tolerations

# Check if the pod has the right tolerations:
kubectl get pod <pod-name> -o jsonpath='{.spec.tolerations}'
```

## Cause 7 — Ephemeral Storage Limit

```bash
# If pod has ephemeral storage limit set and the container was writing
# too much to its own filesystem:

# Event: "container "app" exceeded its local ephemeral storage limit"

kubectl describe pod <pod-name> | grep -A3 "ephemeral-storage"

# Fix: increase the ephemeral storage limit or reduce disk usage in container
resources:
  limits:
    ephemeral-storage: "2Gi"   # increase from whatever it was
```

## Cause 8 — Projected Volume / Service Account Token Issue

```bash
# Newer clusters mount service account tokens via projected volumes
# If this fails, the pod gets stuck in ContainerCreating

# Event: "failed to watch file "/var/run/secrets/kubernetes.io/serviceaccount/token""
# or: "unable to rotate token"

# Check if the ServiceAccount exists:
kubectl get serviceaccount <sa-name> -n <namespace>

# Check token controller is running:
kubectl get pods -n kube-system | grep token

# Fix: ensure the ServiceAccount exists, or recreate it:
kubectl create serviceaccount <sa-name> -n <namespace>
```

## Complete Systematic Debug Sequence

```bash
# ─── 30-second triage ────────────────────────────────────────────────────────

# 1. Read the events — this alone solves 80% of cases
kubectl describe pod <pod-name> -n <namespace> | tail -30

# 2. Check which phase is stuck
kubectl get pod <pod-name> -n <namespace> -o wide
# NODE column → tells you which node to investigate

# 3. Check if volumes are the issue
kubectl get pvc -n <namespace>   # all Bound? or some Pending?

# ─── If image-related ────────────────────────────────────────────────────────

# Test pull credentials manually:
kubectl run test-pull --rm -it \
  --image=registry.example.com/myapp:v1.2 \
  --overrides='{"spec":{"imagePullSecrets":[{"name":"registry-credentials"}]}}' \
  -- echo "pull worked"

# ─── If volume-related ────────────────────────────────────────────────────────

# Check all resources the pod depends on exist in the SAME namespace:
kubectl get configmap,secret,pvc -n <namespace>

# ─── If CNI-related ──────────────────────────────────────────────────────────

kubectl get pods -n kube-system -o wide | grep <node-name>
# Check CNI pods on that specific node

# ─── If nothing obvious ──────────────────────────────────────────────────────

# Check kubelet logs on the node:
kubectl debug node/<node-name> -it --image=alpine -- chroot /host
journalctl -u kubelet -n 100 --no-pager | grep -i "error\|failed\|container"
```

## Decision Tree

```
Pod stuck in ContainerCreating?
         │
         ▼
kubectl describe pod → read Events section
         │
         ├── "Failed to pull image"
         │         ├── "unauthorized" → missing imagePullSecret
         │         ├── "not found"    → wrong image name/tag
         │         └── "timeout"      → node can't reach registry
         │
         ├── "not found" for configmap/secret
         │         └── resource doesn't exist in THIS namespace
         │
         ├── "timed out waiting for the condition" (PVC)
         │         └── kubectl get pvc → check STATUS column
         │                   ├── Pending → StorageClass issue or no PV
         │                   └── Released → clear claimRef on PV
         │
         ├── "NetworkPlugin cni failed"
         │         └── check CNI daemonset pods on that node
         │
         ├── Init container logs
         │         └── kubectl logs <pod> -c <init-container>
         │
         └── No events / vague events
                   └── kubectl debug node → journalctl -u kubelet
```
