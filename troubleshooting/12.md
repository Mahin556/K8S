## Scenario 2: Zero Downtime Deployments

**Question:** How can your company ensure zero downtime deployment with Kubernetes? Which strategies would you use?

### Key Strategies to Mention:

**1. Rolling Update Strategy (Default):**
- Gradually replaces old pods with new version pods
- Some pods always remain running
- Define `maxUnavailable` and `maxSurge` parameters

**2. Readiness Probes:**
- Ensure new pods are ready before receiving traffic
- Prevents traffic from going to not-yet-ready pods

**3. GitOps with ArgoCD:**
- Use ArgoCD for Git-based delivery
- Ensures easy rollbacks and rollouts
- Rollback instantly if something goes wrong

### How Rolling Update Works:
```
Before Update:
┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐
│ v1  │ │ v1  │ │ v1  │ │ v1  │
└─────┘ └─────┘ └─────┘ └─────┘

During Update (maxUnavailable=1, maxSurge=1):
Step 1: ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐
        │ v1  │ │ v1  │ │ v1  │ │ v1  │ │ v2  │
        └─────┘ └─────┘ └─────┘ └─────┘ └─────┘

Step 2: ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐
        │ v1  │ │ v1  │ │ v1  │ │ v2  │ │ v2  │
        └─────┘ └─────┘ └─────┘ └─────┘ └─────┘

After Update:
┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐
│ v2  │ │ v2  │ │ v2  │ │ v2  │
└─────┘ └─────┘ └─────┘ └─────┘
```

### How to Answer in English:
"To ensure zero downtime deployment in Kubernetes, I would use the Rolling Update strategy, which is the default strategy for Deployments. This strategy gradually replaces old instances with new versions, ensuring some instances are always running. I would define the Deployment with appropriate `maxUnavailable` and `maxSurge` values. Additionally, I would implement readiness probes. I would also use ArgoCD and GitOps-based delivery strategy to ensure easy rollbacks and rollouts for performance."
