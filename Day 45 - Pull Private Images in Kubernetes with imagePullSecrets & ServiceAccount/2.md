* The `docker-registry` keyword in `kubectl create secret` specifies the **secret type**, not the registry vendor.

  * It creates a secret of type: `kubernetes.io/dockerconfigjson`.

* It works with **any OCI-compliant container registry**, not just Docker Hub.

  * Examples:

    * Amazon ECR
    * Google Container Registry (GCR)
    * GitHub Container Registry (GHCR)
    * Harbor
    * Azure Container Registry (ACR)

* The important flags are:

  * `--docker-server` → Registry URL
  * `--docker-username` → Registry username
  * `--docker-password` → Password or token
  * `--docker-email` → (optional, mostly ignored now)

* The values depend on the registry provider:

  * For **Amazon ECR**:

    * Username is usually `AWS`
    * Password is a generated authentication token
    * Server is region-based, e.g.:

      ```
      <account-id>.dkr.ecr.ap-south-1.amazonaws.com
      ```
    * Token is generated using:

      ```
      aws ecr get-login-password --region ap-south-1
      ```

  * For **GHCR (GitHub Container Registry)**:

    * Username = your GitHub username
    * Password = Personal Access Token (PAT)
    * Server:

      ```
      ghcr.io
      ```

  * For **Docker Hub**:

    * Username = Docker Hub username
    * Password = Docker Hub password or access token
    * Server:

      ```
      https://index.docker.io/v1/
      ```

* Example generic command:

  ```bash
  kubectl create secret docker-registry my-secret \
    --docker-server=<registry-url> \
    --docker-username=<username> \
    --docker-password=<password-or-token> \
    --docker-email=<email>
  ```

* After creating the secret, attach it to a Pod or ServiceAccount:

  ```yaml
  imagePullSecrets:
    - name: my-secret
  ```

* Important understanding (for EX188 and real-world):

  * Kubernetes stores these credentials in base64 inside a `.dockerconfigjson`.
  * The kubelet uses this secret when pulling private images.
  * If credentials are wrong → Pod will show `ImagePullBackOff`.
