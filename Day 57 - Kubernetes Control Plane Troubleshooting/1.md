**If CNI is missing – Key Points (Simple):**

* Pod networking will **not work**
* Control plane will still **run normally**
* Control plane uses **hostNetwork**, so it doesn’t depend on CNI
* API server, etcd, scheduler, controller-manager → **still Running**
* Node may show **NotReady / NetworkUnavailable**
* CoreDNS pods usually **stay Pending**
* kube-proxy may start but **Services won’t work**
* DNS will **not work**
* Pods cannot **communicate with each other**
* Installing a CNI **fixes pod networking**
* CNI assigns **Pod IPs and routes**
* After CNI install → cluster becomes **normal**
