#### Q2: List the main components of Kubernetes architecture.
**Detailed Answer:**
Kubernetes follows a **Master-Worker** (Control Plane-Data Plane) architecture.

**1. Control Plane (Master Node) Components:**
These components manage the overall state of the cluster.
- **API Server (kube-apiserver):** The front-end to the control plane. All communication (from `kubectl`, other components, external users) goes through the API Server. It is RESTful and validates and configures data for API objects.
- **etcd:** A highly-available, distributed key-value store. It is the **single source of truth** for the cluster. All cluster state, configuration, and desired status are stored here.
- **Scheduler (kube-scheduler):** Watches for newly created Pods with no assigned Node, and selects a Node for them to run on based on resource requirements, hardware/software constraints, affinity rules, and data locality.
- **Controller Manager (kube-controller-manager):** Runs a collection of control loops that drive the cluster toward the **Desired State**. Examples: Node Controller (monitors node health), Replication Controller (ensures correct number of pod replicas), Endpoint Controller (populates Endpoint objects).
- **Cloud Controller Manager (cloud-controller-manager):** Integrates with the underlying cloud provider's API (AWS, Azure, GCP). It handles cloud-specific control logic like creating Load Balancers or managing storage volumes.

**2. Worker Node Components:**
These components run on every node, maintaining running pods and providing the Kubernetes runtime environment.
- **Kubelet:** The primary "node agent" that runs on every node. It ensures that containers described in PodSpecs are running and healthy. It takes instructions from the API Server.
- **Kube-proxy:** A network proxy that runs on each node. It maintains network rules on nodes. These rules allow network communication to your Pods from network sessions inside or outside of your cluster. (More detail in Q5).
- **Container Runtime:** The software responsible for running containers. Kubernetes supports `containerd`, `CRI-O`, and any other implementation of the Kubernetes CRI (Container Runtime Interface). Docker was deprecated in favor of `containerd`.
