## Question 7: How Do You Structure Python Microservices?

**Answer:** Structuring Python microservices involves organizing code, dependencies, and deployment artifacts for independent scalability.

### Recommended Structure:

```
my-microservice/
├── app/
│   ├── __init__.py
│   ├── main.py              # Entry point
│   ├── api/                 # API routes
│   │   ├── __init__.py
│   │   └── routes.py
│   ├── models/              # Data models
│   │   ├── __init__.py
│   │   └── user.py
│   ├── services/            # Business logic
│   │   ├── __init__.py
│   │   └── user_service.py
│   └── utils/               # Utilities
│       ├── __init__.py
│       └── helpers.py
├── tests/
│   ├── __init__.py
│   ├── test_api.py
│   └── test_services.py
├── requirements.txt
├── Dockerfile
├── docker-compose.yml
├── k8s/
│   ├── deployment.yaml
│   ├── service.yaml
│   └── configmap.yaml
└── README.md
```

### Key Principles:

| Principle | Description |
|-----------|-------------|
| **Single Responsibility** | Each microservice does one thing well |
| **Independent Deployment** | Can be deployed independently |
| **API-First Design** | Well-defined REST/gRPC APIs |
| **Configuration Externalized** | Use ConfigMaps, Secrets, env vars |
| **Health Checks** | Implement `/health` and `/ready` endpoints |
| **Observability** | Logging, metrics, tracing built-in |

### Dockerfile Example:
```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8080
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8080"]
```
