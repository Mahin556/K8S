Here’s a clear explanation of **Calico installation and its components** in Kubernetes, including what gets installed and how everything works internally.

---

# What is Calico?

**Calico** is a Kubernetes **CNI plugin** that provides:

* Pod networking
* Pod IP assignment
* Routing between nodes
* Network policies
* Security rules

It handles both:

* **Networking (CNI)**
* **NetworkPolicy enforcement**

Calico is maintained by Tigera.

---

# 1. Why Calico is Installed

When you run:

```bash
kubeadm init --pod-network-cidr=192.168.0.0/16
```

Kubernetes knows:

```
Pods will use 192.168.0.0/16
```

But Kubernetes **cannot create networking itself**.

So Calico is installed to:

* Assign Pod IPs
* Create routes
* Enable communication

Without Calico:

```
Pods → No IP
Pods → No Network
Node → NotReady
CoreDNS → Pending
```

After Calico:

```
Pods → Get IP
Pods → Network works
Node → Ready
```

# 2. Installing Calico

Typical installation:

```bash

```

Or using operator:

```bash
kubectl apply -f tigera-operator.yaml
kubectl apply -f custom-resources.yaml
```

This installs multiple components.

# 5. Main Calico Components

## 1. calico-node (DaemonSet)

Runs on **every node**.

Check it:

```bash
kubectl get ds -n calico-system
```

Responsibilities:

* Assign Pod IPs
* Configure routes
* Setup networking
* BGP routing
* IP tables rules

Flow:

```
Pod Created
   ↓
kubelet
   ↓
calico-node
   ↓
IP assigned
```

Without calico-node:

```
Pods cannot start
```

---

## 2. calico-kube-controllers

Runs as a Deployment.

Responsibilities:

* IPAM management
* Policy sync
* Node updates
* Garbage collection

Example:

```
Unused IP → Released
Policy → Applied
```

---

## 3. calico-typha

Optional but often installed.

Used for:

* Scaling large clusters
* Reducing API Server load

Flow without Typha:

```
100 nodes → API Server
```

With Typha:

```
100 nodes → Typha → API Server
```

Small clusters don’t need it.

---

## 4. tigera-operator

Operator that installs and manages Calico.

Responsibilities:

* Install Calico
* Upgrade Calico
* Configure Calico

You typically install:

```
tigera-operator
   ↓
Installs
   ↓
calico-node
calico-controllers
typha
```

# 6. How Pods Get IPs

When a Pod is created:

```
Scheduler → Assign node
kubelet → Create pod
kubelet → Call CNI
Calico → Assign IP
Pod → Running
```

Example:

```
Pod CIDR = 192.168.0.0/16
Pod IP = 192.168.1.10
```

---

# 7. Pod CIDR vs Node CIDR

## Node IP (VPC CIDR)

Example:

```
172.31.43.189
```

Used by:

* Nodes
* API Server
* SSH

---

## Pod IP (Pod CIDR)

Example:

```
192.168.1.10
```

Used by:

* Pods
* CoreDNS
* Applications

---

# 8. Why CoreDNS Was Pending

Before Calico:

```
CoreDNS → Pending
```

Because:

```
No CNI → No IP → No Start
```

After Calico:

```
CoreDNS → Running
```

Because:

```
Calico → IP assigned
```

Example:

```
CoreDNS = 192.168.235.132
```

# 9. How Networking Works

If Pod A talks to Pod B:

```
Pod A → calico-node
        ↓
     Route
        ↓
   calico-node
        ↓
     Pod B
```

---

# 10. Routing in Calico

Calico uses:

* BGP (default)
* VXLAN (optional)
* IP-in-IP (optional)

Example:

```
Node1 → 192.168.1.0/24
Node2 → 192.168.2.0/24
```

Routes:

```
Node1 knows → Node2 subnet
Node2 knows → Node1 subnet
```

---

# 11. Control Plane Pods vs Normal Pods

Control plane pods:

```
hostNetwork: true
```

So they use:

```
Node IP
```

Example:

```
kube-apiserver → 172.31.43.189
```

---

Normal Pods:

```
Use Pod CIDR
```

Example:

```
nginx → 192.168.1.5
```
