### Roll out a new version gradually by exposing it to a small percentage of users first, then increasing traffic as metrics look good.

**Solution:**

**Stable Deployment (Version 1 - Full Traffic):**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-v1-stable
spec:
  replicas: 5
  selector:
    matchLabels:
      app: web-app
      version: v1
  template:
    metadata:
      labels:
        app: web-app
        version: v1
    spec:
      containers:
      - name: web
        image: webapp:1.0
        ports:
        - containerPort: 80
```

**Canary Deployment (Version 2 - Small Traffic):**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-v2-canary
spec:
  replicas: 1                          # Only 1 replica = ~17% traffic
  selector:
    matchLabels:
      app: web-app
      version: v2
  template:
    metadata:
      labels:
        app: web-app
        version: v2
    spec:
      containers:
      - name: web
        image: webapp:2.0
        ports:
        - containerPort: 80
```

**Service (Shared Label):**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: web-service
spec:
  selector:
    app: web-app                        # Shared label matches both versions!
  ports:
  - port: 80
    targetPort: 80
```

**Managing Canary Rollout:**
```bash
# Phase 1: Start with 1 canary replica (~17% traffic with 5 stable + 1 canary)
kubectl apply -f canary-deployment.yaml

# Phase 2: If metrics look good, scale up canary
kubectl scale deployment app-v2-canary --replicas=3    # ~38% traffic

# Phase 3: Full rollout
kubectl scale deployment app-v2-canary --replicas=5    # ~50% traffic
kubectl scale deployment app-v1-stable --replicas=0    # 0% traffic

# Instant rollback if issues appear
kubectl scale deployment app-v2-canary --replicas=0
```

**Key Points:**
- Both deployments share a common label (`app: web-app`)
- Service uses shared label to distribute traffic across both versions
- Traffic distribution is based on replica count ratio
- 5 stable + 1 canary = canary gets ~17% of traffic
- Scale up canary replicas gradually to increase traffic
- Instant rollback by scaling canary to zero
- No downtime during the entire process
