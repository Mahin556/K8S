### Blue deployment runs in production with 3 replicas. Increase capacity to 5 replicas and roll out a green version using blue-green deployment strategy for zero downtime.

**Solution:**

**Current Blue Deployment (Production):**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-blue
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
      version: blue
  template:
    metadata:
      labels:
        app: my-app
        version: blue
    spec:
      containers:
      - name: app
        image: myapp:1.0
        ports:
        - containerPort: 8080
```

**Green Deployment (New Version):**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-green
spec:
  replicas: 5                          # Increased capacity
  selector:
    matchLabels:
      app: my-app
      version: green
  template:
    metadata:
      labels:
        app: my-app
        version: green
    spec:
      containers:
      - name: app
        image: myapp:2.0
        ports:
        - containerPort: 8080
```

**Service (Initially pointing to Blue):**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: app-service
spec:
  selector:
    app: my-app
    version: blue                      # Initially points to blue
  ports:
  - port: 80
    targetPort: 8080
  type: ClusterIP
```

**Switching to Green:**
```bash
# Update service selector to route traffic to green
kubectl patch service app-service -p '{"spec":{"selector":{"version":"green"}}}'
```

**Key Points:**
- Both blue and green deployments exist simultaneously in the cluster
- Blue continues serving live traffic while green is deployed
- No traffic changes until service selector is updated
- Switch traffic by changing service selector from `version: blue` to `version: green`
- Zero downtime during cutover
- Blue remains running for instant rollback if needed
- Green deployment scales to 5 replicas for increased capacity
