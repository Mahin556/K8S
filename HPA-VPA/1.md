  name: nginx-deployment-hpa

    kind: Deployment
    name: nginx-deployment

  minReplicas: 3
  maxReplicas: 10

  behavior:
    scaleUp:
      stabilizationWindowSeconds: 30
      policies:
        - type: Pods
          value: 1
          periodSeconds: 10

      stabilizationWindowSeconds: 30
      policies:
        - type: Pods
          value: 1
          periodSeconds: 20

        target:
          type: Utilization

```
How HPA Works

  Every 15 seconds:
    → Check metrics (CPU/Memory)
    → Calculate desired replicas
    → Apply limits:
        - minReplicas
        - maxReplicas
        - scaling policies
        - stabilization window
    → Then adjust replicas

------------------------------------------------

Scaling Formula

  Desired Replicas =
  currentReplicas × ( currentMetric / targetMetric )

  Example:
    3 replicas
    CPU = 50%
    Target = 10%

  3 × (50/10) = 15 replicas
  (but capped by maxReplicas)

------------------------------------------------

What is periodSeconds?

  periodSeconds does NOT control metric checking.

  It controls how fast scaling is allowed.

  Example:

  policies:
    - type: Pods
      value: 1
      periodSeconds: 10

  Meaning:
  → HPA can add only 1 pod every 10 seconds.

  It is a scaling rate limiter.

------------------------------------------------

What is stabilizationWindowSeconds?

  Example:

  scaleUp:
    stabilizationWindowSeconds: 30
  scaleDown:
    stabilizationWindowSeconds: 30

  Meaning:
  → HPA waits 30 seconds before scaling up/down.
  → Prevents rapid up/down (flapping).

------------------------------------------------

HPA uses CPU "requests", NOT limits.

  If you don’t define:
  resources:
    requests:
      cpu: 100m

  HPA won’t work properly.

```
