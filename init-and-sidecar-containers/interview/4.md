### Microservice needs to talk to multiple external APIs (payment, shipping) with different authentication and rate limiting. Create an ambassador container to handle all outbound calls.

**Solution:**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-with-ambassador
spec:
  replicas: 2
  selector:
    matchLabels:
      app: app-with-ambassador
  template:
    metadata:
      labels:
        app: app-with-ambassador
    spec:
      containers:
      # Main Application Container
      - name: main-application
        image: my-microservice:latest
        env:
        - name: PROXY_URL
          value: "http://localhost:9000"
        # Application sends ALL requests to localhost:9000
      
      # Ambassador Container
      - name: ambassador
        image: ambassador-proxy:latest
        ports:
        - containerPort: 9000
        env:
        - name: PAYMENT_API_URL
          value: "https://payment-api.example.com"
        - name: SHIPPING_API_URL
          value: "https://shipping-api.example.com"
        - name: PAYMENT_API_KEY
          valueFrom:
            secretKeyRef:
              name: api-secrets
              key: payment-api-key
```

**Key Points:**
- **Ambassador Pattern**: proxy container that handles external communication
- Main application only knows `localhost:9000` - simple and clean
- Ambassador handles:
  - Routing requests to correct external API (payment vs shipping)
  - Injecting authentication headers
  - Applying rate limiting rules
  - Managing API keys securely
- Main application remains simple and focused on business logic
- External API complexity is isolated in the ambassador container
- Both containers share the pod's network namespace
