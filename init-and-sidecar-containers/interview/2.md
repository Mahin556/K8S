### Database migration must run before the main application container starts. If migration fails, the application should never start.

**Solution - Init Containers:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app-with-migration
spec:
  initContainers:
  - name: db-migration
    image: busybox:latest
    command:
    - sh
    - -c
    - |
      echo "Running database migration..."
      # Replace with actual migration command
      # ./run-migration.sh
      echo "Migration completed successfully"
  containers:
  - name: application
    image: nginx:latest
    ports:
    - containerPort: 80
```

**Key Points:**
- **Init Containers** run before main containers start
- They run sequentially to completion
- If an init container fails, Kubernetes restarts it until it succeeds
- Main container (application) starts ONLY after all init containers succeed
- Ensures database migration completes before application runs
- If migration consistently fails, application never starts (desired behavior)
- Use cases: database migrations, file permissions, dependency checks
