## What is a sidecar container and when to use it?

### What is a Sidecar Container?
A sidecar container runs **alongside your main container** in the same pod to extend its functionality without modifying the main container.

### Example with Istio:
- When you deploy Istio, it uses **mutating webhook admission controllers**
- It injects a sidecar container (Envoy proxy) beside your main application container
- Your pod now has 2 containers instead of 1
- The sidecar handles traffic routing, mTLS, and other service mesh features
- **Your main application container is NOT touched or modified**

### Generic Definition:
"Whenever you want to extend the functionality of your existing container without touching the original one, you use a sidecar container."

### Use Cases:
- **Logging:** Sidecar collects and ships logs
- **Monitoring:** Sidecar collects metrics
- **Service Mesh:** Sidecar handles traffic routing (Istio/Envoy)
- **Security:** Sidecar handles authentication/authorization

### Different Types of Containers in Kubernetes:

| Type | Description |
|------|-------------|
| **Init Containers** | Run before main container starts |
| **Sidecar Containers** | Run alongside main container |
| **Ambassador Containers** | Proxy external connections |
| **Adapter Containers** | Transform output/data |
