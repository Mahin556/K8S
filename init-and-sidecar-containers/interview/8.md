#### Q10: What is an Init Container?
**Detailed Answer:**
Init Containers are specialized containers that run **before** app containers in a Pod. They always run to completion sequentially.

**Key Differences from App Containers:**
1.  **Sequential Execution:** `init-1` must finish successfully before `init-2` starts.
2.  **No Liveness/Readiness Probes:** They either succeed (exit 0) or fail (exit non-zero). If they fail, the Pod restarts the Init Container (based on `restartPolicy`).
3.  **Different Image:** You can use a different image (e.g., `busybox` with `sed`/`awk`) for setup tasks, keeping your main app image small and secure.

**Use Cases:**
- Waiting for a dependency (Database, Cache) to be available using `nc -z db 5432`.
- Running database schema migrations.
- Downloading assets or configurations from Git/Secrets Manager before the app starts.
