### Application logs must be shipped to an external system in real time. Use a sidecar container to tail logs and send them to a remote server.

**Solution:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app-with-log-shipper
spec:
  volumes:
  - name: shared-logs
    emptyDir: {}
  
  containers:
  # Main Application Container
  - name: app-container
    image: myapp:latest
    volumeMounts:
    - name: shared-logs
      mountPath: /var/log/app
    # Application writes logs to /var/log/app/app.log
  
  # Log Shipper Sidecar Container
  - name: log-shipper
    image: fluentd:latest  # or any log shipper
    volumeMounts:
    - name: shared-logs
      mountPath: /var/log/app
    env:
    - name: REMOTE_LOG_SERVER
      value: "log-server.example.com:5140"
    command:
    - sh
    - -c
    - |
      tail -f /var/log/app/app.log | \
      while read line; do
        echo "$line" | nc $REMOTE_LOG_SERVER
      done
```

**Key Points:**
- **Shared Volume** (`emptyDir`) enables communication between containers
- `emptyDir` is temporary storage that lives as long as the pod runs
- Main application writes logs to the shared volume
- Log shipper reads from the same shared volume
- Sidecar tails the log file in real time and forwards to external system
- Architecture is clean and decoupled - application doesn't know about logging
- Both containers can read/write to the shared folder
