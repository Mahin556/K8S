## Question 6: What Are Sidecar Containers?

**Question:** What are sidecar containers and what is their purpose?

### Definition:
Sidecar containers (also known as composite containers) are **additional containers** that extend and enhance the main application container. They run alongside the main container in the same pod.

### Purpose:
- Acts as a **helper container** for the application
- Extends functionality without modifying the main container's codebase
- Separates critical tasks from the main application

### Common Use Cases:

| Use Case | Description |
|----------|-------------|
| **Network Proxies** | SSL/TLS termination, mTLS, traffic routing |
| **Service Mesh** | Istio/Envoy proxy for service-to-service communication |
| **Logging** | Collect and ship application logs |
| **Monitoring** | Collect metrics from the application |
| **Security** | Handle authentication/authorization |
| **Batch Processing** | Offload processing tasks |

### How to Verify Sidecar Containers:
```bash
# Check pods in the namespace
kubectl get pods -n <namespace>

# Describe a pod to see all containers
kubectl describe pod <pod-name> -n <namespace>
# Look for multiple containers: "istio-init", "istio-proxy", "app"
```

### Key Points:
- A pod can have **multiple containers** (e.g., 2/2 running means 2 containers)
- Sidecar containers are automatically injected (via mutating webhooks) in service mesh setups
- They handle cross-cutting concerns without changing application code
