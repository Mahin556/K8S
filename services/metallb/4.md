If you're asking:

> **Can the same MetalLB IP route traffic to a MySQL pod and an SMTP pod?**

The answer is **yes**, but **how** depends on whether the services use different ports or the same port.

---

# Option 1: Same MetalLB IP, Different Ports (Recommended)

This is the most common approach.

Suppose MetalLB assigns:

```text
192.168.1.200
```

Create two Kubernetes Services that share the same LoadBalancer IP.

### MySQL Service

```yaml
apiVersion: v1
kind: Service
metadata:
  name: mysql
spec:
  type: LoadBalancer
  loadBalancerIP: 192.168.1.200
  selector:
    app: mysql
  ports:
  - port: 3306
    targetPort: 3306
```

### SMTP Service

```yaml
apiVersion: v1
kind: Service
metadata:
  name: smtp
spec:
  type: LoadBalancer
  loadBalancerIP: 192.168.1.200
  selector:
    app: smtp
  ports:
  - port: 25
    targetPort: 25
```

Normally, Kubernetes won't let two Services share the same IP unless you enable sharing.

---

## Enable IP Sharing

Both Services must have the same annotation:

```yaml
metadata:
  annotations:
    metallb.io/allow-shared-ip: mail-stack
```

Example:

```yaml
metadata:
  name: mysql
  annotations:
    metallb.io/allow-shared-ip: mail-stack
```

```yaml
metadata:
  name: smtp
  annotations:
    metallb.io/allow-shared-ip: mail-stack
```

MetalLB will then allow both Services to use:

```text
192.168.1.200
```

Traffic flows like this:

```text
Client
     |
192.168.1.200
     |
+----------------+
| MetalLB Service|
+----------------+
   |         |
3306        25
 |           |
MySQL      SMTP
```

Clients connect using:

```text
mysql.example.com:3306
```

or

```text
mail.example.com:25
```

Both resolve to the same IP.

---

# Option 2: Use One Service with Multiple Ports

If both ports belong to the **same application/pod**, you can expose them through one Service:

```yaml
ports:
- name: mysql
  port: 3306
  targetPort: 3306

- name: smtp
  port: 25
  targetPort: 25
```

This works only if the selected pods provide **both** services.

---

# Option 3: Use an Ingress (HTTP/HTTPS Only)

Ingress controllers route based on:

* Host
* Path

Example:

```text
app.example.com
api.example.com
```

This works only for HTTP/HTTPS traffic, **not** for MySQL or SMTP.

So **Ingress cannot route MySQL (3306) or SMTP (25)**.

---

# Option 4: TCP/UDP Proxy

If you want advanced routing for protocols like MySQL, SMTP, IMAP, etc., you can use a proxy such as:

* NGINX (TCP stream module)
* HAProxy
* Envoy

The proxy receives traffic on a MetalLB IP and forwards it based on the destination port.

Example:

```text
Internet
    |
MetalLB IP
192.168.1.200
    |
+----------------+
| HAProxy/NGINX  |
+----------------+
   |        |
3306      25
 |          |
MySQL     SMTP
```

---

# Can MetalLB itself route based on ports?

**No.**

MetalLB's job is only to:

* Allocate external IPs.
* Advertise those IPs (Layer 2 or BGP).

It does **not** inspect ports or make routing decisions.

Kubernetes Services and `kube-proxy` handle the mapping from **IP:port** to the correct backend pods.

---

### Your use case

If you have:

* MySQL pod on port **3306**
* SMTP pod on port **25**

and you want them both reachable via:

```text
192.168.1.200
```

then the recommended setup is:

* Two separate `LoadBalancer` Services.
* Both use `loadBalancerIP: 192.168.1.200`.
* Both include the same `metallb.io/allow-shared-ip` annotation.
* Each exposes a different port (3306 for MySQL, 25 for SMTP).

This gives you one external IP serving multiple non-HTTP services on different ports.
