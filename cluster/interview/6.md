#### Q4: What is the role of kube-proxy in Cluster?
**Detailed Answer:**
`kube-proxy` is a daemon running on each node that implements the **Kubernetes Service** concept. A Service is an abstraction defining a logical set of Pods and a policy to access them (virtual IP).

**What it does:**
1.  **Watches API Server:** It watches for changes to `Services` and `Endpoints` (the actual IP addresses of Pods backing a service).
2.  **Manages Network Rules:** It updates the node's network rules (using **iptables** or **IPVS** modes) to redirect traffic destined for the Service's **ClusterIP** to the actual Pod IPs.
3.  **Load Balancing:** It provides basic layer-4 round-robin load balancing across the backend pods.

**Modes of Operation:**
- **iptables (Default Legacy):** Creates a massive chain of rules. Performance degrades significantly with >10,000 services due to sequential rule matching.
- **IPVS (Recommended):** Uses Linux Kernel IP Virtual Server. It uses a hash table for lookups, providing **O(1)** performance regardless of the number of services. Supports more load balancing algorithms (RR, Least Connections, Source Hash).
