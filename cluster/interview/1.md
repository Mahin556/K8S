##  The master node is not coming up. The API server is not responding. How would you troubleshoot this?

### Troubleshooting Steps:

**1. Check kubelet Status:**
```bash
systemctl status kubelet
journalctl -u kubelet -f
```

**2. Check Static Pod Manifest Path:**
```bash
# Verify the static pod path in kubelet config
cat /var/lib/kubelet/config.yaml | grep staticPodPath
# Default: /etc/kubernetes/manifests/

# Check if manifest files exist
ls -la /etc/kubernetes/manifests/
```

**3. Check API Server Port:**
```bash
# Check if API server is listening on port 6443
netstat -tlnp | grep 6443
# or
ss -tlnp | grep 6443
```

**4. Check Authentication Files:**
```bash
# Verify admin.conf exists and is valid
cat /etc/kubernetes/admin.conf

# Check certificate validity
openssl x509 -in /etc/kubernetes/pki/apiserver.crt -text -noout | grep -A2 "Validity"
```

**5. Check Container Runtime:**
```bash
# Check if containerd/CRI-O is running
systemctl status containerd
# or
crictl ps
```

**6. Common Issues:**
- Static pod path commented out in kubelet config → Uncomment it
- Certificate expired → Renew certificates
- Manifest files missing or corrupted → Restore from backup
- Container runtime not running → Start containerd/CRI-O

**7. Check Logs:**
```bash
# Check kubelet logs
journalctl -u kubelet -n 100 --no-pager

# Check container logs (if running)
crictl logs <container-id>

# Or check pod logs if API server is accessible
kubectl logs -n kube-system <pod-name>
```

**8. Audit Logs (if enabled):**
```bash
# Linux audit service can track file changes
# Check who modified files and when
ausearch -f /etc/kubernetes/manifests/
```

**9. crictl**

```bash
Use the crictl command:
crictl ps # Look for api server container
crictl logs <container_id>
```
