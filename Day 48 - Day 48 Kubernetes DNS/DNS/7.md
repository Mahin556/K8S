* 🔹 **DNS Zone = Administrative portion of DNS namespace**

A **zone** is a part of the DNS hierarchy that is managed by a specific DNS server.

---

* 🔹 Simple Definition

Zone =
A domain (or part of it) + all its DNS records stored on an authoritative DNS server.

---

* 🔹 Example

If you own:

```
example.com
```

The zone file for `example.com` may contain:

```
A     www      192.168.1.10
MX    mail     mail.example.com
NS              ns1.example.com
```

That collection of records = **example.com zone**

---

* 🔹 Domain vs Zone (Important Difference)

Domain = logical name in DNS hierarchy
Zone = actual configured data stored on DNS server

Example:

```
example.com
   ├── www.example.com
   ├── mail.example.com
   └── blog.example.com
```

If `blog.example.com` is delegated to another DNS server:

Then:

* `example.com` = one zone
* `blog.example.com` = separate zone

Even though both are domains.

---

* 🔹 Zone Types

1️⃣ **Primary (Master) Zone**

* Original writable copy
* Stored in zone file
* Example: `/var/named/example.com.zone`

2️⃣ **Secondary (Slave) Zone**

* Read-only copy
* Receives data via AXFR (zone transfer)

3️⃣ **Forward Zone**

* Name → IP mapping

4️⃣ **Reverse Zone**

* IP → Name mapping
* Example:

  ```
  8.8.8.8 → dns.google
  ```

  Reverse zone name:

  ```
  8.8.8.in-addr.arpa
  ```

---

* 🔹 What is a Zone File?

A text file that contains DNS records.

Example:

```
$TTL 86400
@   IN  SOA ns1.example.com. admin.example.com. (
        2025022601 ; serial
        3600       ; refresh
        900        ; retry
        1209600    ; expire
        86400 )    ; minimum

@     IN  NS  ns1.example.com.
@     IN  NS  ns2.example.com.
www   IN  A   192.168.1.10
mail  IN  A   192.168.1.20
@     IN  MX  10 mail.example.com.
```

---

* 🔹 Why Zones Exist

* DNS is distributed

* No single server stores entire internet DNS

* Each authoritative server manages its own zone

* Zones allow delegation

---

* 🔹 Real Internet Flow

When you run:

```bash
dig example.com +trace
```

You will see:

Root (.)
→ .com TLD zone
→ example.com zone
→ final answer

Each step is a different zone.

---

* 🔹 DevOps View

Zone = ownership boundary

If you control the zone:

* You control A records
* MX records
* TXT (SPF, DKIM)
* Subdomain delegation
* TTL
