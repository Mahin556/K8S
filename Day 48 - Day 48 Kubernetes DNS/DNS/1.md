* DNS cache location depends on **what is doing DNS caching** on your system

  * OS resolver
  * systemd-resolved
  * nscd
  * dnsmasq
  * Browser

---

* 🔹 On modern Linux (Ubuntu 20+, RHEL 8+, etc.) → usually **systemd-resolved**

  * It does NOT store cache in a file
  * Cache is stored in memory

  Check if running:

  ```bash
  systemctl status systemd-resolved
  ```

  View cache statistics:

  ```bash
  resolvectl statistics
  ```

  Flush cache:

  ```bash
  sudo resolvectl flush-caches
  ```

  Or older command:

  ```bash
  sudo systemd-resolve --statistics
  ```

---

* 🔹 If using `nscd` (Name Service Cache Daemon)

  Check service:

  ```bash
  systemctl status nscd
  ```

  Cache is memory-based, not stored in a readable file.

  Show statistics:

  ```bash
  nscd -g
  ```

  Flush DNS cache:

  ```bash
  sudo nscd -i hosts
  ```

---

* 🔹 If using `dnsmasq`

  Check:

  ```bash
  systemctl status dnsmasq
  ```

  Cache is also in memory.

  Restart to clear:

  ```bash
  sudo systemctl restart dnsmasq
  ```

---

* 🔹 Check which DNS server you are using

  ```bash
  cat /etc/resolv.conf
  ```

  If you see:

  ```
  nameserver 127.0.0.53
  ```

  → systemd-resolved is caching locally.

---

* 🔹 Browser DNS cache

  Browsers maintain their own cache.

  Chrome:

  ```
  chrome://net-internals/#dns
  ```

---

* 🔹 Important concept (DevOps understanding)

  DNS caching can exist at multiple layers:

  * Application (browser)
  * OS resolver
  * Local caching daemon
  * ISP DNS server
  * Upstream recursive DNS
  * Authoritative DNS

  That’s why DNS changes sometimes “don’t update”.

---

* 🔹 Quick way to test if cache exists

  Compare:

  ```bash
  dig google.com
  ```

  vs

  ```bash
  dig google.com @8.8.8.8
  ```

  If results differ → local caching or different resolver in use.
