* NetworkManager **does not directly edit `/etc/resolv.conf` manually like a normal file**
* It **generates and manages it automatically**

---

* 🔹 First understand this:

```bash
ls -l /etc/resolv.conf
```

You will usually see:

* Symlink to:

  * `/run/NetworkManager/resolv.conf`
  * OR `/run/systemd/resolve/stub-resolv.conf`
  * OR `/run/systemd/resolve/resolv.conf`

That means:
→ `/etc/resolv.conf` is NOT a real file
→ It is dynamically managed

---

* 🔹 How NetworkManager sets DNS

When:

* You connect to WiFi
* Plug Ethernet
* Enable VPN

NetworkManager gets DNS from:

* DHCP server (most common)
* Static config
* VPN profile
* Manual nmcli config

Then it:

* Writes DNS servers into `/run/NetworkManager/resolv.conf`
* Updates `/etc/resolv.conf` symlink

---

* 🔹 Check current DNS via NetworkManager

```bash
nmcli device show | grep DNS
```

or

```bash
nmcli connection show
```

Detailed view:

```bash
nmcli connection show <connection-name>
```

---

* 🔹 Where DNS actually comes from (DHCP case)

When interface uses DHCP:

* DHCP server sends:

  * IP address
  * Gateway
  * DNS server
* NetworkManager stores it
* Writes into resolv.conf dynamically

---

* 🔹 If system uses systemd-resolved (modern Ubuntu)

Flow becomes:

DHCP → NetworkManager → systemd-resolved → stub resolver (127.0.0.53) → /etc/resolv.conf

Check:

```bash
cat /etc/resolv.conf
```

If you see:

```
nameserver 127.0.0.53
```

That means:

* systemd-resolved is managing DNS
* Real DNS servers are internal

Check real servers:

```bash
resolvectl status
```

---

* 🔹 Set manual DNS using NetworkManager

```bash
nmcli connection modify <connection-name> ipv4.dns "8.8.8.8 1.1.1.1"
nmcli connection modify <connection-name> ipv4.ignore-auto-dns yes
nmcli connection up <connection-name>
```

That:

* Overrides DHCP DNS
* Forces custom DNS

---

* 🔹 Prevent NetworkManager from managing resolv.conf (not recommended normally)

Edit:

```
/etc/NetworkManager/NetworkManager.conf
```

Add:

```
[main]
dns=none
```

Then restart:

```bash
systemctl restart NetworkManager
```

Now you can manually edit `/etc/resolv.conf`.

---

* 🔹 Summary (important for DevOps understanding)

NetworkManager:

* Gets DNS from DHCP or manual config
* Writes to runtime file
* Controls `/etc/resolv.conf`
* Works with systemd-resolved if enabled
* Prevents manual edits from persisting
