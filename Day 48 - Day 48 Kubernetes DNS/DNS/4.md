To make DNS settings **persistent** with NetworkManager (so reboot or reconnect does NOT overwrite them), use one of these proper methods — do NOT edit `/etc/resolv.conf` directly.

---

### ✅ Method 1 — Set Persistent DNS via `nmcli` (Recommended)

1️⃣ Find your connection name:

```bash
nmcli connection show
```

2️⃣ Set custom DNS:

```bash
nmcli connection modify <connection-name> ipv4.dns "8.8.8.8 1.1.1.1"
```

3️⃣ Disable DHCP DNS override:

```bash
nmcli connection modify <connection-name> ipv4.ignore-auto-dns yes
```

4️⃣ Bring connection up again:

```bash
nmcli connection up <connection-name>
```

Now DNS will persist across:

* Reboot
* Network reconnect
* Interface restart

---

### ✅ Method 2 — Using `nmtui` (Text UI)

```bash
nmtui
```

* Edit connection
* Set DNS servers
* Check "Ignore automatically obtained DNS"
* Save and reconnect

---

### ✅ Method 3 — If Using systemd-resolved

If `/etc/resolv.conf` shows:

```
nameserver 127.0.0.53
```

Then systemd-resolved is in use.

Set DNS through NetworkManager (Method 1), then verify:

```bash
resolvectl status
```

---

### ❌ Do NOT do this (Not persistent)

```bash
vi /etc/resolv.conf
```

Because:

* NetworkManager overwrites it
* Reboot resets it
* DHCP replaces it

---

### 🔥 If You Want Manual Control of /etc/resolv.conf

Disable NetworkManager DNS control:

Edit:

```bash
sudo vi /etc/NetworkManager/NetworkManager.conf
```

Add:

```
[main]
dns=none
```

Restart:

```bash
sudo systemctl restart NetworkManager
```

Then manually create:

```bash
sudo vi /etc/resolv.conf
```

But this is **not recommended** for production unless you know what you're doing.

---

### 🎯 Best Practice (DevOps / Production)

* Use `nmcli`
* Keep DHCP enabled
* Override DNS properly
* Never edit resolv.conf manually
