### Why do you use 3 master nodes? Why not 2 or 4?

#### The Answer - etcd Quorum:

**The Formula:**
```
Available Votes ≥ (Total Votes / 2) + 1
```

**For 3 Master Nodes:**
- Total Votes = 3
- Minimum votes needed = (3/2) + 1 = 1.5 + 1 = 2 (round down)
- **Only 1 node can fail** - if 2 nodes fail, etcd stops working
- If 1 node goes down, 2 remain → quorum satisfied → cluster operates

**For 4 Master Nodes (Why NOT):**
- Total Votes = 4
- Minimum votes needed = (4/2) + 1 = 2 + 1 = 3
- If network splits into 2+2 → each side has 2 votes
- **Neither side reaches quorum (3)** → Split-brain condition
- Both sides might try to write → data corruption

#### Split-Brain Problem:
- When a cluster splits into two partitions
- Both partitions think they should be the leader
- Both write to etcd separately → **data corruption**
- Quorum prevents this by requiring majority

#### Important etcd Facts:
- Only **one etcd node is the Leader** at a time
- Leader handles all **write requests**
- Members can handle **read requests**
- If leader fails, **automatic election** happens
- etcd uses the **RAFT consensus algorithm** for data synchronization

#### Commands to Know:
```bash
# Find etcd leader
kubectl describe pod <etcd-pod> -n kube-system | grep -i leader

# Or using etcdctl
etcdctl endpoint status --endpoints=<etcd-endpoints>
```
