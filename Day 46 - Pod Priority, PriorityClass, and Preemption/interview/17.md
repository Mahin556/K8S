### When to Use Pod Anti-Affinity (Real Scenario):

**Problem:** Two Redis pods accidentally get scheduled on the same node. If that node fails, both Redis instances go down simultaneously.

**Solution:** Use **Pod Anti-Affinity** to keep them apart:
- Two Redis pods should NEVER run on the same node
- Ensures high availability

**Problem 2:** Database pod consumes high CPU/memory. If an application pod also lands on the same node, performance degrades.

**Solution:** Use **Pod Anti-Affinity**:
- Database pod and Application pod should NOT run on the same node
- Keeps resource-intensive workloads separate
