## Troubleshooting a Pod Stuck in `Pending` State - 1 (Scheduler Down)? A pod created using `kubectl run ram --image=nginx` is stuck in a `Pending` state. You need to find the root cause.

**Symptom:** `kubectl describe pod ram` shows no recent events, and the pod is not being scheduled to any node.

**Root Cause:** The **kube-scheduler** service was intentionally stopped, preventing new pods from being assigned to nodes.

**Verification:**
-   Describe the pod and observe there are no scheduling events.
-   Check the status of control plane components:
    ```bash
    kubectl get componentstatuses
    ```
    This command shows the health status of the scheduler, controller-manager, and etcd. A missing or unhealthy scheduler component will be evident here.

**Follow-up Question:** If the scheduler is not running, is there any way to deploy a container?

**Answer:** Yes, by using the `nodeName` field in the pod specification.
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: test-pod
spec:
  containers:
  - name: nginx
    image: nginx
  nodeName: worker-2  # Directly schedules the pod to this node
```
*Note: Other scheduling rules like `nodeSelector`, `affinity`, `anti-affinity`, and `tolerations` will NOT work without the scheduler.*
