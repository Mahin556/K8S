## 21. How Does the Kubernetes Scheduler Assign Pods to Nodes?

The Kubernetes Scheduler (`kube-scheduler`) is a control plane component responsible for deciding which node should run a Pod.

Its main goal is:

* Efficient resource utilization
* High availability
* Proper workload placement

---

# Kubernetes Scheduling Workflow

## 1. Filtering Phase (Predicates)

The scheduler first checks all nodes and removes nodes that cannot run the Pod.

### Common Filtering Checks

* Insufficient CPU or memory
* Node taints and tolerations
* Node selectors
* Node affinity/anti-affinity rules
* Storage/volume constraints
* Port conflicts

---

### Example

If a Pod requests:

```yaml id="5m2p8"
resources:
  requests:
    cpu: "2"
    memory: "4Gi"
```

Nodes without enough:
* CPU
* Memory
are automatically filtered out.

---

# 2. Scoring Phase (Priorities)

After filtering:
* Remaining nodes are scored.

The scheduler prefers nodes based on:
* Resource balance
* Least resource usage
* Affinity preferences
* Topology spread
* Custom scheduler priorities

---

### Example

A node with:
* Lower CPU usage
* Better resource distribution
may receive:
* Higher score

---

# 3. Binding Phase

Finally:
* The highest-scoring node is selected.

The scheduler:
* Binds the Pod to that node
* Updates the API Server

Then:
* Kubelet on that node starts the Pod.

---

# Simple Scheduling Flow

```text id="8k1n4"
Pod Created
     ↓
Scheduler Checks Nodes
     ↓
Unsuitable Nodes Filtered Out
     ↓
Remaining Nodes Scored
     ↓
Best Node Selected
     ↓
Pod Bound to Node
```

---

# Important Scheduling Concepts

## Node Selector

Schedules Pod only on matching nodes.

Example:

```yaml id="3x7q2"
nodeSelector:
  env: production
```

---

# Taints and Tolerations

Used to:
* Restrict Pods from certain nodes
Example:
* GPU nodes
* Dedicated nodes

---

# Affinity and Anti-Affinity

Controls:
* Pod placement rules
Example:
* Keep Pods together
* Separate replicas across nodes

---

# Resource Requests and Limits

Scheduler mainly uses:

* Resource requests

to decide placement.

Example:

```yaml id="6v1m5"
resources:
  requests:
    cpu: "500m"
```

---

# High-Level Goal of Scheduler

The scheduler tries to:

* Balance workloads
* Prevent resource exhaustion
* Improve reliability
* Optimize cluster utilization

---

# Interview-Ready Answer

“The Kubernetes scheduler is responsible for assigning Pods to nodes. It works in three phases: filtering, scoring, and binding. First, it filters out nodes that cannot run the Pod based on factors like CPU, memory, taints, affinity rules, or storage constraints. Then it scores the remaining nodes according to scheduling priorities such as resource balance and topology preferences. Finally, it binds the Pod to the highest-scoring node by updating the API Server.”
