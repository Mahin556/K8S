### Deploying critical web frontend for high availability. Multiple replicas should NOT be on the same node to avoid single point of failure.

**Solution:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-frontend
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web-frontend
  template:
    metadata:
      labels:
        app: web-frontend
    spec:
      affinity:
        podAntiAffinity:
          # Strict rule - Node level
          requiredDuringSchedulingIgnoredDuringExecution:
          - labelSelector:
              matchExpressions:
              - key: app
                operator: In
                values:
                - web-frontend
            topologyKey: "kubernetes.io/hostname"
          
          # Soft rule - Zone level
          preferredDuringSchedulingIgnoredDuringExecution:
          - weight: 100
            podAffinityTerm:
              labelSelector:
                matchExpressions:
                - key: app
                  operator: In
                  values:
                  - web-frontend
                topologyKey: "topology.kubernetes.io/zone"
      
      containers:
      - name: web-frontend
        image: web-frontend:latest
        ports:
        - containerPort: 80
```

**Key Points:**
- **Pod Anti-Affinity** repels pods from specific nodes/zones
- `requiredDuringSchedulingIgnoredDuringExecution` (strict): Pod won't schedule if rule can't be met
- `preferredDuringSchedulingIgnoredDuringExecution` (soft): Scheduler tries but won't block
- Node-level anti-affinity: No two web frontend pods on the same node
- Zone-level anti-affinity: Spreads pods across different availability zones
- Prevents single node failure from taking down multiple replicas
- Ensures high availability and fault tolerance
- `topologyKey: kubernetes.io/hostname` ensures unique node placement
