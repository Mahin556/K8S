### Multi-Container Pod - Payment Service with Sidecar Log Processor

**Scenario:** E-commerce application has a payment service that processes orders. Need a separate log processor to parse and send logs to Elasticsearch. Both must share volume and scale as a unit.

**Solution:**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: payment-with-logger
spec:
  replicas: 3
  selector:
    matchLabels:
      app: payment-with-logger
  template:
    metadata:
      labels:
        app: payment-with-logger
    spec:
      volumes:
      - name: shared-logs
        emptyDir: {}
      
      containers:
      # Main Payment Service Container
      - name: payment-service
        image: payment-service:latest
        ports:
        - containerPort: 8080
        volumeMounts:
        - name: shared-logs
          mountPath: /var/log/payment
      
      # Sidecar Log Processor Container
      - name: log-processor
        image: log-processor:latest
        volumeMounts:
        - name: shared-logs
          mountPath: /var/log/payment
        env:
        - name: ELASTICSEARCH_URL
          value: "http://elasticsearch:9200"
```

**Key Points:**
- **Multi-container pod** with payment service and log processor
- Both containers share the same `emptyDir` volume at `/var/log/payment`
- Payment service writes logs to the shared volume
- Log processor reads logs and sends to Elasticsearch
- `replicas: 3` ensures both containers scale together as a unit
- Labels ensure all replicas are consistent and managed together
- Sidecar pattern keeps containers isolated but working together
