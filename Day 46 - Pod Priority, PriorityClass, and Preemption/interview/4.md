### Backend service has 3 replicas. By default, they might all schedule on the same node, creating a single point of failure.

Solution:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: backend
  template:
    metadata:
      labels:
        app: backend
    spec:
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
          - labelSelector:
              matchExpressions:
              - key: app
                operator: In
                values:
                - backend
            topologyKey: "kubernetes.io/hostname"
      containers:
      - name: backend
        image: backend-app:latest
```

Key Points:
- Pod Anti-Affinity improves fault tolerance
- Prevents pods with label `app: backend` from scheduling on the same node
- `requiredDuringSchedulingIgnoredDuringExecution:` Rule is enforced during scheduling only
- `topologyKey: kubernetes.io/hostname` ensures pods spread across different nodes
- If one node fails, other replicas on different nodes remain available
- Improves high availability and reduces risk
