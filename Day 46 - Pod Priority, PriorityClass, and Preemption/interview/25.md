## Troubleshooting a Pod Stuck in `Pending` State - 4 (Disk Pressure) - A Redis deployment named `demo` is stuck in `Pending`?

**Symptoms & Error:** `kubectl describe pod` shows warnings about `DiskPressure`, `MemoryPressure`, and the node condition `MemoryPressure` is `True`. On the target node (`worker-3`), running `df -h` shows the disk is 100% full.

**Root Cause:** The node's disk space is completely full, causing the node to taint itself with `node.kubernetes.io/disk-pressure`. This prevents new pods from being scheduled on it.

**Commands for Troubleshooting & Solution:**

1.  **Check Disk Space on the Node:**
    ```bash
    df -h /
    ```

2.  **Free Up Disk Space/or extend it:**
    This involves cleaning up unused images, logs, or temporary files on the worker node.

3.  **Restart kubelet:**
    After freeing up space, the node might not immediately update its status. Restarting `kubelet` forces it to re-evaluate the node's health and report the new status to the API server.
    ```bash
    systemctl restart kubelet
    ```
    The pod should now move from `Pending` to `Running` state.
