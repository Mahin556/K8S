## 22. You're deploying a mix of latency-sensitive services and batch jobs in a Kubernetes cluster. How would you ensure each workload is scheduled appropriately?

In Kubernetes, I would use scheduling policies and node isolation mechanisms to ensure both workload types run efficiently without affecting each other.

---

# Strategy for Latency-Sensitive Services

These workloads require:

* Low latency
* Stable performance
* Fast response times

Examples:

* APIs
* Real-time applications
* Payment services

---

## Techniques I Would Use

### 1. Node Affinity

Place critical services only on high-performance nodes.

Example:

```yaml id="5m2p8"
affinity:
  nodeAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      nodeSelectorTerms:
      - matchExpressions:
        - key: workload
          operator: In
          values:
          - critical
```

---

### 2. Taints and Tolerations

Dedicate nodes only for critical workloads.

### Node Taint

```bash id="8k1n4"
kubectl taint nodes node1 workload=critical:NoSchedule
```

### Pod Toleration

```yaml id="3x7q2"
tolerations:
- key: "workload"
  operator: "Equal"
  value: "critical"
  effect: "NoSchedule"
```

This prevents:

* Batch jobs from using critical nodes.

---

### 3. Resource Requests and Limits

Guarantee CPU and memory availability.

```yaml id="6v1m5"
resources:
  requests:
    cpu: "2"
    memory: "4Gi"
```

This ensures:

* Scheduler reserves resources properly.

---

# Strategy for Batch Jobs

Batch workloads are:

* Flexible
* Non-latency-sensitive
* Usually CPU-intensive

Examples:

* ETL jobs
* Data processing
* Analytics

---

## Techniques I Would Use

### 1. Separate Node Pool

Run batch jobs on:

* Lower-priority nodes
* Spot/preemptible instances

---

### 2. Lower PriorityClass

```yaml id="2k8n7"
priorityClassName: low-priority
```

This allows:

* Critical workloads to preempt batch jobs if needed.

---

### 3. Use Kubernetes Jobs/CronJobs

```yaml id="4p7m1"
kind: Job
```

or

```yaml id="9x2k5"
kind: CronJob
```

for scheduled batch processing.

---

# Optional Advanced Optimization

## Topology Spread Constraints

Distribute latency-sensitive Pods across nodes/zones for high availability.

---

## Pod Anti-Affinity

Prevent replicas from running on the same node.

```yaml id="1k9n4"
podAntiAffinity:
```

Improves:

* Fault tolerance
* Availability

---

# High-Level Architecture

```text id="7m3p8"
Critical Services
    ↓
Dedicated Nodes + High Priority
    ↓
Low Latency

Batch Jobs
    ↓
Separate Nodes + Lower Priority
    ↓
Efficient Resource Usage
```

---

# Interview-Ready Answer

“In a Kubernetes cluster with both latency-sensitive services and batch jobs, I would isolate workloads using node affinity, taints and tolerations, dedicated node pools, and PriorityClasses. Critical low-latency services would run on dedicated high-performance nodes with guaranteed resources, while batch jobs would run on separate lower-priority nodes. I would also use affinity and anti-affinity rules to improve availability and workload distribution.”
