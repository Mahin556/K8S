* In Kubernetes, scheduling decisions determine where a pod runs within the cluster. While Kubernetes has a built-in **scheduler** that automatically assigns pods to nodes but in production every node is different some has GPUs some have SSDs some have High CPUs and these node can run different kind of workloads, administrators often need to influence **scheduling decisions** to ensure specific workloads run on designated nodes.
* Scheduling can be influence by: 
    * `Request and Limit`
    * `NodeSelector`(basic)
    * `Affinity`(advance)
    * `Taint and Toleration`

* What we can achive using scheduling
    - Workloads are placed on **nodes with required hardware** (e.g., GPUs, SSDs).  
    - Applications are **isolated by environment** (e.g., prod, staging, production).  
    - Compliance with **resource constraints** (e.g., memory, CPU).

```bash
Kubernetes Scheduler – Parameters Used While Scheduling a Pod

Scheduling happens in 2 steps:
1) Filter nodes (remove unsuitable ones)
2) Score remaining nodes (pick the best one)

1. Resource Requests
   - CPU (requests.cpu)
   - Memory (requests.memory)
   - Storage
   - GPU or extended resources
   Scheduler checks requests, not limits.
   If not enough resources → node is rejected.

2. Node Selector
   Pod must match node labels.
   Example:
     nodeSelector:
       disktype: ssd

3. Node Affinity
   Advanced label matching.
   - required → must match
   - preferred → good to match (soft rule)

4. Taints and Tolerations
   If node has a taint:
     NoSchedule
   Pod must have matching toleration.
   Otherwise → cannot run there.

5. Pod Affinity / Anti-Affinity
   - Run near certain Pods
   - Avoid certain Pods
   Based on labels and topology (zone, hostname)

6. Pod Priority
   Higher priority Pods are scheduled first.
   Lower priority Pods may be preempted.

7. Node Conditions
   Scheduler checks:
   - Ready
   - MemoryPressure
   - DiskPressure
   - PIDPressure
   If node is NotReady → ignored.

8. Volume Constraints
   If Pod uses PVC:
   - Storage must be available
   - Volume must attach to that node

9. Topology Spread
   Distributes Pods evenly across:
   - Nodes
   - Zones
   - Regions

10. Scoring Phase
   Among valid nodes, scheduler prefers:
   - More free resources
   - Balanced load
   - Image already present

Simple Flow:

Pod created
→ Scheduler filters unsuitable nodes
→ Scores remaining nodes
→ Picks best node
→ Binds Pod to node
```
