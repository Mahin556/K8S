# 8️⃣ Observe Preemption

```bash
kubectl get pods -o wide
```

You will notice:

* Critical pods Running
* Some normal pods moved to Pending

Kubernetes preempts lower priority pods to schedule higher priority pods.

---

# 🔥 What Happened?

* Normal apps had priority = 0
* Critical app had priority = 1000
* No free resources available
* Kubernetes evicted lower-priority pods
* Freed resources were assigned to critical pods

Here is a **clear and simple explanation of Normal, Minimum, Highest and System component default priorities in Kubernetes** 👇

---

```
🔥 Kubernetes Pod Priority Explained

Priority in Kubernetes is an integer value.
Higher number = Higher priority.

Range (32-bit integer):

Lowest possible:
-2147483648

Highest allowed for user:
1000000000 (1 billion)

------------------------------------------------

1️⃣ Normal Priority (Default)

If you do NOT define any PriorityClass:

priority = 0

So:
Default pod priority = 0

Example:
Any normal Deployment without priorityClassName runs at priority 0.

------------------------------------------------

2️⃣ Minimum Priority

Lowest possible value:
-2147483648

You can create a PriorityClass with negative value:

value: -100
value: -1000

Lower value = lower priority

Pods with negative priority will be evicted first
when higher priority pods need resources.

------------------------------------------------

3️⃣ Highest User Priority

Maximum value allowed for user-defined PriorityClass:

1000000000  (1 Billion)

You cannot exceed this for custom workloads.

Example:

apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata:
  name: super-critical
value: 1000000000

------------------------------------------------

4️⃣ System Component Default Priorities

Kubernetes control-plane components use
VERY HIGH built-in priorities.

Examples:

system-cluster-critical
system-node-critical

Their values are around:

2000000000 (2 Billion+)

Examples:
- kube-apiserver
- etcd
- kube-scheduler
- kube-controller-manager

These ALWAYS get priority over user pods.

You should NEVER use such high values.

------------------------------------------------

🔢 Summary Table

Priority Value         Meaning
------------------------------------------------
-2147483648            Absolute minimum
Negative values        Very low priority
0                      Default (Normal)
1 → 1000000000         User-defined high priority
~2000000000+           System components only

------------------------------------------------

🎯 Important Rule

Higher number = higher priority

If resources are full:

Kubernetes will:
Evict lower priority pods
Schedule higher priority pods

------------------------------------------------

⚠️ Best Practice

Normal apps → 0
Important business apps → 1000–10000
Never use 2 billion range
Never override system priorities
```
