* In **StatefulSet**

  * Deleting the StatefulSet → Pods are deleted
  * PVCs created via `volumeClaimTemplates` are **NOT deleted**
  * PVCs remain in **Bound state**
  * If you recreate the StatefulSet →

    * Pods reattach to the same PVC
    * Data is preserved
  * Designed for **stateful workloads** (DB, Kafka, etc.)

Now your question 👇

### What happens in case of a Deployment?

* **Deployment does NOT create PVCs automatically**

  * No `volumeClaimTemplates` concept
  * You must manually create PVCs

* When you delete a Deployment:

  * Pods are deleted
  * PVC behavior depends on how it was created

---

### Case 1: PVC created separately (manually)

```yaml
kind: PersistentVolumeClaim
```

* Delete Deployment →

  * Pods deleted
  * PVC remains
  * PV remains (based on reclaim policy)
* Data is preserved
* New Deployment can reuse same PVC

---

### Case 2: Pod using emptyDir

```yaml
volumes:
  - name: data
    emptyDir: {}
```

* Delete Pod / Deployment →

  * Data is LOST
* Because `emptyDir` is tied to Pod lifecycle

---

### Case 3: PV Reclaim Policy Matters

* If StorageClass reclaimPolicy = **Retain**

  * PV stays even after PVC deletion
  * Manual cleanup required

* If reclaimPolicy = **Delete**

  * PV deleted automatically when PVC deleted
  * Data is lost

---

### Important Difference: StatefulSet vs Deployment

* StatefulSet

  * Stable identity (pod-0, pod-1)
  * One PVC per Pod
  * Auto-managed persistent storage
  * Designed for stateful apps

* Deployment

  * Pods are interchangeable
  * No stable identity
  * No automatic per-pod PVC
  * Designed for stateless apps

---

### Interview-level clarity

* Delete StatefulSet → PVCs stay
* Delete Deployment →

  * Pods deleted
  * PVC only deleted if you delete it manually
* Delete PVC →

  * PV behavior depends on reclaim policy

---

* Stateless app → Deployment
* Stateful app (DB, Kafka, Elasticsearch) → StatefulSet
