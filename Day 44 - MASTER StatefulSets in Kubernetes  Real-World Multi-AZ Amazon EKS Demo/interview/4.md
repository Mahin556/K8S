### Upgrade database from version 1.0 to 1.1. Only one pod should be updated at a time. Each pod must come back with same identity and storage. System must remain stable during upgrade.

**Solution:**

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: database
spec:
  serviceName: database-svc
  replicas: 3
  updateStrategy:
    type: RollingUpdate
    rollingUpdate:
      partition: 0                     # 0 = update all pods
      maxUnavailable: 1                # Only 1 pod unavailable at a time
  selector:
    matchLabels:
      app: database
  template:
    metadata:
      labels:
        app: database
    spec:
      containers:
      - name: postgres
        image: postgres:15.1           # Updated from 15.0 to 15.1
        ports:
        - containerPort: 5432
        volumeMounts:
        - name: pg-data
          mountPath: /var/lib/postgresql/data
        readinessProbe:                # Ensure pod is ready before proceeding
          exec:
            command:
            - pg_isready
          initialDelaySeconds: 30
          periodSeconds: 10
  volumeClaimTemplates:
  - metadata:
      name: pg-data
    spec:
      accessModes:
      - ReadWriteOnce
      resources:
        requests:
          storage: 10Gi
```

**Rolling Update Process:**
```
Starting State: All pods running postgres:15.0
  database-0 → postgres:15.0 (Running)
  database-1 → postgres:15.0 (Running)
  database-2 → postgres:15.0 (Running)

Update Triggered (image changed to postgres:15.1):

Step 1: Update database-2 (highest ordinal first - reverse order!)
  - Terminate database-2
  - PVC pg-data-database-2 preserved
  - Create new database-2 with postgres:15.1
  - Reattach PVC pg-data-database-2
  - Wait for database-2 to become Ready

Step 2: Update database-1
  - Terminate database-1
  - PVC pg-data-database-1 preserved
  - Create new database-1 with postgres:15.1
  - Reattach PVC pg-data-database-1
  - Wait for database-1 to become Ready

Step 3: Update database-0
  - Terminate database-0
  - PVC pg-data-database-0 preserved
  - Create new database-0 with postgres:15.1
  - Reattach PVC pg-data-database-0
  - Wait for database-0 to become Ready

Final State: All pods running postgres:15.1
  database-0 → postgres:15.1 (Running) - Same PVC
  database-1 → postgres:15.1 (Running) - Same PVC
  database-2 → postgres:15.1 (Running) - Same PVC
```

**Canary Update with Partition:**
```yaml
# Update only database-2 first (partition: 2)
updateStrategy:
  rollingUpdate:
    partition: 2                      # Only update pods with ordinal >= 2
# database-2 updates, database-0 and database-1 stay on old version

# After verifying database-2, update all
updateStrategy:
  rollingUpdate:
    partition: 0                      # Update all pods
```

**Key Points:**
- StatefulSet updates in **reverse ordinal order** (2 → 1 → 0)
- `maxUnavailable: 1` ensures only one pod updates at a time
- Each pod keeps the **same identity** (name) and **same PVC** after update
- `volumeClaimTemplates` ensures PVCs are reattached after restart
- System remains stable - at least 2 pods always available
- `partition` allows canary/ phased rollouts
- Readiness probes prevent proceeding until pod is truly ready
