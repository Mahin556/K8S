### Distributed database where each replica stores its own data. Data must remain attached to the same replica even if the pod is recreated. Each pod needs its own PVC created automatically when scaling.

**Solution:**

```yaml
apiVersion: v1
kind: Service
metadata:
  name: distributed-db
spec:
  clusterIP: None
  selector:
    app: distributed-db
  ports:
  - port: 9042
    targetPort: 9042
    name: cql
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: distributed-db
spec:
  serviceName: distributed-db
  replicas: 3
  selector:
    matchLabels:
      app: distributed-db
  template:
    metadata:
      labels:
        app: distributed-db
    spec:
      containers:
      - name: cassandra
        image: cassandra:4.1
        ports:
        - containerPort: 9042
        volumeMounts:
        - name: db-data
          mountPath: /var/lib/cassandra
  volumeClaimTemplates:
  - metadata:
      name: db-data
    spec:
      accessModes:
      - ReadWriteOnce                   # Dedicated storage per pod
      resources:
        requests:
          storage: 50Gi
      storageClassName: fast-ssd       # High-performance storage
```

**What Happens During Scaling:**
```bash
# Initial deployment - 3 replicas
kubectl apply -f statefulset.yaml

# Created automatically:
# Pods: distributed-db-0, distributed-db-1, distributed-db-2
# PVCs: db-data-distributed-db-0, db-data-distributed-db-1, db-data-distributed-db-2
# PVs:  Dynamically provisioned (50Gi each)

# Scale to 5 replicas
kubectl scale statefulset distributed-db --replicas=5

# New resources created automatically:
# Pod: distributed-db-3 (with PVC db-data-distributed-db-3)
# Pod: distributed-db-4 (with PVC db-data-distributed-db-4)
```

**Data Persistence During Pod Failure:**
```
Scenario: distributed-db-1 crashes

1. Pod distributed-db-1 dies
2. PVC db-data-distributed-db-1 is NOT deleted
3. StatefulSet creates new pod named distributed-db-1
4. New pod reattaches the SAME PVC db-data-distributed-db-1
5. All data from before crash is available
```

**Key Points:**
- **volumeClaimTemplates** creates one PVC per pod automatically
- Each pod gets unique storage that follows it through restarts
- PVC naming convention: `<template-name>-<statefulset-name>-<ordinal>`
- Data never mixes between replicas - each has its own volume
- `ReadWriteOnce` ensures exclusive access per pod
- Scaling up automatically creates new PVCs
- Pod identity + PVC pairing is maintained by StatefulSet controller
