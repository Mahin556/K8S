## 📦 Create StorageClass, PV, PVC, and Pod with Fast Storage

We'll create a complete storage setup with:
- **StorageClass** `fast-storage` (Immediate binding)
- **PV** `fast-pv-cka` (50Mi, hostPath)
- **PVC** `fast-pvc-cka` (30Mi request)
- **Pod** `fast-pod-cka` (nginx with mount)

---

### ✅ Step 1 – Create StorageClass `fast-storage`

```bash
cat <<EOF | kubectl apply -f -
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: fast-storage
provisioner: kubernetes.io/no-provisioner
volumeBindingMode: Immediate
EOF
```

---

### ✅ Step 2 – Create the Host Directory and PV

First, create the directory on the host:
```bash
sudo mkdir -p /tmp/fast-data
```

Then create the PV `fast-pv-cka`:
```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: PersistentVolume
metadata:
  name: fast-pv-cka
spec:
  capacity:
    storage: 50Mi
  accessModes:
    - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  storageClassName: fast-storage
  hostPath:
    path: /tmp/fast-data
EOF
```

---

### ✅ Step 3 – Create PVC `fast-pvc-cka`

```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: fast-pvc-cka
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 30Mi
  storageClassName: fast-storage
EOF
```

---

### ✅ Step 4 – Create Pod `fast-pod-cka` Using the PVC

```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: fast-pod-cka
spec:
  containers:
  - name: nginx
    image: nginx:latest
    volumeMounts:
    - name: fast-storage
      mountPath: /app/data
  volumes:
  - name: fast-storage
    persistentVolumeClaim:
      claimName: fast-pvc-cka
EOF
```

---

### ✅ Step 5 – Verify Everything

**Check StorageClass:**
```bash
kubectl get storageclass fast-storage
```

**Check PV and PVC binding:**
```bash
kubectl get pv,pvc
```

Expected output:
```
NAME           CAPACITY   ACCESS MODES   RECLAIM POLICY   STATUS   CLAIM                    STORAGECLASS   REASON   AGE
fast-pv-cka    50Mi       RWO            Retain           Bound    default/fast-pvc-cka     fast-storage            5s

NAME                STATUS   VOLUME         CAPACITY   ACCESS MODES   STORAGECLASS   AGE
fast-pvc-cka        Bound    fast-pv-cka    50Mi       RWO            fast-storage   5s
```

**Check Pod status:**
```bash
kubectl get pod fast-pod-cka
```

Expected output:
```
NAME            READY   STATUS    RESTARTS   AGE
fast-pod-cka    1/1     Running   0          5s
```

---

### 🔍 Verify the Volume is Mounted

Check that the PVC is mounted correctly inside the pod:
```bash
kubectl exec fast-pod-cka -- df -h | grep /app/data
```

Or test by writing a file:
```bash
kubectl exec fast-pod-cka -- sh -c "echo 'Hello from fast storage' > /app/data/test.txt"
kubectl exec fast-pod-cka -- cat /app/data/test.txt
```

Expected output:
```
Hello from fast storage
```

You can also verify the file on the host:
```bash
sudo cat /tmp/fast-data/test.txt
```

### 🧠 Key Points

- **Immediate binding**: The PVC binds to the PV as soon as it's created (no need for a Pod to be scheduled first).
- **`kubernetes.io/no-provisioner`**: Static provisioning – the PV must be manually created by the admin.
- **hostPath**: The data is stored on the host node at `/tmp/fast-data`. In a multi-node cluster, this Pod would need to be scheduled on the same node that has the PV (but here we use `hostPath` without `nodeAffinity`, so it'll work if the Pod lands on the same node where the directory exists – usually true in a single-node lab).
- **`ReadWriteOnce`**: The volume can be mounted by a single node as read-write.

All resources should be up and running!
