## 📦 Create StorageClass, PV, and PVC

We'll create a StorageClass `blue-stc-cka` with `WaitForFirstConsumer` binding, a PV `blue-pv-cka` with local storage on `controlplane`, and a PVC `blue-pvc-cka` that binds to it.

---

### ✅ Step 1 – Create StorageClass `blue-stc-cka`

```bash
cat <<EOF | kubectl apply -f -
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: blue-stc-cka
provisioner: kubernetes.io/no-provisioner
volumeBindingMode: WaitForFirstConsumer
EOF
```

---

### ✅ Step 2 – Create PersistentVolume `blue-pv-cka`

> **Note**: Ensure `/opt/blue-data-cka` exists on `controlplane`:
> ```bash
> sudo mkdir -p /opt/blue-data-cka
> ```

```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: PersistentVolume
metadata:
  name: blue-pv-cka
spec:
  capacity:
    storage: 100Mi
  accessModes:
    - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  storageClassName: blue-stc-cka
  local:
    path: /opt/blue-data-cka
  nodeAffinity:
    required:
      nodeSelectorTerms:
      - matchExpressions:
        - key: kubernetes.io/hostname
          operator: In
          values:
          - controlplane
EOF
```

---

### ✅ Step 3 – Create PersistentVolumeClaim `blue-pvc-cka`

```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: blue-pvc-cka
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 50Mi
  storageClassName: blue-stc-cka
EOF
```

---

### ✅ Step 4 – Verify the Resources

Check StorageClass:
```bash
kubectl get storageclass blue-stc-cka
```

Check PV:
```bash
kubectl get pv blue-pv-cka
```

Check PVC:
```bash
kubectl get pvc blue-pvc-cka
```

---

### 🔍 Detailed Verification

Check node affinity on PV:
```bash
kubectl describe pv blue-pv-cka | grep -A5 "Node Affinity"
```

Check PVC details:
```bash
kubectl describe pvc blue-pvc-cka
```

```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: blue-test-pod
spec:
  containers:
  - name: test-container
    image: busybox
    command: ["/bin/sh"]
    args: ["-c", "echo 'Blue PVC test file' > /mnt/data/test.txt && sleep 3600"]
    volumeMounts:
    - name: blue-storage
      mountPath: /mnt/data
  volumes:
  - name: blue-storage
    persistentVolumeClaim:
      claimName: blue-pvc-cka
EOF
```

The Pod will be scheduled on controlplane because the PV has nodeAffinity set to controlplane. The scheduler will automatically place the Pod there since that node is the only one that can access the PV.


---

### 🧠 Why This Works

| Component | Key Configuration |
| :--- | :--- |
| **StorageClass** | `provisioner: kubernetes.io/no-provisioner` – indicates static provisioning; `WaitForFirstConsumer` delays binding until a pod uses the PVC. |
| **PV** | `local` path on `controlplane` with node affinity; `storageClassName: blue-stc-cka` matches the StorageClass. |
| **PVC** | Requests `50Mi` from `blue-stc-cka`; binds to the only available PV with enough capacity (100Mi) and matching access mode. |

Since the PVC requests less than the PV's capacity (50Mi < 100Mi) and both use the same StorageClass and access mode, they bind automatically. No explicit `selector` is needed because there's only one PV in that StorageClass.
