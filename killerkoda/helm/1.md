## 📦 CKA: Install Argo CD Using Helm Without Installing CRDs

This guide provides a **complete, step‑by‑step solution** for installing Argo CD via Helm while **skipping CustomResourceDefinition (CRD)** installation – because they are already pre‑installed by the platform team.  

You will **generate a Helm template** (not deploy directly) and save it to `/root/argo-helm.yaml`, with **no CRDs** in the output.

---

### 🔍 Prerequisites
- The namespace `argocd` already exists.
- Argo CD CRDs (e.g., `applications.argoproj.io`) are already present.
- Helm 3.x is installed and configured.

---

### 📌 Step‑by‑Step Solution

#### 1. Verify the `argocd` namespace
```bash
kubectl get namespace argocd
```
You should see it in `Active` status.

#### 2. Verify CRDs are already installed (optional, but good practice)
```bash
kubectl get crd | grep argoproj
```
Example output:
```
applications.argoproj.io               2025-01-01T10:00:00Z
applicationsets.argoproj.io            2025-01-01T10:00:00Z
appprojects.argoproj.io                2025-01-01T10:00:00Z
```

#### 3. Add the official Argo CD Helm repository with name `argocd`
```bash
helm repo add argocd https://argoproj.github.io/argo-helm
```
Expected output:
```
"argocd" has been added to your repositories
```

#### 4. Update the repository cache
```bash
helm repo update
```

#### 5. Verify the repository list
```bash
helm repo list
```
You should see:
```
NAME     URL
argocd   https://argoproj.github.io/argo-helm
```

#### 6. Search for the Argo CD chart to confirm availability
```bash
helm search repo argocd/argo-cd
```
This shows the latest version. To see all versions and confirm `9.1.4` exists:
```bash
helm search repo argocd/argo-cd --versions | grep 9.1.4
```

---

### 📄 Step 7 – Generate the Helm Template WITHOUT CRDs

The key is to set `crds.install=false` – this tells the chart **not** to include CRD manifests in the rendered output.

Run the following command:
```bash
helm template argocd argocd/argo-cd \
  --version 9.1.4 \
  --namespace argocd \
  --set crds.install=false \
  > /root/argo-helm.yaml
```

**Breakdown of options:**
| Option | Purpose |
|--------|---------|
| `argocd` | Helm release name (can be anything, but we use `argocd`). |
| `argocd/argo-cd` | The chart repository and chart name (correct for Argo CD). |
| `--version 9.1.4` | Exact chart version (as required). |
| `--namespace argocd` | The target namespace (sets `metadata.namespace` on all resources). |
| `--set crds.install=false` | **Disables CRD installation** – the chart will omit the `crds/` directory. |
| `> /root/argo-helm.yaml` | Saves the rendered YAML to the specified file. |

> ⚠️ **Important:** Do **not** use the `--skip-crds` flag – that is for `helm install` and is **deprecated** in Helm 3. The correct method is the `crds.install=false` value.

---

### ✅ Step 8 – Verify CRDs are NOT Present in the Generated File

Run:
```bash
grep "kind: CustomResourceDefinition" /root/argo-helm.yaml || echo "✅ No CRDs found - Correct!"
```

Expected output:
```
✅ No CRDs found - Correct!
```

You can also list all resource kinds to confirm:
```bash
grep "^kind:" /root/argo-helm.yaml | sort | uniq -c
```
Typical output includes `Deployment`, `StatefulSet`, `Service`, `ConfigMap`, `Secret`, `ServiceAccount`, `Role`, `ClusterRole`, `RoleBinding`, `ClusterRoleBinding`, `NetworkPolicy` – **but no `CustomResourceDefinition`**.

---

### 🚀 Step 9 (Optional) – Install Argo CD Using the Template

If you are satisfied with the rendered manifest and want to install Argo CD **without** installing CRDs (since they already exist), you can apply the generated YAML:

```bash
kubectl apply -f /root/argo-helm.yaml
```

Or you can install directly with Helm (avoiding the template step) using the same `--set`:

```bash
helm install argocd argocd/argo-cd \
  --version 9.1.4 \
  --namespace argocd \
  --set crds.install=false \
  --create-namespace=false   # because namespace already exists
```

But the task specifically asks to **generate a Helm template and save it** – so the first method (using `helm template`) is what you need to do.

### 📊 Summary of Commands

```bash
# 1. Add repo
helm repo add argocd https://argoproj.github.io/argo-helm

# 2. Update
helm repo update

# 3. Generate template without CRDs
helm template argocd argocd/argo-cd \
  --version 9.1.4 \
  --namespace argocd \
  --set crds.install=false \
  > /root/argo-helm.yaml

# 4. Verify no CRDs
grep "kind: CustomResourceDefinition" /root/argo-helm.yaml || echo "✅ No CRDs found"
```

---

### 🧠 Why This Works
- The Argo CD Helm chart includes a `crds/` directory that normally gets installed when you run `helm install` **unless** you disable it.
- The value `crds.install` is a boolean that controls whether those CRDs are rendered.
- By setting it to `false`, the chart’s templating logic **skips** the CRD objects entirely.
- Since CRDs are already present in the cluster, this avoids conflicts (like "already exists" errors) and keeps the installation safe.
