## 🛠️ Step‑by‑Step Execution (Using `kubeadm`)

### Step 1 – Check and save current certificate expiration
```bash
sudo kubeadm certs check-expiration > /k8s/cert-details-old.txt
```

### Step 2 – Renew all control‑plane certificates
```bash
sudo kubeadm certs renew all
```
You’ll see confirmation for each renewed certificate.

### Step 3 – Save the new expiration details
```bash
sudo kubeadm certs check-expiration > /k8s/cert-details-new.txt
```

### Step 4 – Compare old vs new (optional but recommended)
```bash
colordiff -u /k8s/cert-details-old.txt /k8s/cert-details-new.txt
```

### Step 5 – Restart kubelet and verify cluster health
```bash
sudo systemctl restart kubelet
kubectl wait --for=condition=Ready nodes --all --timeout=180s
```

### Step 6 – Retrieve the list of control‑plane images
```bash
kubeadm config images list > /k8s/image-list.txt
```

## 🧠 Understanding the Certificate Hierarchy

```
Root CA (ca.crt) – 10 years
├── API Server (apiserver.crt) – 1 year
├── Controller Manager (controller-manager.conf) – 1 year
├── Scheduler (scheduler.conf) – 1 year
├── Kubelet Client (apiserver-kubelet-client.crt) – 1 year
├── Front Proxy Client (front-proxy-client.crt) – 1 year
└── etcd CA (etcd/ca.crt) – 10 years
    ├── etcd Server (etcd/server.crt) – 1 year
    ├── etcd Peer (etcd/peer.crt) – 1 year
    ├── etcd Health Check (etcd/healthcheck-client.crt) – 1 year
    └── API Server etcd Client (apiserver-etcd-client.crt) – 1 year
```

**Key Point:** All leaf certificates are signed by their respective CAs. Renewing a leaf certificate does **not** affect the CA.

---

## ⚠️ What `kubeadm certs renew all` **Does** and **Does Not** Do

| ✅ **Does** | ❌ **Does Not** |
|-------------|-----------------|
| Renews all CA‑signed certificates (apiserver, controller‑manager, scheduler, kubelet‑client, front‑proxy‑client) | Renew the root CA (`ca.crt` / `ca.key`) |
| Renews all etcd certificates (server, peer, healthcheck‑client, apiserver‑etcd‑client) | Renew the etcd CA (`etcd/ca.crt`) |
| Extends validity by **1 year** from the renewal date | Automatically restart control‑plane components or kubelet |
| Keeps the same CA (does not touch `ca.crt`) | Update kubeconfigs for external clients (you must manually refresh those) |

---

## 🔄 The Critical Scenario: Renewing the CA Itself

If the **CA certificate** is expiring (after ~10 years), you must perform a **two‑step renewal**:

1. **Renew the CA**  
   ```bash
   sudo kubeadm certs renew ca
   ```
   ⚠️ **This invalidates ALL existing component certificates** because they are signed with the old CA.

2. **Re‑renew all leaf certificates** (to be signed by the new CA)  
   ```bash
   sudo kubeadm certs renew all
   ```

3. **Restart all control‑plane components** and **kubelets on all nodes** to pick up the new certificate chain.

> **Golden Rule:**  
> *If you renew the CA, you MUST re‑renew all other certificates.*  
> `CA renewed → all certs invalid → renew all → restart everything`

## 📸 Manual (Non‑`kubeadm`) Alternative – For Emergency Use

If `kubeadm` is unavailable, you can inspect and even renew certificates using `openssl` and direct file manipulation. **This is risky** and should only be used as a last resort.

- **Audit:** Use `openssl x509 -in <file> -noout -enddate` on each `.crt` and decode kubeconfigs to extract embedded certs.
- **Renew:** Generate a CSR, sign with the CA private key, and update the kubeconfig files manually.
- **Images:** Extract images from static pod manifests (`/etc/kubernetes/manifests/*.yaml`) or with `crictl images`.

*For production, always prefer the `kubeadm` commands – they are safe, tested, and fully supported.*

## 🖼️ Control‑Plane Images – Expected vs. Running

The command `kubeadm config images list` gives you the **exact** images that kubeadm would use for the current cluster version.  

**Example output (v1.28.2):**
```
registry.k8s.io/kube-apiserver:v1.28.2
registry.k8s.io/kube-controller-manager:v1.28.2
registry.k8s.io/kube-scheduler:v1.28.2
registry.k8s.io/kube-proxy:v1.28.2
registry.k8s.io/pause:3.9
registry.k8s.io/etcd:3.5.9-0
registry.k8s.io/coredns/coredns:v1.10.1
```

To verify what’s actually running, use:
```bash
kubectl get pods -n kube-system -o jsonpath='{.items[*].spec.containers[*].image}' | tr ' ' '\n' | sort -u
```
