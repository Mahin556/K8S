# 🔐 CKA Security Audit: Certificate Management & Control-Plane Image Baselining

This guide walks you through the full audit process on a **kubeadm‑deployed control‑plane node**.  
You’ll check certificate expiration, renew all certificates, compare before/after, and document the expected container images.

---

## 📁 Prerequisites

- You are logged in as **root** or have `sudo` access on the **control‑plane** node.
- The cluster is healthy (`kubectl get nodes` shows `Ready`).
- `kubeadm`, `kubectl`, and `colordiff` are installed (install `colordiff` if missing: `apt install colordiff` or `yum install colordiff`).

---

## 📋 Task 1 – Audit Current Certificate Status

Use `kubeadm certs check‑expiration` to get a clean, machine‑readable summary of all control‑plane certificates.

```bash
# Save the full output to the required file
sudo kubeadm certs check-expiration > /k8s/cert-details-old.txt

# Quickly view it
cat /k8s/cert-details-old.txt
```

**Sample output** (dates will vary):
```
CERTIFICATE                EXPIRES                  RESIDUAL TIME   CERTIFICATE AUTHORITY   EXTERNALLY MANAGED
admin.conf                 Jan 15, 2026 10:30 UTC   51d             ca                      no      
apiserver                  Jan 15, 2026 10:30 UTC   51d             ca                      no      
apiserver-kubelet-client   Jan 15, 2026 10:30 UTC   51d             ca                      no      
controller-manager.conf    Jan 15, 2026 10:30 UTC   51d             ca                      no      
scheduler.conf             Jan 15, 2026 10:30 UTC   51d             ca                      no      
front-proxy-client         Jan 15, 2026 10:30 UTC   51d             front-proxy-ca          no      
```

> ⚠️ **Why not `openssl`?**  
> For kubeadm clusters, `kubeadm certs check‑expiration` is the **official** and most reliable tool.  
> The earlier `openssl x509 … | jc` error likely arose from locale issues or multi‑cert bundles; using `LC_ALL=C` could help, but the kubeadm method is simpler and audit‑ready.

---

## 🔄 Task 2 – Renew All Certificates & Compare

### Step 2.1 – Renew
```bash
sudo kubeadm certs renew all
```

This will regenerate every certificate, extending their validity (typically by one year).  
You’ll see confirmation lines like:
```
certificate embedded in the kubeconfig file for the admin to use and for kubeadm itself renewed
certificate for serving the Kubernetes API renewed
...
```

### Step 2.2 – Capture New Expiration Details
```bash
sudo kubeadm certs check-expiration > /k8s/cert-details-new.txt
```

### Step 2.3 – Compare Old vs New
```bash
colordiff -u /k8s/cert-details-old.txt /k8s/cert-details-new.txt
```

The diff will clearly show the **EXPIRES** and **RESIDUAL TIME** columns updated.  
A `+` line indicates the new value; a `-` line the old one.

### Step 2.4 – Restart Kubelet and Verify
The renewed certificates are written to disk, but the kubelet and API server need to reload them.

```bash
# Restart kubelet
sudo systemctl restart kubelet

# Wait for the control‑plane to become ready again
kubectl wait --for=condition=Ready nodes --all --timeout=180s

# (Optional) Restart other static pods if needed – kubelet will restart them automatically.
```

## 🖼️ Task 3 – Document Control‑Plane Image List

`kubeadm config images list` outputs the exact container images that kubeadm would use for the current cluster version.

```bash
kubeadm config images list > /k8s/image-list.txt

# View the list
cat /k8s/image-list.txt
```

**Example output**:
```
registry.k8s.io/kube-apiserver:v1.28.2
registry.k8s.io/kube-controller-manager:v1.28.2
registry.k8s.io/kube-scheduler:v1.28.2
registry.k8s.io/kube-proxy:v1.28.2
registry.k8s.io/pause:3.9
registry.k8s.io/etcd:3.5.9-0
registry.k8s.io/coredns/coredns:v1.10.1
```

> This list serves as the baseline for the security audit – it confirms which images should be running in the control‑plane.

## ✅ Final Verification

- Ensure the cluster is fully operational:
  ```bash
  kubectl get nodes
  kubectl get pods -A
  kubectl cluster-info
  ```
- Confirm the three required files exist:
  ```bash
  ls -l /k8s/cert-details-old.txt /k8s/cert-details-new.txt /k8s/image-list.txt
  ```

## 🧹 Troubleshooting Tips

| Issue | Solution |
|-------|----------|
| `kubeadm` not found | Ensure you are on the control‑plane node and that `kubeadm` is in your `PATH`. |
| Permission denied | Use `sudo` for all `kubeadm` commands. |
| `colordiff` not installed | Install it (`apt install colordiff` / `yum install colordiff`) or use `diff -u`. |
| API server not ready after renewal | Wait a minute; restart the static pods by moving their manifests out and back (`/etc/kubernetes/manifests/`). |
| Certificates not updated in `kubectl` | You may need to update your local `~/.kube/config`; restarting kubelet usually suffices. |

---

## 📌 Additional Notes for Audit Evidence

- The output of `kubeadm certs check‑expiration` is considered **official proof** of certificate health.
- The renewed certificates are stored in `/etc/kubernetes/pki/` and are automatically used by the control‑plane components.
- The image list is version‑specific; it matches the `kubeadm` version and the cluster’s Kubernetes version.
