## 🎯 Scenario Overview

### Your Mission

Configure CoreDNS to support **multiple domains** simultaneously — the default `cluster.local` plus a custom `killercoda.com` domain.

### The Context

- You are the cluster administrator responsible for DNS configuration
- The development team needs to access services using a custom domain `killercoda.com`
- Both domains must work **simultaneously** and resolve to the **same services**

### Critical Requirement

| Domain | Status |
|--------|--------|
| `SERVICE.NAMESPACE.svc.cluster.local` | ✅ Must continue working |
| `SERVICE.NAMESPACE.svc.killercoda.com` | ✅ New custom domain |

> **Both DNS domains must resolve to the same services at the same time!**

### Task 2: Update CoreDNS Configuration

#### Step 2.1: Edit the CoreDNS ConfigMap

```bash
kubectl edit configmap coredns -n kube-system
```

#### Step 2.2: Understand the Current Configuration

**Before (Current State):**

```yaml
data:
  Corefile: |
    .:53 {
        errors
        health {
            lameduck 5s
        }
        ready
        kubernetes cluster.local in-addr.arpa ip6.arpa {
            pods insecure
            fallthrough in-addr.arpa ip6.arpa
            ttl 30
        }
        prometheus :9153
        forward . /etc/resolv.conf
        cache 30
        loop
        reload
        loadbalance
    }
```

#### Step 2.3: Modify the Corefile

**Find this block:**
```coredns
kubernetes cluster.local in-addr.arpa ip6.arpa {
    pods insecure
    fallthrough in-addr.arpa ip6.arpa
    ttl 30
}
```

**Replace with this (ADD killercoda.com, do NOT remove cluster.local):**
```coredns
kubernetes cluster.local killercoda.com in-addr.arpa ip6.arpa {
    pods insecure
    fallthrough in-addr.arpa ip6.arpa
    ttl 30
}
```

**After (Modified State):**

```yaml
data:
  Corefile: |
    .:53 {
        errors
        health {
            lameduck 5s
        }
        ready
        kubernetes cluster.local killercoda.com in-addr.arpa ip6.arpa {
            pods insecure
            fallthrough in-addr.arpa ip6.arpa
            ttl 30
        }
        prometheus :9153
        forward . /etc/resolv.conf
        cache 30
        loop
        reload
        loadbalance
    }
```

#### Step 2.4: Why This Works

```
kubernetes cluster.local killercoda.com in-addr.arpa ip6.arpa
           ↑              ↑
    Default domain    Custom domain (added)

CoreDNS now serves TWO DNS zones simultaneously:
✅ cluster.local → continues to work
✅ killercoda.com → added in parallel
```

This forces CoreDNS to reload the updated configuration.

```bash

```

**Check restart status:**

**Verify pods are running:**

## 🔍 Deep Dive: Understanding the Configuration

### Complete YAML Breakdown

```yaml
data:
  Corefile: |
    .:53 {
        # CoreDNS listens on port 53 for all domains (.)

        errors
        # ↑ Logs errors to stdout

        health {
            lameduck 5s
        }
        # ↑ Health check endpoint :8080/health

        ready
        # ↑ Readiness probe endpoint :8181/ready

        kubernetes cluster.local killercoda.com in-addr.arpa ip6.arpa {
            # 🔥 KEY CHANGE: Added killercoda.com
            # CoreDNS now handles both cluster.local AND killercoda.com

            pods insecure
            # ↑ Includes pod records in DNS

            fallthrough in-addr.arpa ip6.arpa
            # ↑ Passes unknown queries to other plugins

            ttl 30
            # ↑ DNS record TTL (Time To Live) in seconds
        }

        prometheus :9153
        # ↑ Exports Prometheus metrics

        forward . /etc/resolv.conf
        # ↑ Forwards external queries to upstream DNS

        cache 30
        # ↑ Caches responses for 30 seconds

        loop
        # ↑ Detects forwarding loops

        reload
        # ↑ Auto-reloads Corefile on changes

        loadbalance
        # ↑ Round-robin load balancing
    }
```

### Key Configuration Fields

| Field | Value | Purpose |
|-------|-------|---------|
| **`.:53`** | Port 53 | Listen on standard DNS port |
| **`kubernetes`** | Plugin | Handles Kubernetes service discovery |
| **`cluster.local`** | Zone | Default Kubernetes domain |
| **`killercoda.com`** | Zone | **Custom added domain** |
| **`in-addr.arpa`** | Zone | Reverse DNS for IPv4 |
| **`ip6.arpa`** | Zone | Reverse DNS for IPv6 |
| **`pods insecure`** | Setting | Include pod records |
| **`fallthrough`** | Setting | Pass unknown queries forward |
| **`ttl 30`** | Value | Cache records for 30 seconds |

### Service DNS Format

```
<service>.<namespace>.svc.<domain>

Examples:
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Both Domains Work                                       │
│                                                                             │
│   kubernetes.default.svc.cluster.local    → 10.96.0.1                     │
│   kubernetes.default.svc.killercoda.com   → 10.96.0.1                     │
│                                                                             │
│   nginx.production.svc.cluster.local      → 10.96.0.5                     │
│   nginx.production.svc.killercoda.com     → 10.96.0.5                     │
│                                                                             │
│   ✅ Both domains resolve to the same IP!                                 │
└─────────────────────────────────────────────────────────────────────────────┘
```

### DNS Record Types

| Type | Format | Example |
|------|--------|---------|
| **Service A Record** | `<service>.<namespace>.svc.<domain>` | `kubernetes.default.svc.cluster.local` |
| **Service A Record (Custom)** | `<service>.<namespace>.svc.<domain>` | `kubernetes.default.svc.killercoda.com` |

| **SRV Record** | `_<port>._<proto>.<service>.<namespace>.svc.<domain>` | `_https._tcp.kubernetes.default.svc.cluster.local` |

## 🛠️ Troubleshooting Common Issues

| Issue | Diagnosis | Solution |
|-------|-----------|----------|
| **Custom domain not resolving** | ConfigMap not updated correctly | Check: `kubectl get cm coredns -n kube-system -o yaml` |
| **CoreDNS pods not restarting** | Reload plugin not working | Restart manually: `kubectl rollout restart deployment coredns -n kube-system` |
| **Test pod cannot resolve** | DNS policy issue | Check Pod's `/etc/resolv.conf` |
| **ConfigMap syntax error** | Invalid Corefile | Validate: Check for typos in kubernetes plugin line |
| **Backup not created** | Directory missing | `mkdir -p /opt/course/16` |
| **Both domains not working** | `cluster.local` removed | Ensure BOTH domains are on the same line |
| **IPs differ** | Different services | Both should resolve to the same service |

## 🔑 CoreDNS Plugins Reference

### Essential Plugins

| Plugin | Description | Example |
|--------|-------------|---------|
| **errors** | Log errors to stdout | `errors` |
| **health** | Health check endpoint | `health { lameduck 5s }` |
| **ready** | Readiness probe endpoint | `ready` |
| **kubernetes** | Kubernetes service discovery | `kubernetes cluster.local` |
| **prometheus** | Metrics endpoint | `prometheus :9153` |
| **forward** | Forward to upstream DNS | `forward . /etc/resolv.conf` |
| **cache** | Cache DNS responses | `cache 30` |
| **loop** | Detect forwarding loops | `loop` |
| **reload** | Auto-reload configuration | `reload` |
| **loadbalance** | Round-robin responses | `loadbalance` |

### Kubernetes Plugin Options

| Option | Description |
|--------|-------------|
| `pods insecure` | Include pod records in DNS |
| `pods verified` | Include pod records with IP verification |
| `pods disabled` | Exclude pod records |
| `fallthrough` | Pass unknown queries forward |
| `ttl <seconds>` | Set TTL for DNS records |
| `namespace <namespace>` | Restrict to specific namespace |

### Forward Plugin Syntax

```coredns
# Single upstream
forward . 8.8.8.8

# Multiple upstreams
forward . 8.8.8.8 1.1.1.1

# Use system resolv.conf
forward . /etc/resolv.conf

# With policy
forward . 8.8.8.8 {
    policy sequential
    max_concurrent 1000
}
```

## 💡 Real-World Use Cases

### When to Use Custom Domains

| Use Case | Description | Implementation |
|----------|-------------|----------------|
| **Organization-specific domains** | Use company domain for internal services | Add `company.com` to kubernetes plugin |
| **Multi-cluster DNS** | Different domains for different clusters | Each cluster has unique domain |
| **Hybrid cloud integration** | On-prem and cloud services | Custom domain for hybrid DNS |
| **Legacy application compatibility** | Legacy apps expect specific domains | Add legacy domain alongside cluster.local |
| **Service mesh requirements** | Mesh-specific domain patterns | Custom domain for service mesh |

### Example: Multiple Custom Domains

```coredns
kubernetes cluster.local company.com app.internal in-addr.arpa ip6.arpa {
    pods insecure
    fallthrough in-addr.arpa ip6.arpa
    ttl 30
}
```

### Example: Domain-Specific Forwarding

```coredns
# Forward external.company.com to specific DNS
external.company.com:53 {
    forward . 10.0.0.53
}

# Default Kubernetes domain
.:53 {
    kubernetes cluster.local {
        pods insecure
    }
    forward . /etc/resolv.conf
}
```

### Example: Split DNS Configuration

```coredns
# Internal domain served by Kubernetes
internal.company.com:53 {
    kubernetes internal.company.com {
        pods insecure
    }
}

# External domain forwarded
external.company.com:53 {
    forward . 8.8.8.8
}
```
