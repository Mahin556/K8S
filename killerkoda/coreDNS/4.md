## 🧠 CoreDNS Architecture Overview

### What is CoreDNS?

CoreDNS is a **flexible, extensible DNS server** written in Go that serves as the default DNS server in Kubernetes. It replaced kube-dns in Kubernetes 1.11 and has been the standard since.

### Core Components

| Component | Description |
|-----------|-------------|
| **CoreDNS** | The DNS server itself, built on a plugin-based architecture |
| **ConfigMap** | Stores the `Corefile` configuration that defines CoreDNS behavior |
| **Corefile** | Configuration file using plugins to handle DNS queries |
| **Forward Plugin** | Proxies DNS queries to upstream DNS servers for external resolution |
| **Kubernetes Plugin** | Handles service discovery for cluster.local domains |

### How DNS Works in Kubernetes

```
Pod DNS Query (kubernetes.io)
        ↓
CoreDNS Service (kube-dns) — ClusterIP: 10.96.0.10
        ↓
CoreDNS Pod reads Corefile
        ↓
Checks if query matches kubernetes cluster.local
        ↓
    ┌─────────────────────────────────────┐
    │                                     │
    │   YES (cluster.local)               │  NO (external)
    │         ↓                           │       ↓
    │   Kubernetes API                    │  Forward to upstream
    │         ↓                           │       ↓
    │   Returns Service/Pod IP           │  Upstream resolves
    │                                     │       ↓
    └─────────────────────────────────────┘
                ↓
         Response returns to Pod
```

## 🌐 DNS Resolution Flow in Kubernetes

### External Domain DNS
```
kubernetes.io
    ↓
CoreDNS forward plugin
    ↓
Upstream DNS (8.8.8.8, 1.1.1.1)
    ↓
Returns external IP
```

### Internal Service DNS
```
my-service.my-namespace.svc.cluster.local
    ↓
CoreDNS kubernetes plugin
    ↓
Queries Kubernetes API
    ↓
Returns Service ClusterIP
```

### Pod DNS
```
pod-ip-address.my-namespace.pod.cluster.local
    ↓
CoreDNS kubernetes plugin (with pods insecure)
    ↓
Returns Pod IP
```

## ⚙️ CoreDNS Configuration Breakdown

### Default Corefile Structure

```coredns
.:53 {                         # Listen on port 53 for all domains
    errors                     # Log errors to stdout
    health { lameduck 5s }     # Health check endpoint :8080
    ready                      # Readiness probe endpoint :8181
    kubernetes cluster.local in-addr.arpa ip6.arpa {   # Service discovery
        pods insecure
        fallthrough in-addr.arpa ip6.arpa
        ttl 30
    }
    prometheus :9153           # Metrics endpoint
    forward . /etc/resolv.conf # 🔑 Upstream DNS servers (default)
    cache 30                   # Cache responses for 30 seconds
    loop                       # Detect forwarding loops
    reload                     # Auto-reload on Corefile changes
    loadbalance                # Round-robin load balancing
}
```

### Modified Configuration (After Our Changes)

## 🔑 CoreDNS Plugins Reference

### Essential Plugins

| Plugin | Description | Example |
|--------|-------------|---------|
| **errors** | Logs errors to stdout | `errors` |
| **health** | HTTP endpoint at `:8080/health` for health checks | `health { lameduck 5s }` |
| **ready** | HTTP endpoint at `:8181/ready` for readiness probes | `ready` |
| **kubernetes** | Handles service discovery for cluster.local domains | `kubernetes cluster.local in-addr.arpa ip6.arpa { ... }` |
| **prometheus** | Metrics endpoint at `:9153/metrics` | `prometheus :9153` |
| **forward** | Proxies DNS queries to upstream nameservers | `forward . 8.8.8.8 1.1.1.1` |
| **cache** | Caches DNS responses for improved performance | `cache 30` |
| **loop** | Detects and prevents infinite forwarding loops | `loop` |
| **reload** | Automatically reloads Corefile when changed | `reload` |
| **loadbalance** | Round-robin load balancing for A/AAAA/MX records | `loadbalance` |

### Forward Plugin Syntax

```
forward . <NAMESERVER_1> [NAMESERVER_2 ...] { optional_policies }
```

#### Examples

```coredns
# Single DNS server
forward . 8.8.8.8

# Multiple DNS servers (tries in order)
forward . 8.8.8.8 1.1.1.1

# Use system resolv.conf
forward . /etc/resolv.conf

# Specific domain forwarding
example.com:53 {
    forward . 10.0.0.1
}

# DNS over TLS
forward . tls://1.1.1.1 {
    tls_servername cloudflare-dns.com
}
```

## 🔧 Common CoreDNS Configuration Patterns

### Pattern 1: Multiple Upstream Servers (Failover)

```coredns
forward . 8.8.8.8 8.8.4.4 1.1.1.1 1.0.0.1
```
CoreDNS will try servers in order until one responds.

### Pattern 2: Split-Horizon DNS (Different DNS for Different Domains)

```coredns
.:53 {
    kubernetes cluster.local
    forward . 8.8.8.8
}

corp.local:53 {
    forward . 10.0.0.53
}
```

### Pattern 3: Conditional Forwarding with Exceptions

```coredns
.:53 {
    kubernetes cluster.local
    forward . /etc/resolv.conf {
        except example.com
    }
}

example.com:53 {
    forward . 10.0.0.1
}
```

### Pattern 4: DNS over TLS (Encrypted Queries)

```coredns
forward . tls://1.1.1.1 {
    tls_servername cloudflare-dns.com
}
```

### Pattern 5: High-Performance Configuration

```coredns
.:53 {
    errors
    health
    ready
    kubernetes cluster.local {
        pods insecure
        fallthrough in-addr.arpa ip6.arpa
        ttl 30
    }
    prometheus :9153
    forward . 8.8.8.8 1.1.1.1 {
        max_concurrent 1000
        prefer_udp
    }
    cache 300
    loop
    reload
    loadbalance
}
```

## 📚 Important DNS Concepts

### 1. The `ndots` Option

```
options ndots:5
```

**What it does:**
- Determines when to use search domains
- If query has **fewer than 5 dots**, append search domains

**Example:**
```
kubernetes.io (1 dot)
    → tries kubernetes.io.default.svc.cluster.local first
    → then kubernetes.io.svc.cluster.local
    → then kubernetes.io.cluster.local
    → finally kubernetes.io

www.kubernetes.io (2 dots)
    → still tries search domains
```

**Impact:**
- Can cause extra DNS queries and latency
- Each failed search domain query adds to DNS load

**Optimization:** For pods that frequently query fully qualified domain names, consider reducing `ndots` to 2:

```yaml
spec:
  dnsConfig:
    options:
      - name: ndots
        value: "2"
```

---

### 2. DNS Search Path

```
search default.svc.cluster.local svc.cluster.local cluster.local
```

**What it does:**
- Order of domains to append when resolving short names
- Reduces typing for in-cluster services

**Example:**
```
Query: nginx
    → tries nginx.default.svc.cluster.local first
    → then nginx.svc.cluster.local
    → then nginx.cluster.local
    → finally nginx
```

---

### 3. DNS Policy Options

Pods can specify `dnsPolicy` to control DNS behavior:

| Policy | Description | Use Case |
|--------|-------------|----------|
| **ClusterFirst** | Use CoreDNS (default for pods) | Most workloads |
| **Default** | Inherit DNS from node (not recommended) | Legacy workloads |
| **ClusterFirstWithHostNet** | Use CoreDNS even with `hostNetwork` | Pods using host networking |
| **None** | Use custom `dnsConfig` (full control) | Advanced use cases |

**Example: Custom DNS Configuration**

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: custom-dns-pod
spec:
  containers:
    - name: nginx
      image: nginx
  dnsPolicy: None
  dnsConfig:
    nameservers:
      - 1.1.1.1
    searches:
      - my-custom.search.domain
    options:
      - name: ndots
        value: "2"
```

---

### 4. DNS Cache & TTL

```coredns
cache 30    # Cache responses for 30 seconds
```

**Impact:**
- Reduces upstream DNS queries
- Improves response time
- Can cause stale records if TTL is too high

**Optimal TTL Settings:**
- **30 seconds** (default): Balance between performance and freshness
- **60-300 seconds**: For stable services with infrequent changes
- **5-10 seconds**: For dynamic environments with frequent changes

## 🛠️ Troubleshooting DNS Issues

### Issue 1: DNS Resolution Fails

```bash
# Check CoreDNS pods status
kubectl get pods -n kube-system -l k8s-app=kube-dns

# Check CoreDNS logs
kubectl logs -n kube-system -l k8s-app=kube-dns --tail=50

# Test DNS from a pod
kubectl run dns-debug --image=busybox:1.28 --rm -it -- nslookup kubernetes.io
```

### Issue 2: CoreDNS Pods CrashLooping

```bash
# Check ConfigMap syntax
kubectl get configmap coredns -n kube-system -o yaml

# Validate Corefile syntax
kubectl exec -n kube-system <coredns-pod> -- cat /etc/coredns/Corefile

# Restart CoreDNS
kubectl rollout restart deployment coredns -n kube-system
```

### Issue 3: Slow DNS Resolution

```bash
# Check cache settings (increase cache TTL)
# In Corefile: cache 300 (5 minutes instead of 30 seconds)

# Check forward plugin timeout
# Add: forward . 8.8.8.8 1.1.1.1 {
#          max_concurrent 1000
#      }

# Increase CoreDNS replicas
kubectl scale deployment coredns -n kube-system --replicas=3
```

### Issue 4: DNS Queries Timing Out

```bash
# Check upstream DNS connectivity from node
nslookup kubernetes.io 8.8.8.8

# Check if forward loop exists
# Ensure forward . doesn't point back to CoreDNS

# Verify firewall rules allow outbound DNS (port 53)
```

### Issue 5: NodeLocal DNSCache (Performance Optimization)

**Problem:** All DNS queries go through CoreDNS service, creating a single point of failure and increasing latency.

**Solution:** Deploy NodeLocal DNSCache to cache DNS responses on each node.

```yaml
# Deploy NodeLocal DNSCache
kubectl apply -f https://raw.githubusercontent.com/kubernetes/enhancements/master/keps/sig-network/0032-nodelocal-dns-cache/config/deploy.yaml
```

## 🔍 DNS Debugging Commands

### Test DNS from within Cluster

```bash
# Create debug pod
kubectl run dns-test --image=nicolaka/netshoot --rm -it -- bash

# Inside pod:
nslookup kubernetes.io
dig kubernetes.io
host kubernetes.io

# Test specific DNS server
nslookup kubernetes.io 8.8.8.8
dig @8.8.8.8 kubernetes.io
```

### Test Kubernetes Service DNS

```bash
# Create a service
kubectl create deployment nginx --image=nginx
kubectl expose deployment nginx --port=80

# Test service DNS
kubectl run dns-test --image=busybox:1.28 --rm -it -- nslookup nginx.default.svc.cluster.local
```

### Check DNS Configuration in Pods

```bash
# View resolv.conf in a pod
kubectl run dns-test --image=busybox:1.28 --rm -it -- cat /etc/resolv.conf

# Expected output:
# nameserver 10.96.0.10 (CoreDNS service IP)
# search default.svc.cluster.local svc.cluster.local cluster.local
# options ndots:5
```

### Verify CoreDNS Endpoints and Health

```bash
# Check CoreDNS service
kubectl get svc -n kube-system kube-dns

# Check endpoints
kubectl get endpoints -n kube-system kube-dns

# Test health endpoint
COREDNS_POD=$(kubectl get pod -n kube-system -l k8s-app=kube-dns -o name | head -1)
kubectl exec -n kube-system $COREDNS_POD -- wget -O- http://localhost:8080/health

# Test ready endpoint
kubectl exec -n kube-system $COREDNS_POD -- wget -O- http://localhost:8181/ready
```
