# How to Make CoreDNS Resolve Pod Names

By default, CoreDNS in Kubernetes resolves **Service** names (like `my-service.my-namespace.svc.cluster.local`), but it **does not** resolve **Pod** names. To enable Pod name resolution, you need to modify the CoreDNS configuration.

---

## ⚙️ Step-by-Step Configuration

### Step 1: Edit the CoreDNS ConfigMap

```bash
kubectl edit configmap coredns -n kube-system
```

### Step 2: Modify the Corefile

Look for the `kubernetes` plugin block and add the `endpoint_pod_names` option.

**Before (Default):**
```coredns
kubernetes cluster.local in-addr.arpa ip6.arpa {
    pods insecure
    fallthrough in-addr.arpa ip6.arpa
    ttl 30
}
```

**After (With Pod Name Resolution):**
```coredns
kubernetes cluster.local in-addr.arpa ip6.arpa {
    pods insecure
    endpoint_pod_names   # ← ADD THIS LINE
    fallthrough in-addr.arpa ip6.arpa
    ttl 30
}
```

### Step 3: Save and Exit

CoreDNS's `reload` plugin will automatically detect the change and reload the configuration. No manual restart is needed.

## 🧪 How to Verify Pod Name Resolution

### 1. Create a Test Deployment and Service

```bash
# Create a deployment
kubectl create deployment nginx --image=nginx

# Expose it as a service
kubectl expose deployment nginx --port=80

# Get the pod name
kubectl get pods
```

Example output:
```
NAME                     READY   STATUS    RESTARTS   AGE
nginx-xxxxxxxxxx-xxxxx   1/1     Running   0          2m
```

### 2. Test DNS Resolution

**Create a debugging pod:**
```bash
kubectl run dns-test --image=nicolaka/netshoot --rm -it -- bash
```

**Inside the pod, test resolutions:**

```bash
# 1. Test Service DNS (always works)
nslookup nginx.default.svc.cluster.local
# Expected: Returns ClusterIP

# 2. Test Pod DNS (now works with endpoint_pod_names)
nslookup nginx-xxxxxxxxxx-xxxxx.nginx.default.svc.cluster.local
# Expected: Returns Pod IP
```

---

## 📋 DNS Record Format

With `endpoint_pod_names` enabled, the DNS record format is:

```
<pod-name>.<service-name>.<namespace>.svc.cluster.local
```

**Example:**
```
nginx-5c8b7b6d-9z2x4.nginx.default.svc.cluster.local
    ↓ resolves to Pod IP (not Service IP)
```

## ⚠️ Important Notes

| Consideration | Explanation |
|---------------|-------------|
| **Service vs Pod DNS** | Service DNS returns the **Service ClusterIP**. Pod DNS returns the **Pod's actual IP address**. |
| **Pod IPs are dynamic** | Pods get new IPs when restarted or rescheduled, so Pod DNS records are **ephemeral**. |
| **Use with caution** | Direct Pod DNS should not be used for stable communication. Use Services for resilience. |
| **Scalability** | This feature can increase the number of DNS entries in CoreDNS but is manageable for small to medium clusters. |

---

## 🛠️ Alternative: Using Headless Services for Pod DNS

If you need reliable, stable Pod DNS without modifying CoreDNS, you can use a **headless service**:

```bash
kubectl create service clusterip nginx-headless --clusterip=None
```

With a headless service, CoreDNS creates DNS records for **each Pod backing the service** without needing the `endpoint_pod_names` flag.

---

## 🏁 Summary

To enable Pod name resolution in CoreDNS:

1. **Edit ConfigMap:** `kubectl edit configmap coredns -n kube-system`
2. **Add:** `endpoint_pod_names` under the `kubernetes` plugin block
3. **Test:** Use `nslookup <pod-name>.<service-name>.<namespace>.svc.cluster.local`

This configuration allows you to resolve individual Pod IPs directly, which is useful for debugging and specific use cases where you need to target a specific Pod instance. However, for production workloads, always prefer Service DNS for resilience and load balancing.
