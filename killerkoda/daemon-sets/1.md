## 🧠 Conceptual Summary

### What is a DaemonSet?

A **DaemonSet** ensures that all (or some) nodes run a copy of a Pod. As nodes are added to the cluster, Pods are added to them. As nodes are removed, those Pods are garbage collected.

### Key Characteristics

| Feature | Description |
|---------|-------------|
| **One Pod per Node** | Automatically schedules exactly one Pod on each eligible node |
| **No Replica Count** | Unlike Deployments, DaemonSets don't use `replicas` field |
| **Automatic Scheduling** | New nodes automatically get DaemonSet Pods |
| **Node Selector Support** | Can target specific nodes using `nodeSelector` or `affinity` |
| **Toleration Support** | Can run on tainted nodes (like control planes) |

### Why Use DaemonSets?

✅ **Node-Level Services** → Each node needs an agent (monitoring, logging)  
✅ **Infrastructure Components** → Network plugins, storage drivers  
✅ **Consistent Configuration** → Every node runs the same Pod  
✅ **Automatic Scaling** → New nodes automatically get the Pod

## 📊 DaemonSet vs Deployment

| Feature | DaemonSet | Deployment |
|---------|-----------|------------|
| **Scheduling** | One Pod per node | N replicas across cluster |
| **Scaling** | Automatic with node count | Manual via `replicas` field |
| **Use Case** | Node-level services | Application workloads |
| **Updates** | RollingUpdate or OnDelete | RollingUpdate or Recreate |
| **Node Addition** | Auto-schedules Pod | No automatic action |
| **`replicas` field** | ❌ Not used | ✅ Required |
| **`strategy` field** | ❌ Not used (uses `updateStrategy`) | ✅ Used |

## 🔒 Understanding Tolerations

### What are Taints and Tolerations?

- **Taints** → Applied to nodes to repel Pods
- **Tolerations** → Applied to Pods to allow scheduling on tainted nodes

### Why Control Plane Nodes Have Taints

Control plane nodes have a taint to prevent regular workloads from running on them:

```bash
kubectl describe node controlplane | grep Taints
```

**Typical Taint:**
```
Taints: node-role.kubernetes.io/control-plane:NoSchedule
```

### Tolerations for Control Plane

```yaml
tolerations:
- effect: NoSchedule
  key: node-role.kubernetes.io/control-plane
  operator: Exists
```

## 🔍 Deep Dive: Understanding the Configuration

### Complete YAML Breakdown

```yaml
apiVersion: apps/v1
# ↑ API group and version for DaemonSet

kind: DaemonSet
# ↑ Resource type (changed from Deployment)

metadata:
  name: ds-important
  # ↑ DaemonSet name

  namespace: project-tiger
  # ↑ Namespace where DaemonSet is created

  labels:
    id: ds-important
    uuid: 18426a0b-5f59-4e10-923f-c0e078e82462
  # ↑ Labels for the DaemonSet itself

spec:
  # ↑ Specification of the DaemonSet

  selector:
    matchLabels:
      id: ds-important
      uuid: 18426a0b-5f59-4e10-923f-c0e078e82462
  # ↑ Labels used to select Pods owned by this DaemonSet
  # ⚠️ Must match template.labels!

  template:
    # ↑ Pod template for creating Pods

    metadata:
      labels:
        id: ds-important
        uuid: 18426a0b-5f59-4e10-923f-c0e078e82462
      # ↑ Labels for Pods created by this DaemonSet
      # ⚠️ Must match selector.matchLabels!

    spec:
      # ↑ Pod specification

      containers:
      - name: ds-important
        # ↑ Container name

        image: httpd:2-alpine
        # ↑ Container image (Apache HTTP server)

        resources:
          # 🔥 Resource requests

          requests:
            cpu: 10m
            # ↑ CPU request: 10 millicore (1/100 of a core)

            memory: 10Mi
            # ↑ Memory request: 10 Mebibytes

      tolerations:
        # 🔥 Tolerations to allow scheduling on control plane

      - effect: NoSchedule
        # ↑ Effect of the taint to tolerate

        key: node-role.kubernetes.io/control-plane
        # ↑ Key of the taint on control plane nodes

        operator: Exists
        # ↑ Operator: Exists means any value for the key is tolerated
```

### Key Changes Explained

| Change | Why |
|--------|-----|
| **Kind: Deployment → DaemonSet** | DaemonSets run one Pod per node |
| **Removed `replicas`** | DaemonSets automatically manage Pod count |
| **Removed `strategy`** | DaemonSets use `updateStrategy` instead |
| **Added labels** | Required for identification and selection |
| **Added resource requests** | Ensures Pods get guaranteed resources |
| **Added tolerations** | Allows scheduling on control plane nodes |

## 🛠️ Troubleshooting Common Issues

| Issue | Diagnosis | Solution |
|-------|-----------|----------|
| **DaemonSet not creating Pods** | Namespace missing | Create namespace: `kubectl create namespace project-tiger` |
| **Pods not running on control plane** | Missing tolerations | Add control plane toleration |
| **Pods stuck in Pending** | Resource constraints | Check node resources: `kubectl describe nodes` |
| **Wrong labels** | Selector mismatch | Ensure selector matches template labels |
| **Resource requests not applied** | Wrong indentation | Check YAML indentation |
| **DaemonSet not updating** | UpdateStrategy not set | Default is RollingUpdate |
| **Pod count mismatched** | Some nodes not ready | Check node status: `kubectl get nodes` |

## 💡 Best Practices & Key Takeaways

### Best Practices

| Practice | Why |
|----------|-----|
| **Set resource requests** | Guarantees resources for critical services |
| **Use tolerations for control planes** | Allow monitoring on all nodes |
| **Use meaningful labels** | Easy identification and selection |
| **Use updateStrategy: RollingUpdate** | Zero-downtime updates |
| **Set nodeSelector if needed** | Target specific node types |
| **Monitor DaemonSet status** | Ensure all nodes have Pods |
| **Test in dev first** | Validate before production |

### Key Takeaways

| Concept | Key Insight |
|---------|-------------|
| **DaemonSet** | Runs one Pod per node |
| **No replicas** | DaemonSets manage Pod count automatically |
| **Resource requests** | Ensure guaranteed resources |
| **Tolerations** | Allow scheduling on tainted nodes |
| **Control plane** | Has a taint to repel regular Pods |
| **Labels** | Must match across selector and template |

### CKA Exam Tips

📌 **Remember:** DaemonSet uses `kind: DaemonSet` (not Deployment)  
📌 **Remember:** DaemonSets do NOT use `replicas` field  
📌 **Remember:** DaemonSets do NOT use `strategy` field  
📌 **Remember:** Control plane nodes have taint: `node-role.kubernetes.io/control-plane:NoSchedule`  
📌 **Remember:** Tolerations must match the taint key and effect  
📌 **Remember:** Labels must match across `selector` and `template`  
📌 **Remember:** Resource requests are specified in `resources.requests`  
📌 **Remember:** `10m` = 10 millicores (0.01 CPU core)
