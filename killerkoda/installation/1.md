# 🚀 Complete Kubernetes Cluster Setup from Scratch — Comprehensive Documentation

This document provides a complete, step-by-step guide to building a production-ready Kubernetes cluster from bare Ubuntu servers using `kubeadm`. All commands, explanations, and official documentation links are included.

---

## 📋 Prerequisites

Before you begin, ensure each node meets the following requirements:

- A compatible Linux host (Ubuntu 22.04 LTS or 24.04 LTS recommended)
- **2 GB or more** of RAM per machine
- **2 CPUs or more** for control plane machines
- Full network connectivity between all machines
- Unique hostname, MAC address, and `product_uuid` for every node
- Required ports open (6443, 2379-2380, 10250, 10251, 10252, etc.)

## Step 1: System Preparation and Prerequisites 🔧

**Objective:** Prepare each node for Kubernetes installation by updating packages, disabling swap, loading kernel modules, and configuring network parameters.

### Task 1.1: Update System Packages

```bash
sudo apt-get update
sudo apt-get upgrade -y
```

### Task 1.2: Disable Swap

Kubernetes requires swap to be disabled — the kubelet will fail to start if swap is detected.

```bash
# Temporarily disable swap
sudo swapoff -a

# Permanently disable swap by commenting out swap entry in /etc/fstab
sudo sed -i '/ swap / s/^\(.*\)$/#\1/g' /etc/fstab

# Verify swap is disabled
free -h
```
*Expected: Swap line should show 0B or be absent.*

### Task 1.3: Load Required Kernel Modules

Create a configuration file for the required kernel modules:

```bash
cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF

# Load the modules immediately
sudo modprobe overlay
sudo modprobe br_netfilter

# Verify modules are loaded
lsmod | grep br_netfilter
lsmod | grep overlay
```

Problem: "modprobe: FATAL: Module overlay not found"

Solution: Update your kernel: sudo apt-get install linux-modules-extra-$(uname -r)

### Task 1.4: Configure Kernel Parameters for Networking

```bash
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

# Apply the settings
sudo sysctl --system

# Verify the settings
sysctl net.bridge.bridge-nf-call-iptables net.bridge.bridge-nf-call-ip6tables net.ipv4.ip_forward
```
*Expected: All values should be = 1.*

## Step 2: Install Container Runtime (containerd) 🐳

**Objective:** Install and configure containerd as the container runtime for Kubernetes.

Kubernetes needs a container runtime to run containers. Containerd is:

Lightweight: Industry-standard core container runtime
CRI-compliant: Works seamlessly with Kubernetes
Production-ready: Used by major cloud providers

### Task 2.1: Install containerd

```bash
# Install containerd from Ubuntu repositories
sudo apt-get update

# Install required packages for repository management:
sudo apt-get install -y apt-transport-https ca-certificates curl gpg

sudo apt-get install -y containerd

# Or install the latest containerd.io from Docker's official repository
# Download and add Docker's GPG key:
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

# Set proper permissions:
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# Add Docker repository:
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Task 2.3: Install containerd
# Update package list and install:
sudo apt-get update
sudo apt-get install -y containerd.io

#*** config.toml (Y/I/N/O/D/Z) [default=N] ? N
# Choose the default option
# Verify installation:
containerd --version

# Expected output: Should show containerd version (e.g., containerd containerd.io 1.7.x )
```

### Task 2.2: Configure containerd

```bash
# Create containerd configuration directory:
sudo mkdir -p /etc/containerd

# Generate default configuration
containerd config default | sudo tee /etc/containerd/config.toml
# CRITICAL: Enable SystemdCgroup (required for kubelet):

# Set SystemdCgroup to true for kubelet integration
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/g' /etc/containerd/config.toml

# Verify the change:
grep SystemdCgroup /etc/containerd/config.toml
# Expected output: SystemdCgroup = true

# Task 2.5: Restart and Enable containerd
# Restart the service to apply configuration:


```

**Why this matters:** Kubernetes requires the container runtime to use the systemd cgroup driver for proper resource management.

### Task 2.3: Start and Enable containerd

```bash
sudo systemctl restart containerd
sudo systemctl enable containerd
sudo systemctl status containerd
# Expected output: Should show active (running) in green
```

Problem: "Failed to start containerd.service"

Solution: Check logs with journalctl -xeu containerd.service

Verify configuration syntax: containerd config dump

Problem: SystemdCgroup not set to true

Solution: Manually edit the file:

sudo nano /etc/containerd/config.toml

Find [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc.options] Set SystemdCgroup = true

## Step 3: Install Kubernetes Components (kubeadm, kubelet, kubectl) ☸️

**Objective:** Install the three essential Kubernetes components.

kubeadm: Tool to bootstrap the cluster(creates and manages the control plane)
kubelet: Node agent that runs on every node(ensures containers are running in pods)
kubectl: Command-line tool to interact with the cluster(allows you to manage cluster resources)

> ⚠️ **Important:** Using the new package repositories hosted at `pkgs.k8s.io` is **strongly recommended** and required for Kubernetes versions released after September 13, 2023.

### Task 3.1: Add Kubernetes Repository GPG Key

```bash
# Download and add the Kubernetes GPG key for package verification:
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.31/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
```

### Task 3.2: Add Kubernetes Repository

```bash
echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.31/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list

sudo apt-get update
```

### Task 3.3: Install Kubernetes Components

```bash
sudo apt-get install -y kubelet kubeadm kubectl
```

### Task 3.4: Hold Package Versions

Prevent automatic updates that could cause version mismatches:

```bash
sudo apt-mark hold kubelet kubeadm kubectl
```

Why hold packages?
  Prevents accidental version mismatches
  Allows controlled cluster upgrades
  Ensures version consistency across nodes

### Task 3.5: Enable kubelet Service

```bash
sudo systemctl enable --now kubelet
sudo systemctl status kubelet
```

> **Note:** The kubelet will crash-loop until the cluster is initialized — this is normal and expected!

### Task 3.6: Verify Installation

```bash
kubeadm version
kubectl version --client
kubelet --version
```
*Expected: All should show version v1.31.x.*

---

#### Problem: Version mismatch between components
Solution: Specify exact version during install:
sudo apt-get install -y kubelet=1.31.x-* kubeadm=1.31.x-* kubectl=1.31.x-*

#### Problem: kubelet shows as failed
Solution: This is normal before cluster initialization. It will start properly after kubeadm init

## Step 4: Initialize Control Plane (Master Node) 🎛️

**Objective:** Initialize the Kubernetes control plane using `kubeadm init`.

Creates the control plane components (API server, scheduler, controller manager, etcd)
Generates certificates for secure communication
Creates the kubeconfig file for cluster access
Provides the join command for worker nodes

### Task 4.1: Get the Node's IP Address

```bash
hostname -I | awk '{print $1}'
```
Use this IP as `--apiserver-advertise-address` in the next command.

### Task 4.2: Initialize the Cluster

```bash
sudo kubeadm init \
  --pod-network-cidr=192.168.0.0/16 \
  --apiserver-advertise-address=<YOUR_NODE_IP> \
  --kubernetes-version=v1.31.0
```

**Parameter explanations:**
- `--pod-network-cidr=192.168.0.0/16`: IP range for pod network (required for Calico CNI)
- `--apiserver-advertise-address`: IP address the API server will advertise
- `--kubernetes-version`: Explicit version specification
- `--ignore-preflight-errors=NumCPU` : It tells kubeadm to ignore the CPU requirement check and continue even if you have too few CPUs.

> ⏱️ **Wait time:** 2-5 minutes for initialization to complete.

```bash
Example output:

Your Kubernetes control-plane has initialized successfully!

To start using your cluster, you need to run the following as a regular user:

  mkdir -p $HOME/.kube
  sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
  sudo chown $(id -u):$(id -g) $HOME/.kube/config

Then you can join any number of worker nodes by running the following on each as root:

kubeadm join 192.168.1.100:6443 --token abc123.xyz789 \
	--discovery-token-ca-cert-hash sha256:abcd1234...
```

### Task 4.3: Save the Join Command

The output includes a `kubeadm join` command — **save this immediately** for worker nodes:

```
kubeadm join <MASTER_IP>:6443 --token <TOKEN> --discovery-token-ca-cert-hash sha256:<HASH>
```

### Task 4.4: Configure kubectl for the Master Node

```bash
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
```

### Task 4.5: Verify Cluster Initialization

```bash
kubectl cluster-info
kubectl get nodes

# Expected output:

# Kubernetes control plane is running at https://<IP>:6443
# CoreDNS is running at https://<IP>:6443/api/v1/namespaces/kube-system/services/kube-dns:dn
```
*Expected: Node shows `NotReady` status — this is expected until CNI is installed.*

---

#### Problem: "Port 6443 is already in use"
Solution: Another process is using the API server port
Check: `sudo lsof -i :6443`
If previous init failed: sudo kubeadm reset then try again

#### Problem: "kubelet is not running or healthy"
Solution: Check kubelet status: sudo systemctl status kubelet
Restart: `sudo systemctl restart kubelet`

#### Problem: "Unable to connect to the server"
Solution: Verify kubectl config is copied correctly
Check: `ls -la ~/.kube/config`

#### Problem: Lost join command
Solution: Generate a new one:
`kubeadm token create --print-join-command`

## Step 5: Install Pod Network (CNI Plugin) 🌐

**Objective:** Install a CNI plugin to enable pod-to-pod communication across the cluster.

### Option A: Calico (Recommended for Production) ⭐

Calico provides network policy support, better scalability, and advanced networking features.

Advantages:

Network policy support
Better scalability
Advanced networking features
Production-ready

```bash
# Install Tigera Operator and CRDs
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.32.0/manifests/tigera-operator.yaml

# Download and apply custom resources
curl -O https://raw.githubusercontent.com/projectcalico/calico/v3.32.0/manifests/custom-resources.yaml
kubectl create -f custom-resources.yaml

# Monitor Calico pods
watch kubectl get pods -n calico-system
```
⏱️ **Wait:** 2-3 minutes for all pods to reach `Running` state.

### Option B: Flannel (Simpler Alternative) 🚀

Flannel is a lightweight, simpler CNI plugin ideal for testing and learning.

```bash
kubectl apply -f https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml

# Monitor Flannel pods
watch kubectl get pods -n kube-flannel
```
⏱️ **Wait:** 1-2 minutes for pods to reach `Running` state.

Advantages:

Simpler architecture
Faster installation
Good for testing/learning

### Task 5.1: Verify Node Status

```bash
kubectl get nodes
```
*Expected: STATUS should now be `Ready`.*

```bash
kubectl get pods -n kube-system
```
*Expected: All pods (including CoreDNS) should be in `Running` state.*

---

#### Problem: Node still shows NotReady after 5 minutes
Solution: Check CNI pod logs:
kubectl logs -n calico-system -l k8s-app=calico-node
or for Flannel:
kubectl logs -n kube-flannel -l app=flannel


#### Problem: CNI pods in CrashLoopBackOff
Solution:
Verify pod network CIDR matches init: 192.168.0.0/16
Check: kubectl cluster-info dump | grep cluster-cidr
If mismatch, you may need to reinitialize

#### Problem: CoreDNS pods pending
Solution: This is normal until CNI is fully running
Wait 2-3 more minutes and check again

#### Problem: "connection refused" errors
Solution: Ensure API server is healthy:
kubectl get --raw /healthz

## Step 6: Join Worker Nodes to Cluster 👷

**Objective:** Add worker nodes to the Kubernetes cluster using the `kubeadm join` command.

### Task 6.1: Retrieve the Join Command

If you lost the join command, generate a new one on the master node:

```bash
kubeadm token create --print-join-command
```

### Task 6.2: Worker Node Prerequisites

On each worker node, ensure **Steps 1-3** are completed (system preparation, containerd installation, Kubernetes components installation).

> 🔴 **DO NOT run `kubeadm init` on worker nodes** — only on the master!

### Task 6.3: Execute Join Command

On each worker node, run the join command as root:

```bash
sudo kubeadm join <MASTER_IP>:6443 --token <TOKEN> --discovery-token-ca-cert-hash sha256:<HASH>
```

<MASTER_IP>:6443 : API server address and port
--token : Authentication token (expires in 24 hours)
--discovery-token-ca-cert-hash : CA certificate hash for security

```bash
[preflight] Running pre-flight checks
[preflight] Reading configuration from the cluster...
[preflight] FYI: You can look at this config file with 'kubectl -n kube-system get cm kubeadm-config -o yaml'
[kubelet-start] Writing kubelet configuration to file "/var/lib/kubelet/config.yaml"
[kubelet-start] Writing kubelet environment file with flags to file "/var/lib/kubelet/kubeadm-flags.env"
[kubelet-start] Starting the kubelet
[kubelet-start] Waiting for the kubelet to perform the TLS Bootstrap...

This node has joined the cluster:
* Certificate signing request was sent to apiserver and a response was received.
* The Kubelet was informed of the new secure connection details.

Run 'kubectl get nodes' on the control-plane to see this node join the cluster.
```

### Task 6.4: Verify Worker Nodes

On the master node:

```bash
kubectl get nodes
```


### Manual Token and Hash Retrieval (Advanced)
If you need to construct the join command manually:

```bash
# Get the token:
kubeadm token list

# Create a new token if needed:
kubeadm token create

# Get the CA certificate hash:
openssl x509 -pubkey -in /etc/kubernetes/pki/ca.crt | \
   openssl rsa -pubin -outform der 2>/dev/null | \
   openssl dgst -sha256 -hex | sed 's/^.* //'

# Construct the join command:
sudo kubeadm join <MASTER_IP>:6443 \
  --token <TOKEN_FROM_LIST> \
  --discovery-token-ca-cert-hash sha256:<HASH_FROM_ABOVE>
```

## 🔍 Troubleshooting Quick Reference

| Problem | Solution |
|---------|----------|
| Node stays `NotReady` | Check CNI pod logs: `kubectl logs -n calico-system -l k8s-app=calico-node` |
| CNI pods in `CrashLoopBackOff` | Verify `--pod-network-cidr` matches CNI configuration |
| `kubeadm init` fails | Run `sudo kubeadm reset` and try again |
| Lost join token | Generate new: `kubeadm token create --print-join-command` |
| "connection refused" | Verify API server is healthy: `kubectl get --raw /healthz` |
| Token expired | Generate a new token with `kubeadm token create` |
