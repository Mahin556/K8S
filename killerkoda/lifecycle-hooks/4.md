Your explanation is correct, but there is **one important inaccuracy** regarding the order of events.

The statement:

> **SIGTERM Signal: Kubernetes sends a stop signal to the container process right away.**

is **not always true** when a **`preStop` hook** is configured.

According to the Kubernetes lifecycle documentation:

* The **termination grace period countdown starts first**.
* Then the **`preStop` hook executes** (if present).
* **Only after the `preStop` hook completes** does Kubernetes send the stop signal (by default `SIGTERM`).
* If the grace period expires before the container exits, Kubernetes sends `SIGKILL`.

---

# Correct Shutdown Sequence

```text
Pod Deletion Requested
        │
        ▼
terminationGracePeriodSeconds timer starts
        │
        ▼
Run preStop hook (if configured)
        │
        ▼
Send SIGTERM (or custom StopSignal)
        │
        ▼
Application performs graceful shutdown
        │
        ▼
Container exits
        │
        ▼
Done
```

If the application doesn't exit before the grace period ends:

```text
Pod Deletion Requested
        │
        ▼
Grace period timer starts
        │
        ▼
Run preStop hook
        │
        ▼
SIGTERM sent
        │
        ▼
Application still running...
        │
        ▼
Grace period expires
        │
        ▼
SIGKILL sent
        │
        ▼
Container forcefully terminated
```

# Example 1: No `preStop` Hook

```yaml
spec:
  terminationGracePeriodSeconds: 30
```

Timeline:

```text
0s  Pod deletion requested
│
├── SIGTERM sent immediately
│
├── Application shuts down
│
└── Must finish within 30 seconds
```

Since there is no `preStop` hook, Kubernetes sends `SIGTERM` right away.

---

# Example 2: With a `preStop` Hook

```yaml
spec:
  terminationGracePeriodSeconds: 30

  containers:
  - name: app
    image: nginx

    lifecycle:
      preStop:
        exec:
          command:
            - sh
            - -c
            - sleep 10
```

Timeline:

```text
0s  Pod deletion requested
│
├── 30-second timer starts
│
├── preStop hook runs (10 seconds)
│
├── SIGTERM sent
│
├── Application shuts down
│
└── Must finish before 30 seconds total
```

The application now has only **20 seconds** remaining after the hook finishes.

# Example 3: Grace Period Too Short

```yaml
terminationGracePeriodSeconds: 15
```

`preStop`:

```bash
sleep 10
```

Application needs:

```text
10 seconds
```

Timeline:

```text
0s  Delete Pod
│
├── Timer starts (15s)
│
├── preStop sleeps 10s
│
├── SIGTERM sent
│
├── Application needs 10s
│
└── At 15s → SIGKILL
```

The application gets only **5 seconds** after receiving `SIGTERM`, so it is forcefully terminated.

# Configuration Example

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: graceful-app
spec:
  terminationGracePeriodSeconds: 60

  containers:
    - name: app
      image: nginx

      lifecycle:
        preStop:
          exec:
            command:
              - sh
              - -c
              - |
                echo "Draining connections..."
                sleep 20
```

Timeline:

```text
Delete Pod
      │
      ▼
60-second timer starts
      │
      ▼
preStop executes (20s)
      │
      ▼
SIGTERM sent
      │
      ▼
Application has 40 seconds left to exit
      │
      ▼
Container exits normally
```

# Key Takeaways

* **Default value:** `terminationGracePeriodSeconds: 30`
* The **grace period timer starts before** the `preStop` hook.
* If a `preStop` hook exists, **`SIGTERM` is sent only after the hook completes**.
* The `preStop` hook time **counts against** the grace period.
* If the total time (**`preStop` + application shutdown**) exceeds `terminationGracePeriodSeconds`, Kubernetes sends **`SIGKILL`**.
* Increase `terminationGracePeriodSeconds` if your application needs more time to drain requests, flush data, or perform cleanup.
