Lifecycle hooks become much easier to understand once you see them solving real problems instead of just echoing text.

---

# What are Lifecycle Hooks?

A lifecycle hook is **code that Kubernetes executes at specific moments in a container's life**.

There are only **two hooks**:

| Hook          | When it runs                            | Common Uses                                                          |
| ------------- | --------------------------------------- | -------------------------------------------------------------------- |
| **postStart** | Immediately after the container starts  | Initialization, logging, downloading files, waiting for dependencies |
| **preStop**   | Just before the container is terminated | Graceful shutdown, save data, notify other services, drain traffic   |

Think of them like:

```
Container Starting
        │
        ▼
   postStart Hook
        │
        ▼
  Application Runs
        │
        ▼
Container Termination Requested
        │
        ▼
    preStop Hook
        │
        ▼
Container Stops
```

# Example 1: Simple Logging

When the container starts, create a log.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: poststart-log
spec:
  containers:
  - name: app
    image: busybox
    command:
      - sh
      - -c
      - sleep 300

    lifecycle:
      postStart:
        exec:
          command:
            - sh
            - -c
            - |
              echo "Started at $(date)" >> /tmp/start.log
```

Verify

```bash
kubectl exec poststart-log -- cat /tmp/start.log
```

Output

```
Started at Wed Jul 30 10:40:05 UTC 2026
```

# Example 2: Create Directories

Many applications need folders before they start.

```
Container Starts

↓

Create folders

↓

Application Uses Them
```

```yaml
lifecycle:
  postStart:
    exec:
      command:
      - sh
      - -c
      - |
        mkdir -p /tmp/data
        mkdir -p /tmp/cache
```

Verify

```
kubectl exec poststart-log -- ls /tmp
```

Output

```
cache
data
```

# Example 3: Download Configuration

Imagine your application needs a configuration file.

```
Container Starts

↓

Download config

↓

Run application
```

```yaml
lifecycle:
  postStart:
    exec:
      command:
      - sh
      - -c
      - |
        wget https://example.com/config.json -O /tmp/config.json
```

Production applications often fetch:

* Configurations
* Certificates
* API keys (usually from Secrets instead)

# Example 4: Wait for Database

Application cannot work until MySQL starts.

```
Start Container

↓

Wait for MySQL

↓

Continue
```

```yaml
postStart:
  exec:
    command:
    - sh
    - -c
    - |
      until nc -z mysql-service 3306
      do
        echo "Waiting..."
        sleep 2
      done

      echo "Database Ready"
```

# Example 9: Graceful Shutdown

Instead of killing immediately:

```
Delete Pod

↓

Tell application

↓

Finish requests

↓

Exit
```

```yaml
preStop:
  exec:
    command:
    - sh
    - -c
    - |
      echo "Stopping..."
      sleep 20
```

# Example 12: Deregister from Load Balancer

Delete Pod

↓

Remove from Load Balancer

No New Requests

↓

Finish Old Requests

↓

# Example 16: Combined Example

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: lifecycle-complete
spec:
  containers:
  - name: demo
    image: busybox
    command:
    - sh
    - -c
    - sleep 3600

    lifecycle:

      postStart:
        exec:
          command:
          - sh
          - -c
          - |
            echo "Started at $(date)"
            mkdir -p /tmp/data
            touch /tmp/data/app.log

      preStop:
        exec:
          command:
          - sh
          - -c
          - |
            echo "Stopping at $(date)"
            sleep 15
```

# Real-World Uses by Application Type

| Application           | `postStart`                                  | `preStop`                                                  |
| --------------------- | -------------------------------------------- | ---------------------------------------------------------- |
| Nginx                 | Generate config, create directories          | Finish serving active requests before shutdown             |
| MySQL                 | Initialize data directory, set permissions   | Flush buffers and close connections cleanly                |
| Redis                 | Load cache or configuration                  | Persist in-memory data to disk before exit                 |
| Java (Spring Boot)    | Download configuration, initialize resources | Complete in-flight requests and close resources            |
| Node.js               | Install runtime configuration, warm caches   | Stop accepting new requests and close database connections |
| Python (Flask/Django) | Prepare environment, generate files          | Finish current requests and release resources              |
| Kafka Consumer        | Register consumer and initialize state       | Commit offsets before stopping                             |
| CI/CD Runner          | Fetch build scripts or tools                 | Upload logs and clean temporary files                      |

## Important Notes

* **`postStart` is asynchronous** with the container's entrypoint. Kubernetes invokes the hook after the container starts, but it does **not guarantee** the hook finishes before your application begins executing. If your application must not start until initialization is complete, consider using an **init container** instead.
* **`preStop` runs before the container receives `SIGTERM`**, and the hook execution counts toward the Pod's `terminationGracePeriodSeconds`. If the hook takes longer than the grace period, Kubernetes will eventually send `SIGKILL` and terminate the container forcefully.
* Lifecycle hooks are best suited for **lightweight initialization and cleanup**. For lengthy setup tasks, **init containers** are generally the better choice.
