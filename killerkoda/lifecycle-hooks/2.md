Besides `exec`, Kubernetes also supports an **HTTP lifecycle hook** (`httpGet`). This is useful when your application exposes an HTTP endpoint that can perform startup or shutdown actions.

> **Note:** HTTP lifecycle hooks are only available for containers running in the Pod. Kubernetes sends the HTTP request to the container itself (using its IP), not to an external service.

---

# Syntax

```yaml
lifecycle:
  postStart:
    httpGet:
      path: /startup
      port: 8080
      scheme: HTTP

  preStop:
    httpGet:
      path: /shutdown
      port: 8080
      scheme: HTTP
```

When the hook runs, Kubernetes performs:

```text
POSTSTART
Container Starts
        │
        ▼
GET http://<Pod-IP>:8080/startup
```

or

```text
PRESTOP
Pod Deletion
        │
        ▼
GET http://<Pod-IP>:8080/shutdown
```

---

# Example 1: Notify the Application It Has Started

Imagine your application exposes:

```text
GET /startup
```

The application logs:

```text
Application Started Successfully
```

Pod YAML:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: startup-hook
spec:
  containers:
  - name: app
    image: myapp:latest

    lifecycle:
      postStart:
        httpGet:
          path: /startup
          port: 8080
```

Flow:

```text
Container Starts
      │
      ▼
GET /startup
      │
      ▼
Application Performs Initialization
```

# Example 2: Graceful Shutdown

Application exposes:

```text
GET /shutdown
```

When deleting the Pod:

```yaml
lifecycle:
  preStop:
    httpGet:
      path: /shutdown
      port: 8080
```

Application code:

```text
Receive GET /shutdown

↓

Stop accepting new requests

↓

Finish active requests

↓

Close database connections

↓

Exit
```

This is very common in Java, Spring Boot, and .NET applications.

---

# Example 3: Spring Boot

Spring Boot application:

```text
http://localhost:8080/actuator/shutdown
```

Pod:

```yaml
lifecycle:
  preStop:
    httpGet:
      path: /actuator/shutdown
      port: 8080
```

When Kubernetes deletes the Pod:

```text
GET /actuator/shutdown
```

Spring Boot shuts down gracefully.

> Note: The shutdown actuator endpoint is disabled by default in modern Spring Boot versions and must be explicitly enabled.

# HTTP Hook vs Exec Hook

| Feature                                          | `exec`    | `httpGet`   |
| ------------------------------------------------ | --------- | ----------- |
| Runs shell commands                              | ✅         | ❌           |
| Calls an HTTP endpoint in the container          | ❌         | ✅           |
| Good for creating files/directories              | ✅         | ❌           |
| Good for application APIs                        | ❌         | ✅           |
| Used by Nginx, Spring Boot, Node.js, Go services | Sometimes | Very common |
| Requires a shell in the container                | Yes       | No          |

---

# When to Use Each

Use **`exec`** when you need to:

* Create directories
* Set file permissions
* Copy files
* Execute shell scripts
* Run cleanup commands

Use **`httpGet`** when your application already exposes HTTP endpoints to:

* Initialize itself
* Warm up caches
* Register or unregister with service discovery
* Stop accepting traffic
* Flush metrics or sessions
* Perform graceful shutdown logic

In modern microservices, **`httpGet`** is often preferred because the application controls its own startup and shutdown behavior through well-defined HTTP endpoints, while **`exec`** is more appropriate for operating-system-level tasks inside the container.
