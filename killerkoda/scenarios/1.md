You can create your own **Killercoda scenarios** by creating a GitHub repository with the required files and then linking it to Killercoda. A scenario consists of Markdown instructions, environment configuration, and optional setup scripts.

## Step 1: Create a GitHub Repository

Create a public GitHub repository.

Example:

```text
my-killercoda-scenarios/
└── hello-linux/
    ├── index.json
    ├── intro.md
    ├── finish.md
    ├── background.sh
    ├── foreground.sh
    └── assets/
```

* Repository: `my-killercoda-scenarios`
* Scenario: `hello-linux`

You can have multiple scenarios inside one repository.

---

## Step 2: Create `index.json`

This file defines your scenario.

Example:

```json
{
  "title": "Linux Basics",
  "description": "Learn basic Linux commands",
  "difficulty": "beginner",
  "time": "15 minutes",
  "details": {
    "intro": {
      "text": "intro.md"
    },
    "finish": {
      "text": "finish.md"
    }
  },
  "backend": {
    "imageid": "ubuntu"
  }
}
```

Common images:

* ubuntu
* centos
* alpine
* docker
* kubernetes
* k3s
* kind
* vscode

---

## Step 3: Create `intro.md`

This is what the learner sees.

Example:

````markdown
# Linux Basics

Welcome!

Run:

```bash
pwd
```

Now list the files.

```bash
ls
```
````

---

## Step 4: Create `background.sh`

Runs automatically before the user starts.

Example:

```bash
#!/bin/bash

mkdir /root/demo

echo "Hello Killercoda" >/root/demo/file.txt

apt update
apt install -y tree
```

Useful for:

* installing packages
* cloning repositories
* creating files
* downloading data
* configuring services

---

## Step 5: Create `foreground.sh` (optional)

Runs after the environment is ready.

Example:

```bash
#!/bin/bash

echo "Scenario Ready!"
```

---

## Step 6: Create `finish.md`

Displayed at the end.

```markdown
Congratulations!

You completed the scenario.
```

# Example: Docker Scenario

```
docker-scenario/
│
├── index.json
├── intro.md
├── finish.md
└── background.sh
```

background.sh

```bash
#!/bin/bash

apt update
apt install -y docker.io

systemctl enable docker
systemctl start docker

docker run -d nginx
```

intro.md

````markdown
## Verify Docker

Run

```bash
docker ps
```

Now inspect the nginx container.
````

# Example: Kubernetes Scenario

background.sh

```bash
#!/bin/bash

curl -sfL https://get.k3s.io | sh -

export KUBECONFIG=/etc/rancher/k3s/k3s.yaml

kubectl create deployment nginx --image=nginx
```

Then in the instructions ask the learner to:

* Check pods
* Expose deployment
* Scale deployment
* Delete deployment

---

# Step 7: Test Locally

You can simply verify that:

```bash
bash background.sh
```

runs without errors before pushing to GitHub.

---

# Step 8: Publish to Killercoda

1. Push your repository to GitHub.
2. Sign in to Killercoda.
3. Create a new scenario.
4. Connect your GitHub repository.
5. Select the scenario directory.
6. Save and publish.

Whenever you push changes to GitHub, Killercoda can use the updated scenario.

---

# Adding Validation (Recommended)

A good interactive lab checks whether the learner completed the task.

Example `verify.sh`:

```bash
#!/bin/bash

if docker ps | grep -q nginx; then
    echo "Success!"
    exit 0
else
    echo "Container not running."
    exit 1
fi
```

You can configure your scenario so users must pass these checks before moving on.

# Advanced Features

You can create rich learning experiences with:

* **Multiple tabs** (terminal, editor, browser)
* **Embedded VS Code**
* **Kubernetes clusters** (K3s, Kind, Minikube)
* **Docker environments**
* **Multiple machines** (master/worker, client/server)
* **Port forwarding** (e.g., expose web apps)
* **Automatic grading** with validation scripts
* **Hints and step-by-step instructions**
* **Custom startup scripts**
* **Preloaded repositories and datasets**

## Scenario Ideas for Your DevOps Background

Given your experience with Linux, Docker, Kubernetes, Terraform, AWS, and CI/CD, you could create labs such as:

1. **Linux Troubleshooting**

   * Fix broken permissions
   * Repair systemd services
   * Analyze logs with `journalctl`

2. **Docker**

   * Build an image
   * Optimize a Dockerfile
   * Debug a failing container

3. **Kubernetes**

   * Fix a CrashLoopBackOff pod
   * Repair networking issues
   * Configure Ingress
   * Troubleshoot PVC problems

4. **Terraform**

   * Write modules
   * Manage state
   * Fix a broken plan

5. **Ansible**

   * Complete missing playbook tasks
   * Use handlers
   * Work with roles and variables

6. **GitHub Actions**

   * Repair a failing CI pipeline
   * Configure caching
   * Publish Docker images

7. **AWS**

   * Deploy EC2 instances
   * Configure an Application Load Balancer
   * Set up Auto Scaling
   * Create VPC networking

These kinds of hands-on, troubleshooting-focused scenarios are especially valuable for interview preparation and DevOps training.
