## 🎯 Scenario Overview

### Your Mission

Create an Egress NetworkPolicy that controls outgoing traffic from specific Pods while allowing DNS resolution.

### The Context

- Namespace: `venus`
- Target Pods: Pods with label `app=frontend`
- Policy Name: `np1`
- Policy Type: Egress

### Allowed Egress Traffic

| **Pods with `app=api`** | TCP port `2222` | Application communication |

## 🧠 Conceptual Summary

### What is an Egress NetworkPolicy?

An **Egress NetworkPolicy** controls **outbound** traffic from Pods. It defines:

- **WHERE** Pods can send traffic (destinations)
- **WHAT** ports/protocols they can use
- **WHEN** traffic is allowed or denied

### Key Concepts

| Concept | Description |
|---------|-------------|
| **Egress** | Outbound traffic from Pods to external destinations |
| **Ingress** | Inbound traffic to Pods from external sources |
| **`podSelector`** | Selects which Pods the policy applies to |
| **`to`** | Specifies allowed destinations (similar to `from` for ingress) |
| **`namespaceSelector`** | Selects destinations by namespace labels |
| **`podSelector`** | Selects destinations by pod labels |

### Why DNS Allowance is Important

```

┌─────────────────────────────────────────────────────────────────────────────┐
```

## 📋 Step-by-Step Solution

### Step 1: Create the NetworkPolicy

```bash
vi np1.yaml
```

### Step 2: Add the NetworkPolicy Configuration

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: np1
  namespace: venus
spec:
  podSelector:
    matchLabels:
      app: frontend
  policyTypes:
  - Egress
  egress:
  - to:
    - podSelector:
        matchLabels:
          app: api
    ports:
    - protocol: TCP
      port: 2222
  - to:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: kube-system
      podSelector:
        matchLabels:
          k8s-app: kube-dns
    ports:
    - protocol: UDP
      port: 53
    - protocol: TCP
      port: 53
```

### Step 3: Apply the NetworkPolicy

```bash
kubectl apply -f np1.yaml
```

**Expected Output:**
```
networkpolicy.networking.k8s.io/np1 created
```

### Step 4: Verify the NetworkPolicy

```bash
kubectl get networkpolicy -n venus
```

**Expected Output:**
```
NAME   POD-SELECTOR     AGE
np1    app=frontend     10s
```

```bash
kubectl describe networkpolicy np1 -n venus
```

## 🔍 Deep Dive: Understanding the Configuration

### Complete YAML Breakdown

```yaml
apiVersion: networking.k8s.io/v1
# ↑ API group and version for NetworkPolicy

kind: NetworkPolicy
# ↑ Resource type

metadata:
  name: np1
  # ↑ Policy name

  namespace: venus
  # ↑ Namespace where policy is applied

spec:
  # ↑ Specification

  podSelector:
    matchLabels:
      app: frontend
  # ↑ Selects which Pods this policy applies to
  # Only Pods with label app=frontend are affected

  policyTypes:
  - Egress
  # ↑ Specifies the type of traffic this policy controls
  # Egress = outbound traffic

  egress:
  # ↑ List of egress rules

  # ──────────────────────────────────────────────
  # RULE 1: API Access (TCP 2222)
  # ──────────────────────────────────────────────
  - to:
    - podSelector:
        matchLabels:
          app: api
    # ↑ Allow traffic to Pods with label app=api

    ports:
    - protocol: TCP
      port: 2222
    # ↑ Only allow TCP traffic on port 2222

  # ──────────────────────────────────────────────
  # RULE 2: DNS Resolution (UDP/TCP 53)
  # ──────────────────────────────────────────────
  - to:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: kube-system
      # ↑ Allow traffic to kube-system namespace

      podSelector:
        matchLabels:
          k8s-app: kube-dns
      # ↑ Allow traffic to CoreDNS pods

    ports:
    - protocol: UDP
      port: 53
      # ↑ UDP for DNS queries

    - protocol: TCP
      port: 53
      # ↑ TCP for DNS zone transfers
```

### Key Fields Explained

| Field | Value | Purpose |
|-------|-------|---------|
| **`podSelector`** | `app: frontend` | Policy applies to frontend Pods only |
| **`policyTypes`** | `[Egress]` | Controls outbound traffic |
| **`to`** | API Pods | Destinations allowed to send traffic to |
| **`to`** | CoreDNS | DNS resolution destinations |
| **`ports`** | TCP `2222` | API communication port |
| **`ports`** | UDP `53`, TCP `53` | DNS ports (both protocols!) |

### Why Both UDP and TCP for DNS?

| Protocol | Purpose |
|----------|---------|
| **UDP 53** | Standard DNS queries (small responses) |
| **TCP 53** | Large DNS responses, zone transfers, fallback |

**Important:** DNS uses **both** UDP and TCP. You must allow both for full DNS functionality.

## 🌐 DNS Considerations in Egress Policies

### The Problem

Without DNS allowance, Pods cannot resolve service names:

```
frontend Pod → nslookup api.venus.svc.cluster.local
                     ↓
            NetworkPolicy blocks UDP 53
                     ↓
           ❌ DNS resolution fails!
                     ↓
       frontend Pod cannot find api Pod
```

### The Solution

Allow DNS to CoreDNS:

```yaml
- to:
  - namespaceSelector:
      matchLabels:
        kubernetes.io/metadata.name: kube-system
    podSelector:
      matchLabels:
        k8s-app: kube-dns
  ports:
  - protocol: UDP
    port: 53
  - protocol: TCP
    port: 53
```

### CoreDNS Labels

| Label | Value | Purpose |
|-------|-------|---------|
| **`kubernetes.io/metadata.name`** | `kube-system` | CoreDNS namespace |
| **`k8s-app`** | `kube-dns` | CoreDNS pod label |

### DNS Resolution Flow

```
frontend Pod (app=frontend)
        ↓
nslookup api.venus.svc.cluster.local
        ↓
NetworkPolicy: Allowed DNS? ✅
        ↓
CoreDNS (kube-system)
        ↓
api.venus.svc.cluster.local → 10.96.0.5
        ↓
frontend Pod can now access api Pod
```

## 🛠️ Troubleshooting Common Issues

| Issue | Diagnosis | Solution |
|-------|-----------|----------|
| **DNS resolution fails** | UDP 53 or TCP 53 blocked | Allow both UDP and TCP 53 |
| **API access fails** | Wrong port or label | Check port 2222 and `app=api` label |
| **External traffic allowed** | Missing default deny | Egress policy defaults to deny all |
| **Policy not applying** | Wrong namespace | Ensure policy is in `venus` namespace |
| **Pod selector mismatch** | Wrong label | Check `app=frontend` label on Pods |
| **DNS pods not found** | Wrong labels | Check `k8s-app=kube-dns` in `kube-system` |

## 💡 Best Practices & Key Takeaways

### Best Practices

| Practice | Why |
|----------|-----|
| **Always allow DNS** | Pods need DNS for service discovery |
| **Allow both UDP and TCP 53** | DNS uses both protocols |
| **Use specific ports** | Avoid allowing all ports |
| **Use podSelector for destinations** | Target specific Pods |
| **Use namespaceSelector for CoreDNS** | Target CoreDNS in kube-system |
| **Test thoroughly** | Verify before applying to production |
| **Document your policies** | Make them understandable |

### DNS Best Practices

| Practice | Why |
|----------|-----|
| **Allow UDP 53** | Standard DNS queries |
| **Allow TCP 53** | Large responses, zone transfers |
| **Target CoreDNS exactly** | Use specific labels |
| **Test DNS resolution** | Verify from Pods |

### Key Takeaways

| Concept | Key Insight |
|---------|-------------|
| **Egress Policy** | Controls outbound traffic |
| **DNS Allowance** | Required for service discovery |
| **UDP + TCP 53** | Both protocols needed for DNS |
| **CoreDNS Labels** | `k8s-app=kube-dns` in `kube-system` |
| **Default Deny** | All traffic denied unless explicitly allowed |

### CKA Exam Tips

📌 **Remember:** Egress policies control outbound traffic  
📌 **Remember:** DNS uses both UDP and TCP port 53  
📌 **Remember:** CoreDNS is in `kube-system` namespace  
📌 **Remember:** CoreDNS label is `k8s-app=kube-dns`  
📌 **Remember:** `podSelector` selects which Pods the policy applies to  
📌 **Remember:** `to` specifies allowed destinations  
📌 **Remember:** Default behavior is deny all (with policy applied)
