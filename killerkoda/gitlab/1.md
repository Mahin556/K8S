## 🛠️ Step 1: GitLab Runner Gets the Credentials

### Where the Token is Stored

In GitLab, you store your Kubernetes credentials as **CI/CD Variables**:

| Variable | Purpose | Value |
|----------|---------|-------|
| `KUBE_TOKEN` | Authentication token | Your generated token from `kubectl create token` |
| `KUBE_URL` | API Server endpoint | `https://172.30.1.2:6443` |
| `KUBE_CA_CERT` | CA certificate | The `ca.cert` you extracted |
| `KUBE_NAMESPACE` | Target namespace | `gitlab-cicd` |

### How to Set These Variables

1. Go to your GitLab project → **Settings** → **CI/CD** → **Variables**
2. Add the following variables:

```
KUBE_TOKEN   → (your 2-hour token)
KUBE_URL     → https://172.30.1.2:6443
KUBE_CA_CERT → (contents of ca.cert)
KUBE_NAMESPACE → gitlab-cicd
```

## 📄 Step 2: Configure `.gitlab-ci.yml`

### Method 1: Using `kubectl` Directly

```yaml
# .gitlab-ci.yml
image: bitnami/kubectl:latest

variables:
  KUBE_NAMESPACE: gitlab-cicd

deploy:
  stage: deploy
  script:
    # Configure kubectl with the ServiceAccount token
    - kubectl config set-credentials gitlab-ci --token=$KUBE_TOKEN
    - kubectl config set-cluster my-cluster --server=$KUBE_URL --insecure-skip-tls-verify=true
    - kubectl config set-context my-context --cluster=my-cluster --user=gitlab-ci --namespace=$KUBE_NAMESPACE
    - kubectl config use-context my-context
    
    # Now you can run kubectl commands!
    - kubectl get pods
    - kubectl get deployments
    - kubectl apply -f deployment.yaml
    - kubectl rollout status deployment/my-app
  only:
    - main
```

### Method 2: Using GitLab's Kubernetes Integration

```yaml
# .gitlab-ci.yml
image: docker:latest

variables:
  KUBE_NAMESPACE: gitlab-cicd

deploy:
  stage: deploy
  image: 
    name: bitnami/kubectl:latest
    entrypoint: [""]
  script:
    # GitLab automatically sets KUBECONFIG when using integrated Kubernetes
    - kubectl get pods -n $KUBE_NAMESPACE
    - kubectl apply -f deployment.yaml -n $KUBE_NAMESPACE
  environment:
    name: production
    kubernetes:
      namespace: gitlab-cicd
  only:
    - main
```

### Method 3: Using Helm for Deployments

```yaml
# .gitlab-ci.yml
image: alpine/helm:latest

deploy:
  stage: deploy
  script:
    # Configure kubectl
    - kubectl config set-credentials gitlab-ci --token=$KUBE_TOKEN

    - kubectl config use-context my-context

    - helm upgrade --install my-app ./helm-chart --namespace=gitlab-cicd
  only:
    - main
```

## 🔄 Step 3: What GitLab Can Do With These Permissions

Based on your ClusterRole, GitLab can perform the following operations:

### Pods Operations
```bash
# Get pod details
kubectl get pod my-app-xxx
kubectl describe pod my-app-xxx

# List all pods
kubectl get pods

# Watch pod status
kubectl get pods -w

# Create new pods (via deployment)
kubectl run test-pod --image=nginx

# Update pods (via deployment)
kubectl patch deployment my-app -p '{"spec":{"replicas":3}}'

# Delete pods
kubectl delete pod my-app-xxx
```

### Deployments Operations
```bash
# Get deployment details
kubectl get deployment my-app
kubectl describe deployment my-app

# List deployments
kubectl get deployments

# Watch deployment status
kubectl get deployments -w

# Create deployment
kubectl create deployment my-app --image=nginx

# Update deployment (scale, update image, etc.)
kubectl scale deployment my-app --replicas=3
kubectl set image deployment/my-app nginx=nginx:1.21

# Delete deployment
kubectl delete deployment my-app
```

### Jobs Operations
```bash
# Get job details
kubectl get job my-job
kubectl describe job my-job

# List jobs
kubectl get jobs

# Create job
kubectl create job my-job --image=busybox -- echo "Hello"

# Delete job
kubectl delete job my-job
```

## 📊 Step 4: Token Renewal Process

Since your token expires after **2 hours**, you need a process to renew it:

### Manual Renewal (for testing)

```bash
# Generate new token
kubectl create token gitlab-cicd-sa \
  --namespace=gitlab-cicd \
  --duration=2h > token.txt

# Update GitLab CI/CD variable
# Go to Settings → CI/CD → Variables → Update KUBE_TOKEN
```

### Automated Renewal (Production)

```yaml
# .gitlab-ci.yml - Add a job to refresh token

refresh-token:
  stage: setup
  image: bitnami/kubectl:latest
  script:
    # This job uses an admin token to create a new token
    # and update the GitLab variable via API
    - NEW_TOKEN=$(kubectl create token gitlab-cicd-sa --namespace=gitlab-cicd --duration=2h)
    - |
      curl --request POST \
        --header "PRIVATE-TOKEN: $GITLAB_API_TOKEN" \
        "https://gitlab.com/api/v4/projects/$CI_PROJECT_ID/variables/KUBE_TOKEN" \
        --form "value=$NEW_TOKEN"
  only:
    - schedules
  schedule:
    - cron: "0 0 * * *"  # Run daily
```

## ✅ Summary: What GitLab Achieves

| GitLab Component | What It Does | How RBAC Helps |
|------------------|--------------|----------------|
| **Runner** | Executes CI/CD jobs | Uses token to authenticate |
| **`kubectl` commands** | Manage cluster resources | Permissions control what's allowed |
| **Helm deployments** | Deploy applications | Permissions control deployment |
| **GitLab Environments** | Track deployments | Same permissions apply |
| **Review Apps** | Create temporary environments | Permissions allow creating resources |

### The Complete Picture

```
GitLab Repository (.gitlab-ci.yml)
        ↓
GitLab Runner
        ↓
Set up kubectl with KUBE_TOKEN
        ↓
kubectl apply -f deployment.yaml
        ↓
Kubernetes API Server
        ↓
Validates Token → Checks RBAC → Allows/Denies
        ↓
Kubernetes Cluster
        ↓
Pod/Deployment/Job Created
        ↓
Application Running!
```

## ⚠️ Important Considerations

| Consideration | Implication |
|---------------|-------------|
| **Token Expiration (2 hours)** | Tokens need regular renewal |
| **Self-Signed Certificate** | Use `--insecure-skip-tls-verify=true` or proper CA cert |
| **Least Privilege** | Only grant what's necessary |
| **Namespace Restriction** | Token works in `gitlab-cicd` namespace with ClusterRole |
| **Security** | Store tokens securely in GitLab CI/CD variables |
