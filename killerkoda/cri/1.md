## 🎯 Scenario Overview

**Context:** You are preparing a Kubernetes node to support Docker-based workloads using **cri-dockerd** as the container runtime interface. Docker is already installed, but the CRI adapter is not yet configured.

**Objective:**
1. Install `cri-dockerd` from the provided `.deb` package
2. Enable and start the `cri-docker` service
3. Configure persistent kernel networking parameters

---

## 🧠 What is cri-dockerd?

**cri-dockerd** is an adapter that provides a **CRI (Container Runtime Interface)** compatible interface for Docker Engine.

### Why is it needed?
- **Kubernetes v1.24+** removed built-in Docker support (deprecated `dockershim`)
- `cri-dockerd` acts as a **bridge** between Kubernetes and Docker
- Allows you to continue using Docker as the container runtime

### Architecture Flow

```
Kubernetes Control Plane
        ↓
    kubelet
        ↓
CRI (Container Runtime Interface)
        ↓
    cri-dockerd ← Bridge/Adapter
        ↓
Docker Engine (containerd + runc)
        ↓
   Containers
```

### Why Use cri-dockerd?

| Reason | Benefit |
|--------|---------|
| **Legacy compatibility** | Continue using Docker in existing environments |
| **Familiar tooling** | Keep using Docker CLI and workflows |
| **Gradual migration** | Transition to containerd at your own pace |
| **Feature parity** | Maintain Docker-specific features during migration |

## ⚙️ Step-by-Step Solution

### Step 1: Verify the Package Exists

```bash
ls -lh ~/cri-dockerd.deb
```

### Step 2: Install the Package

```bash
sudo dpkg -i ~/cri-dockerd.deb
```

**If there are dependency issues:**
```bash
sudo apt-get install -f -y
```

### Step 3: Verify Installation

```bash
which cri-dockerd
cri-dockerd --version
```

### Step 4: Enable and Start Services

Enable the services to start automatically on boot:
```bash
sudo systemctl enable cri-docker.service
sudo systemctl enable cri-docker.socket
```

Start the services:
```bash
sudo systemctl start cri-docker.service
sudo systemctl start cri-docker.socket
```

### Step 5: Verify Services are Running

```bash
sudo systemctl status cri-docker.service
sudo systemctl status cri-docker.socket
sudo systemctl is-active cri-docker.socket
```

### Step 6: Configure Kernel Networking Parameters

Create a persistent sysctl configuration file for Kubernetes networking:

```bash
sudo tee /etc/sysctl.d/99-kubernetes-cri.conf <<EOF
net.bridge.bridge-nf-call-iptables = 1
net.ipv6.conf.all.forwarding = 1
net.ipv4.ip_forward = 1
net.netfilter.nf_conntrack_max = 131072
EOF
```

**What each parameter does:**

| Parameter | Value | Purpose |
|-----------|-------|---------|
| `net.bridge.bridge-nf-call-iptables` | `1` | Allows iptables to see bridged traffic (required for Kubernetes networking) |
| `net.ipv6.conf.all.forwarding` | `1` | Enables IPv6 packet forwarding |
| `net.ipv4.ip_forward` | `1` | Enables IPv4 packet forwarding (required for pod-to-pod communication) |
| `net.netfilter.nf_conntrack_max` | `131072` | Increases connection tracking table size (for high-load clusters) |

### Step 7: Apply the Kernel Parameters

Apply immediately without reboot:

```bash
sudo sysctl --system
```

Or apply the specific file:
```bash
sudo sysctl -p /etc/sysctl.d/99-kubernetes-cri.conf
```

### Step 8: Verify All Parameters

```bash
sysctl net.bridge.bridge-nf-call-iptables
sysctl net.ipv6.conf.all.forwarding
sysctl net.ipv4.ip_forward
sysctl net.netfilter.nf_conntrack_max
```

**Expected output:**
```
net.bridge.bridge-nf-call-iptables = 1
net.ipv6.conf.all.forwarding = 1
net.ipv4.ip_forward = 1
net.netfilter.nf_conntrack_max = 131072
```

### Step 9: Verify Persistence

Confirm the configuration file exists and will persist after reboot:

```bash
cat /etc/sysctl.d/99-kubernetes-cri.conf
```

### Step 10: Test the cri-dockerd Socket

Verify the CRI socket is accessible:

```bash
sudo ls -la /run/cri-dockerd.sock
```

## 🔍 Troubleshooting

| Problem | Solution |
|---------|----------|
| **Installation dependency errors** | Run `sudo apt-get install -f -y` |
| **Service fails to start** | Check logs: `sudo journalctl -u cri-docker.service` |
| **Socket not found** | Ensure service is running: `sudo systemctl status cri-docker.socket` |
| **sysctl parameter not applying** | Check file syntax: `cat /etc/sysctl.d/99-kubernetes-cri.conf` |
| **Parameter reverts after reboot** | Ensure file is in `/etc/sysctl.d/` directory |
| **Permission denied** | Use `sudo` for all commands |

## 💡 Key Takeaways

1. **cri-dockerd** is the bridge between Kubernetes and Docker after v1.24
2. Always **enable both** the service and socket
3. Kernel networking parameters **must be persistent** via `sysctl.d`
4. `bridge-nf-call-iptables` is **critical** for Kubernetes networking
5. `ip_forward` must be enabled for **pod-to-pod communication**
6. `nf_conntrack_max` should be increased for **production clusters**
