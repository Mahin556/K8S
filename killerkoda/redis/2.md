Your provided "Solution" is **almost there**, but it has one critical flaw: **The `CONFIG GET` commands are Redis CLI commands, not Linux shell commands.** 

If you follow the steps exactly as written, after running `k exec -it redis-pod -- sh`, you will be at a `/ #` shell prompt. If you type `CONFIG GET maxmemory`, you will get an error like `sh: CONFIG: not found`.

You **must** first open the Redis CLI client *inside* the pod shell.

---

### ✅ Correct Method 1: Step-by-Step (as you intended)

1. **Get a shell inside the pod**:
   ```bash
   kubectl exec -it redis-pod -- sh
   ```
   *(You will see the shell prompt, e.g., `/ #`).*

2. **Open the Redis CLI** (while inside the pod):
   ```bash
   redis-cli
   ```
   *(You will now see the Redis prompt, e.g., `127.0.0.1:6379>`).*

3. **Now** run your Redis `CONFIG GET` commands:
   ```bash
   CONFIG GET maxmemory
   CONFIG GET maxmemory-policy
   ```

4. **To exit**: type `exit` to leave `redis-cli`, then type `exit` again to leave the pod shell.

---

### 🔥 Correct Method 2: One-Liners (Easiest / Best Practice)

You don't actually need to spawn an interactive shell at all. You can execute the `redis-cli` directly from your local terminal:

```bash
# Get maxmemory
kubectl exec -it redis-pod -- redis-cli CONFIG GET maxmemory

# Get maxmemory-policy
kubectl exec -it redis-pod -- redis-cli CONFIG GET maxmemory-policy
```

**Expected output:**
```text
1) "maxmemory"
2) "256mb"           # (or whatever you set it to)

1) "maxmemory-policy"
2) "allkeys-lru"     # (or whatever you set it to)
```

---

### 🧠 Why the `--` is important in `kubectl exec`

The double dash `--` tells `kubectl` to stop parsing its own flags and treat everything after as the command to run inside the container. 
For example: `kubectl exec -it redis-pod -- redis-cli CONFIG GET maxmemory`
- `redis-cli` = the command to run.
- `CONFIG GET maxmemory` = the arguments passed to that command.
