## 🧠 Conceptual Summary

### What is a ConfigMap?

A **ConfigMap** is a Kubernetes resource that stores configuration data in key-value pairs. It allows you to decouple configuration from container images.

### What is an InitContainer?

An **InitContainer** is a special container that runs **before** the main application container starts. It's used for setup tasks like:

- ✅ Copying configuration files
- ✅ Database migrations
- ✅ Pre-populating data
- ✅ Waiting for dependencies

### The Flow

## 📊 ConfigMaps Explained

### Creating ConfigMaps

```bash
# From a file
kubectl create configmap my-config --from-file=/path/to/file

# From literal values
kubectl create configmap my-config --from-literal=key=value

# From directory
kubectl create configmap my-config --from-file=/path/to/dir/
```

### Using ConfigMaps in Pods

```yaml
volumes:
- name: config-volume
  configMap:
    name: strawhat-cm
```

### ConfigMap Mount Path

```
ConfigMap → Mounted at /config → File: /config/index.html
```

## 🔧 InitContainers Explained

### Regular InitContainer vs Sidecar InitContainer

| Type | Regular InitContainer | Sidecar InitContainer |
|------|----------------------|----------------------|
| **Purpose** | One-time setup | Continuous service |
| **restartPolicy** | Not specified (default Never) | Always |
| **Lifecycle** | Runs once, exits | Continues running |
| **Use Case** | Copy files, migrations | Logging, monitoring |

### InitContainer Flow

```
Pod Creation
        ↓
    volumes Created
        ↓
    InitContainer Runs
        ↓
    InitContainer Exits (0)
        ↓
    Main Container Starts
        ↓
    Pod Running
```

## 📋 Step-by-Step Solution

### Step 1: Create the Namespace

```bash
kubectl create namespace one-piece
```

**Expected Output:**
```
namespace/one-piece created
```

### Step 2: Create ConfigMap from File

```bash
kubectl create configmap strawhat-cm \
  --from-file=/one-piece/index.html \
  -n one-piece
```

**Expected Output:**
```
configmap/strawhat-cm created
```

### Step 3: Create the Deployment

```bash
cat <<EOF | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: strawhat-deploy
  namespace: one-piece
spec:
  replicas: 1
  selector:
    matchLabels:
      app: strawhat
  template:
    metadata:
      labels:
        app: strawhat
    spec:
      initContainers:
      - name: init-copy
        image: public.ecr.aws/docker/library/busybox:latest
        command: ['sh', '-c', 'cp /config/index.html /usr/share/nginx/html/']
        volumeMounts:
        - name: config-volume
          mountPath: /config
        - name: html-volume
          mountPath: /usr/share/nginx/html
      containers:
      - name: strawhat-nginx
        image: public.ecr.aws/nginx/nginx:latest
        ports:
        - containerPort: 80
        volumeMounts:
        - name: html-volume
          mountPath: /usr/share/nginx/html
      volumes:
      - name: config-volume
        configMap:
          name: strawhat-cm
      - name: html-volume
        emptyDir: {}
EOF
```

**Expected Output:**
```
deployment.apps/strawhat-deploy created
```

### Step 4: Create the NodePort Service

```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Service
metadata:
  name: strawhat-svc
  namespace: one-piece
spec:
  type: NodePort
  selector:
    app: strawhat
  ports:
  - port: 80
    targetPort: 80
    nodePort: 32100
EOF
```

**Expected Output:**
```
service/strawhat-svc created
```

### Step 5: Wait for Deployment

```bash
kubectl rollout status deployment/strawhat-deploy -n one-piece
```

**Expected Output:**
```
deployment "strawhat-deploy" successfully rolled out
```

### Step 6: Verify

```bash
curl localhost:32100
```

**Expected Output:**
```
<!DOCTYPE html>
<html>
<head>
    <title>Strawhat Pirates</title>
</head>
<body>
    <h1>🏴‍☠️ Strawhat Pirates Crew</h1>
    ...
</body>
</html>
```

## 🔍 Deep Dive: Understanding the Configuration

### Complete YAML Breakdown

```yaml
apiVersion: apps/v1
# ↑ API group and version for Deployment

kind: Deployment
# ↑ Resource type

metadata:
  name: strawhat-deploy
  # ↑ Deployment name

  namespace: one-piece
  # ↑ Namespace

spec:
  # ↑ Specification

  replicas: 1
  # ↑ Number of Pod replicas

  selector:
    matchLabels:
      app: strawhat
  # ↑ Labels used to select Pods

  template:
    # ↑ Pod template

    metadata:
      labels:
        app: strawhat
      # ↑ Labels for Pods

    spec:
      # ↑ Pod specification

      initContainers:
      # 🔥 InitContainer section

      - name: init-copy
        # ↑ InitContainer name

        image: public.ecr.aws/docker/library/busybox:latest
        # ↑ Busybox image for copying files

        command: ['sh', '-c', 'cp /config/index.html /usr/share/nginx/html/']
        # ↑ Command to copy HTML file

        volumeMounts:
        - name: config-volume
          mountPath: /config
          # ↑ Mounts ConfigMap at /config

        - name: html-volume
          mountPath: /usr/share/nginx/html
          # ↑ Mounts emptyDir at /usr/share/nginx/html

      containers:
      # 🔥 Main container

      - name: strawhat-nginx
        # ↑ Nginx container

        image: public.ecr.aws/nginx/nginx:latest
        # ↑ Nginx image

        ports:
        - containerPort: 80
        # ↑ Nginx default port

        volumeMounts:
        - name: html-volume
          mountPath: /usr/share/nginx/html
          # ↑ Mounts the same emptyDir as initContainer

      volumes:
      # 🔥 Volumes section

      - name: config-volume
        configMap:
          name: strawhat-cm
        # ↑ ConfigMap volume (read-only)

      - name: html-volume
        emptyDir: {}
        # ↑ EmptyDir volume (shared between init and main)
```

### Key Fields Explained

| Field | Value | Purpose |
|-------|-------|---------|
| **`initContainers`** | `init-copy` | Runs before main container |
| **`command`** | `cp /config/index.html /usr/share/nginx/html/` | Copies HTML to Nginx directory |
| **`volumeMounts`** | `config-volume`, `html-volume` | Mounts ConfigMap and emptyDir |
| **`emptyDir`** | `{}` | Ephemeral storage for HTML file |
| **`nodePort`** | `32100` | External port for NodePort Service |

## 🛠️ Troubleshooting Common Issues

| Issue | Diagnosis | Solution |
|-------|-----------|----------|
| **InitContainer failed** | Check logs | `kubectl logs -c init-copy` |
| **HTML not served** | File not copied | Check mount paths |
| **Nginx not starting** | Port conflict | Check container port 80 |
| **Service not accessible** | Wrong nodePort | Ensure nodePort: 32100 |
| **ConfigMap not found** | Wrong namespace | Check `-n one-piece` |
| **Selector mismatch** | App label mismatch | Ensure `app: strawhat` |
| **EmptyDir not shared** | Wrong volume name | Both use `html-volume` |

### Debugging Commands

```bash
# Check init container logs
```

## 💡 Real-World Use Cases

### 1. Web Applications with Custom Content

```yaml
initContainers:
- name: copy-content
  image: busybox:latest
  command: ['sh', '-c', 'cp /config/* /usr/share/nginx/html/']
  volumeMounts:
  - name: config
    mountPath: /config
  - name: html
    mountPath: /usr/share/nginx/html
```

### 2. Database Migrations

```yaml
initContainers:
- name: db-migration
  image: myapp/migration:latest
  env:
  - name: DATABASE_URL
    value: "postgres://..."
  command: ["node", "migrate.js"]
```

### 3. Fetching Secrets/Configs

```yaml
initContainers:
- name: fetch-config
  image: curlimages/curl:latest
  command: ['sh', '-c', 'curl -o /config/app.conf http://config-server/app.conf']
  volumeMounts:
  - name: config
    mountPath: /config
```

### 4. Waiting for Dependencies

```yaml
initContainers:
- name: wait-for-db
  image: busybox:latest
  command: ['sh', '-c', 'until nslookup postgres; do sleep 2; done']
```

## 💡 Best Practices & Key Takeaways

### Best Practices

| Practice | Why |
|----------|-----|
| **Use ConfigMap for config** | Decouple config from images |
| **Use InitContainer for setup** | Keep main container clean |
| **Use emptyDir for sharing** | Share data between containers |
| **Test init container separately** | Verify before deployment |
| **Set resource limits** | Prevent resource exhaustion |
| **Use meaningful names** | Easy identification |
| **Monitor init container logs** | Debug setup issues |

### Key Takeaways

| Concept | Key Insight |
|---------|-------------|
| **ConfigMap** | Stores configuration data |
| **InitContainer** | Runs before main container |
| **emptyDir** | Shared volume between containers |
| **NodePort** | Exposes service on external port |
| **Volume Mounts** | Enable data sharing |

### CKA Exam Tips

📌 **Remember:** InitContainers run **before** main containers  
📌 **Remember:** InitContainers must **exit successfully** for main container to start  
📌 **Remember:** ConfigMaps are mounted as files/directories  
📌 **Remember:** `emptyDir` is ephemeral storage  
📌 **Remember:** NodePort exposes service on specific port  
📌 **Remember:** Service selector must match Pod labels
