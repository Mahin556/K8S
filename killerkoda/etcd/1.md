## 📦 ETCD Backup and Restore on Controlplane Node

This guide provides the exact commands to take a snapshot of the etcd cluster running in the `kube-system` namespace, store it, and then restore it to a specified data directory (`/root/default.etcd`), while capturing the restore output.

---

### ✅ Prerequisites

- You are logged into the **controlplane** node (via `ssh controlplane` if needed).
- The etcd cluster is running as a static Pod (managed by kubeadm) with certificates available at `/etc/kubernetes/pki/etcd/`.
- `etcdctl` (v3 API) is installed on the node (it usually is, as part of `kubernetes-cni` or `etcd-client` packages).

---

### 1️⃣ Backup ETCD

Use `etcdctl` with the proper certificates to take a snapshot and save it to `/opt/cluster_backup.db`.

```bash
ETCDCTL_API=3 etcdctl \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  snapshot save /opt/cluster_backup.db
```

**Explanation**:
- `ETCDCTL_API=3` ensures we use the v3 API (required for snapshot commands).
- `--endpoints`: etcd listens on localhost:2379 by default.
- The certificate paths are the default locations for kubeadm‑deployed clusters.

---

### 2️⃣ Restore ETCD to a New Data Directory

We will restore the snapshot to `/root/default.etcd` as specified. The restore command will create this directory (if it doesn’t exist) and populate it with the etcd data.

```bash
ETCDCTL_API=3 etcdctl snapshot restore /opt/cluster_backup.db \
  --data-dir /root/default.etcd 2>&1 | tee restore.txt
```

**Explanation**:
- `snapshot restore` reads the backup file and writes the data to `--data-dir`.
- `2>&1` redirects stderr to stdout so we capture all output.
- `tee restore.txt` writes the console output to `restore.txt` while also displaying it on the terminal.

> **Note**: If the directory already exists, you may need to remove it first (`rm -rf /root/default.etcd`) or choose a different location. The instruction specifically asks to use `/root/default.etcd`.

---

### 3️⃣ Verify the Restore (Optional)

Check that the restore completed successfully and that the data directory was created:

```bash
ls -l /root/default.etcd
```

You should see etcd data files inside.

---

### 🔍 Important Notes

- **Certificates**: The backup and restore commands use the **same certificates** as the running etcd cluster. They are needed for authentication to the etcd endpoint, even for snapshot restore.
- **Restore to a Different Dir**: We restored to `/root/default.etcd`, which is **not** the default data directory of the running etcd (which is usually `/var/lib/etcd`). This is safe – it won’t interfere with the live cluster. To actually use the restored data, you would need to stop etcd, replace the data dir, and restart etcd. The exercise only requires the restore command and capturing the output.
- **Output Capture**: The `restore.txt` file will contain any output or errors from the restore process. If the restore succeeds, it typically prints nothing or a success message.

---

### 📋 Summary of Commands

```bash
# Backup
ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 --cacert=/etc/kubernetes/pki/etcd/ca.crt --cert=/etc/kubernetes/pki/etcd/server.crt --key=/etc/kubernetes/pki/etcd/server.key snapshot save /opt/cluster_backup.db

# Restore
ETCDCTL_API=3 etcdctl snapshot restore /opt/cluster_backup.db --data-dir /root/default.etcd 2>&1 | tee restore.txt
```

Your backup file is now at `/opt/cluster_backup.db`, and the restore output is saved in `restore.txt`.
