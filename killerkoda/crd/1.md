## 🧠 Conceptual Summary

### What are Custom Resource Definitions (CRDs)?

**Custom Resource Definitions (CRDs)** extend the Kubernetes API by allowing you to define your own resource types. They enable Kubernetes to handle custom objects that represent your application's domain-specific concepts.

### CRDs vs Built-in Resources

| Aspect | Built-in Resources | Custom Resources (CRDs) |
|--------|-------------------|-------------------------|
| **Examples** | Pods, Services, Deployments | Certificates, Issuers, Challenges |
| **Definition** | Built into Kubernetes | Defined by users/operators |
| **API Group** | `v1`, `apps/v1`, etc. | Custom groups (e.g., `cert-manager.io`) |
| **Controller** | Kubernetes core controllers | User-defined controllers (e.g., cert-manager) |
| **Storage** | etcd | etcd |

### How Operators Use CRDs

```
│                                    │                                        │

│   ┌─────────────────────────────────────────────────────────────────────┐   │
```

## 📊 cert-manager CRDs Overview

### cert-manager CRDs

| CRD Name | API Group | Purpose |
|----------|-----------|---------|
| **`certificates.cert-manager.io`** | `cert-manager.io` | Defines TLS certificates |
| **`certificaterequests.cert-manager.io`** | `cert-manager.io` | Requests for certificates |
| **`issuers.cert-manager.io`** | `cert-manager.io` | Certificate issuers (namespace-scoped) |
| **`clusterissuers.cert-manager.io`** | `cert-manager.io` | Certificate issuers (cluster-scoped) |
| **`challenges.acme.cert-manager.io`** | `acme.cert-manager.io` | ACME challenges for DNS/HTTP validation |
| **`orders.acme.cert-manager.io`** | `acme.cert-manager.io` | ACME orders for certificate issuance |

### Certificate CRD Structure

```yaml
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: example-cert
  namespace: default
spec:
  secretName: example-cert-tls
  duration: 8760h
  renewBefore: 360h
  subject:
    organizations:
    - My Org
    countries:
    - US
  commonName: example.com
  dnsNames:
  - example.com
  - www.example.com
  issuerRef:
    name: letsencrypt-prod
    kind: Issuer
    group: cert-manager.io
```

## 🔍 Deep Dive: Understanding kubectl explain

### What is kubectl explain?

`kubectl explain` is a command that displays documentation for Kubernetes resources and fields. It's like a built-in `man` page for Kubernetes API objects.

### Basic Usage

```bash
# Explain a resource
kubectl explain <resource>

# Explain a specific field
kubectl explain <resource>.<field>

# Explain nested fields
kubectl explain <resource>.<field>.<subfield>

# Show all fields recursively
kubectl explain <resource> --recursive
```

### Examples

```bash
# Explain Pods
kubectl explain pod

# Explain Pod spec
kubectl explain pod.spec

# Explain Pod containers
kubectl explain pod.spec.containers

# Explain Deployment
kubectl explain deployment

# Explain Deployment spec
kubectl explain deployment.spec

# Explain Service
kubectl explain service

# Explain Service spec
kubectl explain service.spec

# Explain Certificate CRD
kubectl explain certificate

# Explain Certificate subject
kubectl explain certificate.spec.subject

# Recursive output
kubectl explain certificate.spec --recursive
```

### Output Format

```
KIND:     <Kind Name>
VERSION:  <API Version>

RESOURCE: <field> <type>

DESCRIPTION:
     <Description of the field>

FIELDS:
   <field1>	<type> - required
        <description>

   <field2>	<type> - optional
        <description>
```

## 🛠️ Troubleshooting Common Issues

| Issue | Diagnosis | Solution |
|-------|-----------|----------|
| **CRDs not found** | cert-manager not installed | Check: `kubectl get pods -n cert-manager` |
| **No output in resources.txt** | Grep filter incorrect | Ensure `grep -i cert-manager` |
| **subject.yaml empty** | Field path wrong | Verify `certificate.spec.subject` exists |
| **kubectl explain fails** | Wrong resource name | Check CRD name: `kubectl get crd` |
| **Permission denied** | File write permissions | Use `sudo` or check directory |

### Debugging Commands

```bash
# Check if CRDs exist
kubectl get crd | grep cert-manager

# Check cert-manager installation
kubectl get pods -n cert-manager

# Check CRD details
kubectl get crd certificates.cert-manager.io -o yaml

# Check kubectl explain version
kubectl explain --help

# Test kubectl explain
kubectl explain certificate

# Check file permissions
ls -la /root/resources.txt
ls -la /root/subject.yaml

# Check file content
head -20 /root/resources.txt
head -20 /root/subject.yaml
```

```yaml
  name: example-cert

  - example.com
  - www.example.com

    organizations:
    - My Organization
```

### 2. Prometheus CRDs

```yaml
# ServiceMonitor CRD
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: app-monitor
spec:
  selector:
    matchLabels:
      app: myapp
  endpoints:
  - port: metrics
    interval: 30s
```

### 3. Ingress Controllers (Nginx)

```yaml
# IngressClass CRD
apiVersion: networking.k8s.io/v1
kind: IngressClass

  name: nginx

  controller: k8s.io/ingress-nginx
```

```yaml

  name: reviews-route

  hosts:
  - reviews

  - route:
```
