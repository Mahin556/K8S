## 🧠 Conceptual Summary

### What are Static Pods?

**Static pods** are special types of pods that are managed **directly by the kubelet** on a specific node, rather than by the Kubernetes API server.

### Key Characteristics

| Characteristic | Description |
|----------------|-------------|
| **Managed by** | kubelet (not API server) |
| **Defined by** | YAML files in static pod directory |
| **Pod Name** | Original name + node name suffix |
| **Deletion** | Remove manifest file |
| **Rescheduling** | Tied to specific node |
| **API Visibility** | Read-only mirror pod |

### Why Static Pods?

✅ **Control Plane Components** → kube-apiserver, etcd, controller-manager run as static pods  
✅ **Node-Specific Services** → Run services on specific nodes  
✅ **Self-Healing** → kubelet automatically restarts them if they fail  
✅ **Bootstrap** → Essential services before cluster is operational

## 🏗️ Static Pods vs Regular Pods

### Comparison Table

| Feature | Regular Pod | Static Pod |
|---------|-------------|------------|
| **Managed by** | Kubernetes API Server | kubelet |
| **Created via** | `kubectl` / API calls | Manifest file in directory |
| **Pod Name** | As specified | Original name + node name suffix |
| **Scheduling** | Scheduler assigns node | Runs on node with manifest |
| **Deletion** | `kubectl delete pod` | Remove manifest file |
| **Rescheduling** | Can be rescheduled | Tied to specific node |
| **API visibility** | Full control | Read-only mirror pod |
| **Storage** | etcd | Node filesystem |

### Visual Comparison

```
Regular Pod Creation Flow:
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Regular Pod                                              │
│                                                                             │
│   User → kubectl → API Server → Scheduler → kubelet → Pod                │
│                        ↓                                                    │
│                    etcd (stores desired state)                            │
│                                                                             │
│   ✅ API Server controls the pod                                           │
│   ✅ Can be rescheduled                                                    │
│   ✅ Can be deleted via kubectl                                           │
└─────────────────────────────────────────────────────────────────────────────┘

Static Pod Creation Flow:
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Static Pod                                               │
│                                                                             │
│   User → Create YAML in /etc/kubernetes/manifests/                       │
│                        ↓                                                    │
│              kubelet (watches directory)                                  │
│                        ↓                                                    │
│              Creates Pod directly                                          │
│                        ↓                                                    │
│              Mirror pod appears in API (read-only)                        │
│                                                                             │
│   ✅ kubelet controls the pod                                              │
│   ❌ Cannot be rescheduled                                                 │
│   ❌ Cannot be deleted via kubectl                                        │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 📋 Step-by-Step Solution

### Step 1: Verify the Namespace

```bash
kubectl get ns mcp-tool
```

**Expected Output:**
```
NAME       STATUS   AGE
mcp-tool   Active   5m
```

### Step 2: Find the Static Pod Directory

```bash
grep staticPodPath /var/lib/kubelet/config.yaml
```

**Expected Output:**
```
staticPodPath: /etc/kubernetes/manifests
```

### Step 3: Create the Static Pod Manifest

```bash
cat > /etc/kubernetes/manifests/mcp-grafana.yaml <<'EOF'
apiVersion: v1
kind: Pod
metadata:
  name: mcp-grafana
  namespace: mcp-tool
  labels:
    app: mcp-grafana
    tool: grafana
    workload: monitoring
spec:
  containers:
  - name: grafana
    image: mcp/grafana:latest
    command: ["sh", "-c"]
    args: ["while true; do sleep 3600; done"]
EOF
```

### Step 4: Verify the Static Pod

Wait a few seconds for kubelet to detect and create the pod:

```bash
# Check if pod is running
kubectl get pods -n mcp-tool
```

**Expected Output:**
```
NAME                         READY   STATUS    RESTARTS   AGE
mcp-grafana-controlplane     1/1     Running   0          30s
```

> **Note:** kubelet appends the node name to the pod name.

### Step 5: Verify Labels

```bash
kubectl get pod -n mcp-tool -l app=mcp-grafana --show-labels
```

**Expected Output:**
```
NAME                         READY   STATUS    RESTARTS   AGE   LABELS
mcp-grafana-controlplane     1/1     Running   0          1m    app=mcp-grafana,tool=grafana,workload=monitoring
```

### Step 6: Check Pod Details

```bash
kubectl describe pod -n mcp-tool mcp-grafana-controlplane
```

**Expected Output:**
```
Name:         mcp-grafana-controlplane
Namespace:    mcp-tool
Labels:       app=mcp-grafana
              tool=grafana
              workload=monitoring
Annotations:  <none>

Containers:
  grafana:
    Container ID:   containerd://...
    Image:          mcp/grafana:latest
    Image ID:       ...
    Port:           <none>
    Host Port:      <none>
    Command:
      sh
      -c
    Args:
      while true; do sleep 3600; done
    State:          Running
```

### Step 7: Verify Static Pod File Exists

```bash
ls -la /etc/kubernetes/manifests/mcp-grafana.yaml
```

**Expected Output:**
```
-rw-r--r-- 1 root root 236 2025-01-15 10:30 /etc/kubernetes/manifests/mcp-grafana.yaml
```

```bash
kubectl get pod -n mcp-tool mcp-grafana-controlplane -o yaml | grep -A 5 "ownerReferences"
```

**Expected Output:**
```

  name: controlplane
  uid: ...
```

This confirms it's a mirror pod owned by the node.

## 🔍 Deep Dive: Understanding the Configuration

### Complete YAML Breakdown

```yaml
apiVersion: v1
# ↑ API version for Pod

kind: Pod
# ↑ Resource type

metadata:
  name: mcp-grafana
  # ↑ Pod name (kubelet appends node name)

  namespace: mcp-tool
  # ↑ Namespace where pod is created

  labels:
    app: mcp-grafana
    tool: grafana
    workload: monitoring
  # ↑ Labels for identification

spec:
  # ↑ Pod specification

  containers:
  - name: grafana
    # ↑ Container name

    image: mcp/grafana:latest
    # ↑ Container image

    command: ["sh", "-c"]
    # ↑ Command to run

    args: ["while true; do sleep 3600; done"]
    # ↑ Arguments (keeps container running)
```

### Why `while true; do sleep 3600; done`?

This is a common pattern to keep a container running indefinitely:

| Command | Purpose |
|---------|---------|
| `sleep 3600` | Sleep for 1 hour |
| `while true; do sleep 3600; done` | Infinite loop |

**Alternative:**
```yaml
command: ["sleep", "infinity"]
```

### Static Pod File Location

The static pod directory is configured in `/var/lib/kubelet/config.yaml`:

```yaml
staticPodPath: /etc/kubernetes/manifests
```

kubelet watches this directory and:
- Creates pods from new YAML files
- Updates pods from modified YAML files
- Deletes pods from removed YAML files

## 🛠️ Troubleshooting Common Issues

| Issue | Diagnosis | Solution |
|-------|-----------|----------|
| **Pod not created** | Wrong static pod directory | Check `grep staticPodPath /var/lib/kubelet/config.yaml` |
| **Pod stuck Pending** | Image pull error | Check image name: `mcp/grafana:latest` |
| **Pod not in API** | kubelet not syncing | Wait 10-30 seconds for kubelet to detect |
| **Wrong pod name** | Node name not appended | Check node name: `kubectl get nodes` |
| **Manifest not found** | Wrong file path | Verify file is in `/etc/kubernetes/manifests/` |
| **Labels missing** | YAML syntax error | Check YAML indentation |
| **Container not running** | Wrong command | Check `command` and `args` |
| **Cannot delete via kubectl** | Static pod behavior | Remove manifest file, kubelet will delete |

### Debugging Commands

```bash
# Check kubelet logs
journalctl -u kubelet -f

# Check kubelet config
cat /var/lib/kubelet/config.yaml | grep staticPodPath

# Check manifest file
cat /etc/kubernetes/manifests/mcp-grafana.yaml

# Check pod events
kubectl describe pod -n mcp-tool mcp-grafana-controlplane

# Check pod logs
kubectl logs -n mcp-tool mcp-grafana-controlplane -c grafana

# Check if pod is mirror
kubectl get pod -n mcp-tool mcp-grafana-controlplane -o yaml | grep -A 5 ownerReferences

# Check all pods in namespace
kubectl get pods -n mcp-tool

# Delete static pod (remove manifest)
sudo rm /etc/kubernetes/manifests/mcp-grafana.yaml
```

## 🔍 Mirror Pods Explained

### What is a Mirror Pod?

A **mirror pod** is a read-only representation of a static pod in the Kubernetes API.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Mirror Pod Architecture                                  │
│                                                                             │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │                    Node (controlplane)                              │   │
│   │                                                                     │   │
│   │   ┌─────────────────────────────────────────────────────────────┐   │   │
│   │   │                    Static Pod Manifest                       │   │   │
│   │   │                    /etc/kubernetes/manifests/               │   │   │
│   │   └──────────────────────────────┬──────────────────────────────┘   │   │
│   │                                  │                                   │   │
│   │                                  ▼                                   │   │
│   │   ┌─────────────────────────────────────────────────────────────┐   │   │
│   │   │                    kubelet                                   │   │   │
│   │   └──────────────────────────────┬──────────────────────────────┘   │   │
│   │                                  │                                   │   │
│   │                                  ▼                                   │   │
│   │   ┌─────────────────────────────────────────────────────────────┐   │   │
│   │   │                    Static Pod                                │   │   │
│   │   │                    (Running on node)                        │   │   │
│   │   └─────────────────────────────────────────────────────────────┘   │   │
│   │                                  │                                   │   │
│   │                                  ▼                                   │   │
│   │   ┌─────────────────────────────────────────────────────────────┐   │   │
│   │   │                    Mirror Pod                                │   │   │
│   │   │                    (Read-only in API Server)               │   │   │
│   │   │                    Owner: Node                              │   │   │
│   │   └─────────────────────────────────────────────────────────────┘   │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   ✅ Mirror pod allows kubectl to see the static pod                     │
│   ❌ Mirror pod cannot be modified or deleted via API                    │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Mirror Pod Characteristics

| Feature | Description |
|---------|-------------|
| **Name** | `<pod-name>-<node-name>` |
| **Owner** | Node resource |
| **Read-only** | Cannot be modified/deleted via API |
| **Synchronization** | Updates when static pod changes |
| **Deletion** | Removed when static pod manifest is deleted |

### Checking Mirror Pod

```bash
# Check owner reference
kubectl get pod mcp-grafana-controlplane -n mcp-tool -o yaml | grep -A 5 ownerReferences

# Output:
ownerReferences:
- apiVersion: v1
  controller: true
  kind: Node
  name: controlplane
  uid: xxxxx
```

## 💡 Best Practices & Key Takeaways

### Best Practices

| Practice | Why |
|----------|-----|
| **Use descriptive filenames** | Easy to identify components |
| **Include health checks** | Add liveness/readiness probes |
| **Set resource limits** | Prevent resource exhaustion |

| Concept | Key Insight |
|---------|-------------|
| **Static Pod** | Managed by kubelet, not API server |
| **Manifest Directory** | `/etc/kubernetes/manifests` (default) |

```yaml

  name: my-static-pod
```
