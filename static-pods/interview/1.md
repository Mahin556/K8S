## What is a Static Pod? The four control plane services (apiserver, etcd, scheduler, controller-manager) run as pods. But who creates and maintains these pods since the API server itself is one of them?

### The Answer: Static Pod Concept

**What is a Static Pod?**
- A static pod is managed directly by **kubelet** on a specific node
- It is NOT managed by the API server, deployment, or replica set
- kubelet watches a specific directory on the node for pod manifest files

**Static Pod Manifest Path:**
```bash
# Default path (configurable in kubelet config)
/etc/kubernetes/manifests/
```

Files in this directory:
```
/etc/kubernetes/manifests/
├── etcd.yaml
├── kube-apiserver.yaml
├── kube-controller-manager.yaml
└── kube-scheduler.yaml
```

**How Static Pods Work:**
1. kubelet watches the manifest directory
2. Any YAML file placed in this directory is automatically created as a pod
3. kubelet ensures the pod keeps running
4. If the pod is deleted, kubelet recreates it automatically
5. If the YAML file is removed, the pod is deleted

**Key Differences: Static Pod vs Regular Pod:**

| Feature | Static Pod | Regular Pod |
|---------|------------|-------------|
| **Created by** | kubelet directly | API server |
| **Managed by** | kubelet | Controller (Deployment, ReplicaSet) |
| **Manifest location** | Node's local directory | etcd (via API server) |
| **High Availability** | No failover to other nodes | Can be rescheduled on other nodes |
| **Supported kinds** | Only Pod | Pod, Deployment, StatefulSet, etc. |
| **Rolling updates** | Not supported | Supported |
| **Self-healing** | kubelet restarts on same node | Controller reschedules anywhere |

**Why Static Pods for Control Plane?**
- When bootstrapping a cluster, the API server doesn't exist yet
- Static pods allow control plane components to start without depending on the API server
- kubelet can create these pods even before the API server is running
- This is a "chicken and egg" problem solution
