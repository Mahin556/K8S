## What is a Pod Disruption Budget (PDB)?

### Understanding Disruptions First:

| Type | Description | Example |
|------|-------------|---------|
| **Voluntary Disruption** | Planned, intentional | Node drain for maintenance, scaling down, deleting deployment |
| **Involuntary Disruption** | Unplanned, unexpected | Node crash, network issue, hardware failure |

### What PDB Does:
- PDB handles **voluntary disruptions only**
- It does NOT handle involuntary disruptions (node crashes, network issues)

### How It Works:
- You specify the **minimum number of replicas** that must remain available
- Example: You have 5 replicas, PDB says minimum 4 must be available
- Kubernetes will only allow voluntary disruption of 1 pod at a time
- It uses the **eviction API** to ensure the budget is not violated

### Example:
```yaml
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: my-app-pdb
spec:
  minAvailable: 4
  selector:
    matchLabels:
      app: my-app
```

### Key Point:
"If you're using Kubernetes in production, you should definitely have PDBs configured for your critical applications."
