## What is service mesh and why do we need it?

### What is Service Mesh?
A service mesh is used for managing **East-West traffic** (service-to-service communication) within the cluster.

### Key Capabilities of Service Mesh:

| Feature | Description |
|---------|-------------|
| **Mutual TLS (mTLS)** | Secure service-to-service communication |
| **Load Balancing** | Distribute traffic across services |
| **Observability** | Monitor and trace requests |
| **Traceability** | Track requests across services |
| **Authentication & Authorization** | Control access between services |
| **Traffic Routing** | Control how traffic flows |

### Important Interview Tip:
"If you know about service mesh, explain it in detail. If you don't have practical experience, be honest and say: 'In our cluster setup, we didn't need to use service mesh because our service-to-service communication was handled with basic security. I know the theory but haven't implemented it practically.'

**Why?** Because the interviewer will then ask about:
- Sidecar injection
- Envoy proxy
- Disadvantages of service mesh
- Complex configuration details

Don't pretend to know if you haven't worked with it."
