## How does pod networking work in Kubernetes? Brief the architecture.

### The Complete Answer Flow:

**Step 1: CNI (Container Network Interface)**
- Pod networking is entirely dependent on **CNI plugin**
- CNI stands for **Container Network Interface**
- It is a **software-defined networking solution**
- Physical switches cannot be connected to containers because containers are virtual objects
- CNI provides networking in software form, just like physical networking but virtual

**Step 2: Popular CNI Solutions**
- **Calico** - Most recommended for on-premises data centers
- **Flannel** - Deprecated/retired from market
- **Weave** - Deprecated/retired from market
- **Cilium** - eBPF-based, growing in popularity

**Step 3: Calico Properties (Why Calico is preferred)**
- Designed for **Layer 3 networking** (Switching + Routing)
- Based on **BGP Protocol** (Border Gateway Protocol)
- Supports **Network Policy Rules** for internal cluster security
- Can integrate with physical network infrastructure via BGP (especially in Telecom)
