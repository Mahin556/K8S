**Yes, you must follow the exact same hierarchical process (Control Plane → Add-ons → Node Groups) every single time you upgrade to a new Kubernetes minor version.** 

However, there is good news: **You do not have to repeat the artificial "error introduction" or the heavy manual setup.** The demo included breaking things on purpose to teach you how to handle real-world pre-existing errors. In a production environment, you won't be doing that.

Here is the reality of doing it a second time (e.g., upgrading from `1.34` to `1.35`):

### 1. The Core Steps You MUST Repeat (Every Time)
For every minor version jump, this sequence is **non-negotiable**:

1. **Upgrade Control Plane** (Master nodes).
2. **Upgrade Add-ons** (`kube-proxy`, `CoreDNS`, `VPC-CNI`) to versions compatible with the *new* Kubernetes version.
3. **Upgrade Node Groups** (Worker nodes) via Rolling Update.
4. *(Optional)* Update workloads if their API versions are deprecated.

### 2. What You DO NOT Need to Repeat
- **No more "Breaking" steps**: You don't need to manually downgrade `kube-proxy` to create errors (that was just a teaching demo).
- **No major tool re-installation**: `kubectl`, `eksctl`, and AWS CLI are already installed and configured. 
- **Faster verification**: Since there are no artificial errors, the **Upgrade Insights** tab will likely show "Passing" immediately, saving you the 5-10 minutes of fixing things.

### 3. How to Make it Faster (Automation)
You don't have to click through the AWS Console every time. You can use `eksctl` or the AWS CLI to speed this up significantly.

**Upgrade Control Plane via CLI:**
```bash
aws eks update-cluster-version --name product-upgrade-demo --kubernetes-version 1.35
```

**Upgrade Managed Add-ons via CLI:**
```bash
aws eks update-addon --cluster-name product-upgrade-demo --addon-name kube-proxy --addon-version latest
aws eks update-addon --cluster-name product-upgrade-demo --addon-name coredns --addon-version latest
aws eks update-addon --cluster-name product-upgrade-demo --addon-name vpc-cni --addon-version latest
```

**Upgrade Node Groups via CLI:**
```bash
eksctl upgrade nodegroup --cluster=product-upgrade-demo --name=ng-1 --kubernetes-version=1.35
```
*(The `eksctl` command automatically handles the rolling update strategy for zero downtime).*

---

### ⚠️ The "No Skip" Rule Still Applies
Just like before, **you cannot skip versions**. 

- If you are on `1.34` and want to get to `1.36`, you **must**:
  1. Upgrade `1.34` → `1.35` (wait for everything to stabilize).
  2. Then upgrade `1.35` → `1.36`.
