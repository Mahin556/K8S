Based on the transcript, to get a complete picture of resource allocation on a node, you need two things from the `kubectl describe node` command:

1.  **Total Allocated Resources for the node.**
2.  **A list of all pods running on that node and their individual resource allocations.**

Here are the commands and what to look for, as demonstrated in the session.

### 1. The Primary Command

The single command to get all this information is `kubectl describe node`. This command provides both the total summary and the pod-by-pod breakdown.

```bash
kubectl describe node <node-name>
```

For example, to check the `worker-3` node as mentioned in the transcript:
```bash
kubectl describe node worker-3
```

### 2. Understanding the Output

The output of this command is divided into key sections that answer your question.

#### A. Total Allocated Resources (The Reservation Summary)

Scroll to the section titled `Allocated resources`. This shows the total CPU and memory that has been promised (reserved) to all pods on that node.

```
Allocated resources:
  (Total limits may be over 100 percent, i.e., overcommitted.)
  Resource           Requests      Limits
  --------           --------      ------
  cpu                500m (25%)    1000m (50%)
  memory             200Mi (12%)   400Mi (25%)
```

- **Requests:** The total guaranteed resources reserved for all pods on the node.
- **Limits:** The total maximum resources all pods on the node are allowed to use.
- As the instructor explained, this is the **hardware reservation** or commitment, not the actual usage. "यह हार्डवेयर रिजर्वेशन बता रहा है... इतना हार्डवेयर वी हैव कमिटेड" (This shows hardware reservation... this much hardware we have committed).

#### B. All Pods and Their Individual Allocations (The Pod Inventory)

Above the `Allocated resources` section, there is a list of `Non-terminated Pods`. This is the detailed inventory the instructor was referring to: "हाउ मेनी पॉट्स आर रनिंग और सभी पड़ का रिसोर्स एलोकेशन कितना हुआ है" (How many pods are running and what is the resource allocation of all pods).

This section lists every pod on the node with its individual CPU and memory requests and limits.

```
Non-terminated Pods:          (3 in total)
  Namespace                   Name                CPU Requests  CPU Limits  Memory Requests  Memory Limits
  ---------                   ----                ------------  ----------  ---------------  -------------
  kube-system                 etcd-worker-3       100m (5%)     0 (0%)      100Mi (1%)       0 (0%)
  database                    postgres-db         250m (12%)    1 (50%)     256Mi (3%)       512Mi (6%)
  default                     nginx-app           0 (0%)        0 (0%)      0 (0%)           0 (0%)
```

From this table, as highlighted in the transcript, you can see exactly how much hardware each individual pod has reserved on that specific node (e.g., the `postgres-db` pod has reserved `250m` CPU and `256Mi` memory).

### Key Commands for Comparison from the Transcript

To make a complete analysis, you also need to understand the difference between this allocated view and actual usage.

| Information | Command | What It Shows |
| :--- | :--- | :--- |
| **Allocated (Reserved) Resources** | `kubectl describe node <node-name>` | Shows the total and per-pod hardware reservation (requests/limits). |
| **Actual Usage** | `kubectl top node <node-name>` | Shows the real-time CPU and memory being consumed on the node. |
| **Actual Usage per Pod** | `kubectl top pod --all-namespaces --field-selector spec.nodeName=<node-name>` | Shows the real-time CPU and memory being consumed by each pod on that node. |

The transcript's core lesson is that `kubectl describe node` is the single source of truth for seeing both the **node-level reservation summary** and the **per-pod allocation breakdown**. To get a complete picture of a node's performance, you must compare this allocated data with the actual usage from `kubectl top`.
