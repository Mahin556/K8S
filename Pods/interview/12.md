## Question 6: If 50% of Pods Go Into Pending State During Peak Traffic, How Will You Troubleshoot?

**Answer:** This is a critical production scenario. Here's the systematic troubleshooting approach:

### Step-by-Step Troubleshooting:

**Step 1: Get an Overview**
```bash
kubectl get pods -o wide
kubectl get nodes
```
- Check which pods are pending
- Check if nodes are in `Ready` state

**Step 2: Describe Pending Pods**
```bash
kubectl describe pod <pod-name>
```
Look in the Events section for:
- `Insufficient cpu` - Node resources exhausted
- `Insufficient memory` - Memory pressure
- `node(s) didn't match node selector` - Scheduling constraints
- `node(s) had taint` - Taint/toleration issues

**Step 3: Check Node Resources**
```bash
kubectl top nodes
kubectl describe node <node-name>
```
- Check CPU and memory utilization
- Check `Allocated resources` section

**Step 4: Check for Resource Quotas**
```bash
kubectl get resourcequota -A
kubectl describe resourcequota <quota-name>
```

**Step 5: Check Cluster Autoscaler (if using cloud)**
```bash
kubectl logs -n kube-system deployment/cluster-autoscaler
```

### Common Causes and Fixes:

| Cause | Fix |
|-------|-----|
| **Insufficient node resources** | Scale up nodes (manually or via Cluster Autoscaler) |
| **Resource quota exhausted** | Increase namespace quota |
| **Node taints** | Add tolerations to pods or remove taints |
| **Node affinity mismatch** | Adjust affinity rules or label nodes |
| **PVC pending** | Check storage class and PV availability |

### Immediate Mitigation:
- Scale down non-critical deployments to free resources
- Increase HPA max replicas
- Add more worker nodes
