### What is the difference between a Deployment, a StatefulSet, and a DaemonSet?

| Deployment                            | StatefulSet                                     | DaemonSet                                    |
| ------------------------------------- | ----------------------------------------------- | -------------------------------------------- |
| Used for stateless applications.      | Used for stateful applications.                 | Used to run a Pod on every node.             |
| Pods are interchangeable.             | Pods have unique identities and stable storage. | Ensures one Pod runs per node.               |
| Suitable for web apps and APIs.       | Suitable for databases and message queues.      | Suitable for monitoring and logging agents.  |
| Supports scaling and rolling updates. | Supports ordered deployment and scaling.        | Automatically adds Pods when new nodes join. |
| Pod names are random.                 | Pod names remain fixed and predictable.         | Pods are distributed across cluster nodes.   |
| Example: Nginx, frontend apps.        | Example: MySQL, MongoDB.                        | Example: Fluentd, Prometheus Node Exporter.  |

---

## Simple Interview Answer

“In Kubernetes, a Deployment is used for stateless applications, a StatefulSet is used for stateful applications requiring stable identity and storage, and a DaemonSet ensures a copy of a Pod runs on every node for tasks like logging and monitoring.”
