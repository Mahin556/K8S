### What is the relationship between a Deployment, ReplicaSet, and Pod?

These components work in a hierarchy:

```text id="1d7k4"
Deployment → ReplicaSet → Pods
```

### 1. Deployment

* Highest-level Kubernetes object.
* Defines the desired application state such as:

  * Number of replicas
  * Container image
  * Update strategy
* Manages rolling updates and rollbacks.

### 2. ReplicaSet

* Created and managed by the Deployment.
* Ensures the required number of Pods are always running.
* If a Pod fails, ReplicaSet automatically creates a new Pod.

### 3. Pod

* Smallest deployable unit in Kubernetes.
* Runs one or more containers.

---

## Update Process

When a Deployment is updated:

* Kubernetes creates a new ReplicaSet.
* New Pods are started gradually.
* Old Pods are terminated gradually.
* This process is called a **Rolling Update**.

Old ReplicaSets are kept for rollback if needed.

---

### Simple Interview Answer

“In Kubernetes, a Deployment manages ReplicaSets, and ReplicaSets manage Pods. The Deployment defines the desired state of the application, the ReplicaSet ensures the correct number of Pods are running, and Pods run the actual containers.”
